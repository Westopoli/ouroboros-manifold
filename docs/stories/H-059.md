# H-059: two-gate-channels

"The simulation lab and the beta land through separate gates, so neither blocks the other; we have enough compute to run multiple gates at the same time."

Flag harness; tool Workflow; no scene. Ready 2026-11-02 (DEC-two-gate-channels-2026-11-02). Lands through today's single gate on the lab channel, after H-057; the beta Dispatcher chat starts when it is on main.

## Why

One lock, `~/Projects/om-push/gate.lock`, serialises every landing (clerk.md step 4). The 2026-10-13 scout (`docs/northstar/plans/harness/gate-parallel-scout.md`) found the gate already private inside (mktemp scratch root, private XDG_DATA_HOME, per-worktree builds, xvfb plays) and listed what two gates still share: `gate_runs.csv` (unlocked append), `baseline_cache/` and `candidate_results/` under the worktree root (read-modify-write with a fixed tmp name), the real display for the play step and its portal capture, the worktree slot cap, and the sweep. The beta staircase (plan `2026-11-02-beta-staircase.md`) needs its own channel.

## Change

- Locks: `gate-lab.lock` and `gate-beta.lock` for stages 0 to 3 (the clerk's flock line takes the story's channel lock); `push.lock` (new, short) around fetch, merge, pre_gate re-check and `git push HEAD:main`; `play.lock` (new) around every real-display `scripts/play.sh` run and `screen_capture.sh` call, both channels. `records.lock` unchanged. The old `gate.lock` name is retired: `status_check.py` and `method_check.py` accept the three new names in command lines.
- `merge_gate.sh`: `gate_runs.csv` rows appended under `flock` on the csv; `merge_gate_support.py`: cache and candidate-result files written through `mktemp` in the same directory and renamed.
- `wt.py`: `--channel lab|beta` (required on `new`, recorded in `.wt-state`, shown by `status`); slots per channel, DRAFT-wt-slots-per-channel 10; the disk cap and reap unchanged.
- Stories: a `Channel: lab|beta` Machine line (default `lab` when absent, so existing stories need no edit); `status_check.py` reads it and the gate refuses a landing whose clerk took the other channel's lock.
- Docs in the same change: `docs/method/clerk.md` step 4 and 5 (which lock, play.lock), `gate.md` (channels, what stays shared), `runner.md` (one chat per channel, names), CLAUDE.md Usage ("one landing in flight per channel"), `docs/method/README.md` (locks row).

## Tests (`tests/specfactory/test_gate_channels.py`, new; red on main)

1. Two scratch candidates gate at the same time under the two locks (the existing `test_gate_concurrent.py` harness for scratch gates reused as a helper, not edited); both land; `gate_runs.csv` holds both rows intact.
2. Positive control: the same two under one lock name serialise (the second waits).
3. `play.lock`: a second `play.sh --check` invocation blocks while a first holds the lock (simulated holder), and proceeds when released.
4. `push.lock`: two pushes to a scratch remote serialise and both land in order.
5. A story with `Channel: beta` gated under `gate-lab.lock` is refused by `status_check.py` with `CHANNEL mismatch`.
6. `wt.py new` without `--channel` refuses; `status` prints the channel; the per-channel slot cap holds (the eleventh `lab` tree refused while `beta` has room).

## Rulings for the build (2026-11-02, the lab Dispatcher's five questions and one gap)

1. `status_check.py` learns the lock the clerk took from an argument: `--lock gate-lab.lock` or `--lock gate-beta.lock`; it reports `STATUS channel DRIFT <id>` when a story's `Channel:` line names the other lock. 2. A new small script `scripts/specfactory/land_push.sh <worktree> <id>` takes `push.lock`, runs fetch, merge of origin/main, the `pre_gate` re-check and `git push HEAD:main`, prints `PUSHED <sha>` or `PUSH REJECT <why>`, and fails closed when the lock is not won inside its timeout; `docs/method/clerk.md` calls it in place of the hand-typed push; it is tested against a scratch remote. 3. `wt.py status` gains a `channel` column and a `channel` JSON key. 4. Lock paths under the push root: `gate-lab.lock`, `gate-beta.lock`, `play.lock`, `push.lock`, `records.lock`, all beside the existing locks. 5. `wt.py new` takes `--channel lab|beta`, default `lab` so every existing caller keeps working (a beta tree must say `--channel beta`); an unknown channel or a full per-channel cap exits 3 with `WT REFUSED ...`, as today. Per-channel cap DRAFT 10 slots each; the shared disk cap and free-space floor stay as they are. 6. The `method_check.py` change that accepts the three new lock names (`gate-lab.lock`, `gate-beta.lock`, `push.lock`, `play.lock` as clerk-side locks) belongs to this story, and its test goes in a new file `tests/method/test_method_check_channels.py` named in this story's Tests line; no existing test file is edited. H-062's reread tests stay in H-062's own file, so the two stories share no test file; both touch `method_check.py` in different functions, and whichever lands second merges main first.
