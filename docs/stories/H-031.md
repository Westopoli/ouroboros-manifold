## Piece two (Ready 2026-10-31, from the display findings)

Westley's Sonnet chat measured the fault on his desktop (memory `project-display-fault-findings-2026-10-31`, verdicts read from real screenshots): a windowed launch at exactly the project viewport size 1920x1080, or the project's fullscreen default, presents only the splash; every other requested size (1280x720, 1600x900, 1900x1060, 1919x1080, 1921x1080, 2560x1440) draws. Godot's own state in a failing run is `window_get_mode()=0` with `window_get_size()=(2560,1440)` (the monitor), and a `window_set_size(size + (1,0))` three seconds after boot turns a failing launch into a drawn game. Minimal projects draw in every combination, so the fault is in this project's startup. The Architect's H1 and H2 were wrong; the stored-settings flip stays ruled out.

Harness piece (this story, flag harness, branch `s/H-031-proof-by-eyes`):
- `scripts/play.sh`: `RESOLUTION` becomes `1919x1080` (DRAFT-play-resolution, was 1920x1080), with a comment naming the finding: a request equal to the project viewport presents only the splash on GNOME Wayland (2026-10-31). The dry-run line shows it.
- `scripts/specfactory/screen_capture.sh <out.png>` (the Capture round): the xdg-desktop-portal Screenshot call from python3 Gio (one connection, subscribe to `Request.Response`, call `org.freedesktop.portal.Screenshot.Screenshot("", {"interactive": False})`), which writes `~/Pictures/Screenshot-N.png`; the script copies the newest such file to `<out.png>`, crops to the monitor whose geometry holds the Godot window when `xdotool` or the Wayland trace can say which, else keeps the whole desktop, and prints `CAPTURE portal <out.png>`. Westley allowed the portal once on 2026-10-31; a denial prints `CAPTURE REJECT portal denied` and exits 2. `play.sh --check` calls it after the scene is reached and prints `PLAY proof <path> portal`; the blank or near-uniform test fails the proof.
- Tests (`tests/method/test_play_proof.py`): dry run prints `--resolution 1919x1080`; a planted portal stub that writes a known PNG makes `screen_capture.sh` print `CAPTURE portal <out>` and the file matches; a planted uniform PNG fails the proof (positive control: a planted non-uniform one passes); a stub that returns the portal's denial code prints `CAPTURE REJECT portal denied`.

The game-side fix is H-038 (client): until it lands, the shipped fullscreen default still shows the splash on this desktop, so H-028 (stable beta) depends on H-038.
