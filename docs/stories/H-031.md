## Finding

All measured 2026-10-30 night on Westley's own desktop (GNOME Wayland, two monitors, RTX 3060, Godot 4.6.3).

- Under the default X11 driver (Xwayland) the window is created and stays IsUnMapped / Iconic, with Vulkan or opengl3, windowed or not.
- Under `--display-driver wayland` the window appears.
- With `--windowed --resolution 1280x720` the proto scene is fully drawn (Westley saw the H-023 stage).
- Without `--windowed` (project default `window/size/mode=3`, fullscreen) only the Godot splash shows.
- Godot's main loop runs at about 140 fps in every case (`--print-fps`), so nothing stalls the game.
- A two-line control project presents fine.
- play.sh's current check (xdotool finds a window by name) passes on an unmapped window.
- The X11-driver mapping failure is a separate, undiagnosed fault.
- Not isolated: whether the fullscreen default or the fullscreen-to-windowed flip in `autoload/ui_data_bus.gd:123-126` (`_apply_stored_settings`) breaks presentation.
- No real screen capture tool works from an agent: no gnome-screenshot or grim; org.gnome.Shell.Screenshot refuses non-session callers; the Xwayland root capture is black.
- The H-023 and H-025 shots were the QA daemon's viewport captures and are unverified.

## First piece

Harness only: `scripts/play.sh` and `tests/method/test_play_proof.py`.

- play.sh launches Godot with `--display-driver wayland` when `WAYLAND_DISPLAY` is set in the environment, else X11 as today, and always `--windowed --resolution <DRAFT-play-resolution 1920x1080>`. The dry-run `launch:` line shows the flags.
- Window check under the Wayland driver (no X window, so no xwininfo): the QA daemon answers `qa_state()` with the scene AND Godot's `--print-fps` output shows at least DRAFT-play-min-fps 30 fps lines for DRAFT 3 consecutive seconds. It prints `PLAY window <s>s wayland`.
- Window check under X11: the old xwininfo check stays and additionally requires Map State IsViewable; otherwise it prints `PLAY REJECT window unmapped <state>`.
- The proof capture (Capture section) is round two. Until it lands a clerk writes `Played: unproven (no capture)` and the landing of a scene story waits (DEC-eyes-proof-gate-2026-10-30).
- Round two: play.sh's "no display" exit must accept a Wayland session (`WAYLAND_DISPLAY` set and `DISPLAY` empty); today it exits "no display". Test: dry run with `WAYLAND_DISPLAY` set and `DISPLAY` unset prints the launch line.

Tests (`tests/method/test_play_proof.py`):
- Dry run with `WAYLAND_DISPLAY` set prints `--display-driver wayland --windowed --resolution 1920x1080` on the launch line.
- Dry run without it prints no wayland flag but still `--windowed`.

## Session env recipe (clerk)

The clerk builds the env for a play as: `WAYLAND_DISPLAY` from the socket name under `$XDG_RUNTIME_DIR` (`wayland-0` if `/run/user/1000/wayland-0` exists), `DISPLAY` and `XAUTHORITY` from the running Xwayland command line (`pgrep -a Xwayland`, the `-auth` argument), `XDG_RUNTIME_DIR=/run/user/1000`, `DBUS_SESSION_BUS_ADDRESS` from gnome-shell's environ. Nothing else is read (found 2026-10-31: gnome-shell's environ holds only the last two).

## Round two (capture)

A capture of the real screen under the Wayland compositor. The builder tries, in order: the GNOME screenshot portal through `xdg-desktop-portal` with `org.freedesktop.portal.Screenshot`, non-interactive; then `gnome-screenshot` if Westley installs it; then Godot's `DisplayServer.screen_get_image` from inside the running game as a last resort, noted as not a compositor capture. The chosen one is `scripts/specfactory/screen_capture.sh <out.png>`, which prints which method it used. A capture that is blank or near-uniform fails. Round two. Westley's eyes are the proof until the capture exists; a clerk cannot see the screen.

## Proof

`play.sh --check` writes `<scratch>/proof.png` with that script after the scene is reached and prints `PLAY proof <path> <method>`. The clerk's `Played:` trailer carries the method. The viewport verb is never used for proof.

## Westley's check

The one command he runs on his desktop:

`xprop -name "Ouroboros (DEBUG)" WM_STATE _NET_WM_STATE; xwininfo -name "Ouroboros (DEBUG)" | grep "Map State"`

`WM_STATE Normal` with `IsViewable` means the window is up and the fault is the agent session. `Iconic` with `IsUnMapped` on his desktop means the fault is in the project or launch line.
