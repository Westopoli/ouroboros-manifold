## Finding

- play.sh launches Godot without a headless flag; Godot renders on the RTX 3060.
- Godot creates the window "Ouroboros (DEBUG)", 1920x1080 at +1920+32.
- In every run from an agent process the window stays IsUnMapped with WM_STATE Iconic.
- A plain xterm launched the same way also stays unmapped: an agent here cannot show any window.
- No real screen capture tool works here: no gnome-screenshot or grim.
- org.gnome.Shell.Screenshot refuses non-session callers.
- The Xwayland root capture is black under the Wayland compositor.
- play.sh's "window" check passes on an unmapped window.
- The H-023 and H-025 shots were the QA daemon's viewport captures and are unverified.

## Window

`play.sh --check` passes only when the window's Map State is IsViewable and WM_STATE is Normal, read with `xwininfo` and `xprop` on the window it finds. It prints `PLAY window <s>s mapped` or `PLAY REJECT window unmapped <state>`. If the window is Iconic on Westley's own desktop too, the first piece finds the cause in the launch line or project.godot and fixes it. Otherwise the cause is the agent session, and the story says how a clerk launches into his session: a `systemd-run --user --scope` or `gnome-session` scoped launch (DRAFT, to be proved).

## Capture

A capture of the real screen under the Wayland compositor. The builder tries, in order: the GNOME screenshot portal through `xdg-desktop-portal` with `org.freedesktop.portal.Screenshot`, non-interactive; then `gnome-screenshot` if Westley installs it; then Godot's `DisplayServer.screen_get_image` from inside the running game as a last resort, noted as not a compositor capture. The chosen one is `scripts/specfactory/screen_capture.sh <out.png>`, which prints which method it used. A capture that is blank or near-uniform fails.

## Proof

`play.sh --check` writes `<scratch>/proof.png` with that script after the scene is reached and prints `PLAY proof <path> <method>`. The clerk's `Played:` trailer carries the method. The viewport verb is never used for proof.

## Westley's check

The one command he runs on his desktop:

`xprop -name "Ouroboros (DEBUG)" WM_STATE _NET_WM_STATE; xwininfo -name "Ouroboros (DEBUG)" | grep "Map State"`

`WM_STATE Normal` with `IsViewable` means the window is up and the fault is the agent session. `Iconic` with `IsUnMapped` on his desktop means the fault is in the project or launch line.
