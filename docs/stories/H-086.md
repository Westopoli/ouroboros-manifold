# H-086: mailbox-reads-whole-and-waits-once

"A mail I or a chat sends arrives whole and is never lost, a flag never wakes a chat for mail it has already read, a chat has one wait that waits as long as it takes, and mail nobody has read for two hours is reported to the Architect."

## Finding (measured 2026-11-04 on `origin/main` scripts, scratch mailbox under `OM_PUSH_DIR`; the real mailboxes untouched)

1. **The digest cuts text.** `cmd_read` prints `m['text'][:200]`; `send` allows 1,500. A 900-character mail printed 246 characters with no mark and the tail was missing. In use, three rulings to the two runners and two long asks to the Architect arrived cut at 200 characters; the full text was only in `delivered.jsonl`.
2. **A read leaves the flag up.** Station raised the flag for an `ask`; `read` drained the mail; the flag file remained; the next `wait` returned in 0.1 s with `MAIL none`: one wasted whole-context wake.
3. **Nothing limits waits.** Chats re-arm at the end of every turn while the previous wait still blocks: 3 pending for the Architect, 4 for the lab runner, 3 for the beta runner (oldest 2 h 52 min). With three waits armed together and one flag, two returned (the code ignores a failed `os.remove(flag)` and reads anyway). A wait left by an ended or restarted chat can take a flag and move the mail to `delivered.jsonl` with nobody to read it. `--max` exists but no card passes it.

## Change

Files: `scripts/method/mail.py`, `scripts/method/station.py`, `scripts/specfactory/status_check.py` (the 2 h DRIFT line), `tests/method/test_mail_waits.py` (new, the writer's); the documentation is done (`communication.md` "Reading and waiting", `architect.md` Escalation, `runner.md` step 3, README Numbers, `agents.toml` `[station]`, H-077 pointers). The behaviour is the one in `communication.md` "Reading and waiting"; here only what the code must do beyond it.

1. **Whole digest.** Remove the `[:200]`. No other change to the line format.
2. **Only `read` consumes.** `cmd_wait` ends with `MAIL pending <n> <classes>` (counts and classes from the inbox, no text) and never writes `delivered.jsonl` or empties the inbox. `cmd_read` is unchanged except for items 1, 3 and 5. The flag taken by a wait whose chat never reads is raised again by the station while mail stays unread.
3. **Flag.** `cmd_read` removes `mail/<agent>/flag` after draining, under the agent lock, whether or not there was mail. `station.py loop()` takes the agent lock (`mail.locked(name)`), re-reads the inbox under it and raises the flag only if mail is still unread and no flag exists; it never reads text or moves mail.
4. **Single take, no limit.** In `cmd_wait` a failed `os.remove(flag)` means another wait took it: keep waiting. Poll stays 0.25 s. No default `--max`; the option stays for tests and `OM_MAIL_WAIT_MAX` does not exist.
5. **Registry.** `wait` writes `mail/<agent>/waits/<pid>` (JSON: pid, `start` from `/proc/<pid>/stat`, `anchor`) and removes it on every exit it controls. `read` ends with `WAIT none` or `WAIT armed <n>`, counting only records whose pid is alive with the same start time and whose `anchor` equals the anchor of the `read` itself; records of dead processes are deleted.
6. **Orphans.** `anchor` is the chat process: `OM_MAIL_ANCHOR_PID` when set, else the first ancestor that is not a shell, `python*`, `setsid`, `timeout` or `env` (the builder checks on this box which ancestor that is for a real pending `mail.py wait`: `ps -o pid,ppid,comm` up its chain). Every 2 s the wait checks the anchor is alive with the same start time; if not it removes its record, appends `<ts> orphan <agent> <pid>` to `station.log`, and exits 0 with no output, taking no flag and reading no mail.
7. **Undelivered watch.** `station.py loop()`, after the flag work: for every inbox, each unread mail older than DRAFT-mail-undelivered (7200 s) whose id is not in `mail/station-alerted/` and whose recipient is not `architect` makes the station run the equivalent of `mail.py send --me station --to architect --class block --re <re> "UNDELIVERED to=<recipient> class=<c> from=<sender> re=<re> waited=<min>m id=<id>: <text>"`, the text cut so the whole stays under DRAFT-mail-max with the id named when cut, then writes the marker file and one `station.log` line. For `architect` itself nothing is sent. `status_check.py` prints `STATUS mail DRIFT <agent> <class> unread <min>m` for any class past 7200 s (the existing block/ask 30-minute check stays), which also covers the Architect's own mail.
8. **Deploy.** `station.py` is a running service: the landing clerk runs `systemctl --user restart om-station` after the push and checks `station.log` for a line within a minute. `mail.py` is used at once by every chat; waits already pending keep the old code (and the old consuming `wait`) until they end. The clerk also re-pins the one old test that asserts `wait` prints the digest (`tests/method/test_mail.py`, t8) under `rulebook.md` with a `Test-defect:` trailer, quoting `communication.md` "Only `read` consumes mail" as the replacing line; nothing else in that file changes.

## Tests (`tests/method/test_mail_waits.py`, written first by a Sonnet who does not build, red on main)

All with `OM_PUSH_DIR` pointing at a temp dir, the temp registry (with a `station` table), and the fakes of `tests/method/mailfix.py`; nothing touches the real mailboxes or the real station.
- A 1,500-character mail prints in full by `read` (red on main); a short mail prints the same line as today (control).
- `wait` returns with `MAIL pending 1 ask` and no text; afterwards the mail is still in `inbox.jsonl` and not in `delivered.jsonl` (red on main: it reads and moves it); a following `read` prints it and marks it delivered (control).
- Station raises a flag for an `ask`; `read` leaves no flag and then `wait --max 2` prints `MAIL idle 2s` and does not return at once (red); `read` with no mail still removes a stray flag.
- Station takes the agent lock: with the test holding `mail/<agent>/.lock`, a `station --once` started in the background is held; the test drains the inbox and releases; no flag and no log line (red on main); control: mail left unread, the flag is raised.
- Three waits armed, one flag: exactly one returns, the other two still block until `--max` (red on main: two return); a second flag then wakes exactly one more (control).
- `read` prints `WAIT none` with none armed and `WAIT armed 1` with one belonging to this chat (`OM_MAIL_ANCHOR_PID` equal); a wait with another anchor, or one killed with `SIGKILL`, is not counted and its record is dropped (red on main: no WAIT line).
- No default limit: `wait` with no `--max` and no flag is still running after 5 s (control for "no expiry"; red on main only through the other items, so it is a guard).
- Orphan: a wait whose `OM_MAIL_ANCHOR_PID` helper is then ended exits within 4 s with empty output and exit 0, a raised flag and an unread mail are untouched, and `station.log` gains one `orphan` line (red on main). Control: with the helper alive the wait keeps waiting and takes the flag when it is raised.
- Undelivered watch (`station --once`, unread age set as `test_station.py` does): mail 121 min old to `runner-lab` makes exactly one `block` mail from `station` to `architect` whose text contains the recipient, class, sender, re, `waited=121m` and the mail text; a second `--once` sends nothing more (marker); mail 119 min old sends nothing; a 1,500-character stale mail yields an alert under 1,500 characters naming the id; stale mail addressed to `architect` sends nothing; the mail itself stays unread in the inbox in every case.
- `status_check.py` (toy registry): an `info` mail 121 min old prints `STATUS mail DRIFT <agent> info unread 121m`; one 119 min old prints no DRIFT; the existing 30-minute block/ask line is unchanged (control).
- Old tests in `tests/method/test_mail.py` (except t8, the clerk's) and `test_station.py` stay green unchanged.
