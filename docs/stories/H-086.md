"A mail I or a chat sends arrives whole, a flag never wakes a chat for mail it has already read, and a chat has one wait, not a growing pile of them."

## Finding (measured 2026-11-04 on `origin/main` scripts, scratch mailbox under `OM_PUSH_DIR`; the real mailboxes untouched)

1. **The digest cuts text.** `cmd_read` prints `m['text'][:200]`; `send` allows 1,500. A 900-character mail printed 246 characters with no mark and the tail was missing. In use, three rulings to the two runners and two long asks to the Architect arrived cut at 200 characters; the full text was only in `delivered.jsonl`.
2. **A read leaves the flag up.** Station raised the flag for an `ask`; `read` drained the mail; the flag file remained; the next `wait` returned in 0.1 s with `MAIL none`: one wasted whole-context wake.
3. **Nothing limits waits.** Chats re-arm at the end of every turn while the previous wait still blocks: 3 pending for the Architect, 4 for the lab runner, 3 for the beta runner (oldest 2 h 52 min). With three waits armed together and one flag, two returned (the code ignores a failed `os.remove(flag)` and reads anyway). A wait left by an ended or restarted chat can take a flag and move the mail to `delivered.jsonl` with nobody to read it. `--max` exists but no card passes it.

## Change

Files: `scripts/method/mail.py`, `scripts/method/station.py`, `tests/method/test_mail_waits.py` (new, the writer's); the docs are done. The behaviour is the one in `communication.md` "Reading and waiting"; here only what the code must do beyond it.

1. **Whole digest.** Remove the `[:200]`. No other change to the line format.
2. **Flag.** `cmd_read` removes `mail/<agent>/flag` after draining, under the agent lock, whether or not there was mail. `station.py loop()` takes the agent lock (`mail.locked(name)`), re-reads the inbox under it and raises the flag only if mail is still unread and no flag exists; it still never reads text or moves mail.
3. **Single take.** In `cmd_wait` a failed `os.remove(flag)` (`FileNotFoundError`) means another wait took it: keep waiting, do not read. Poll stays 0.25 s.
4. **Registry.** `wait` writes `mail/<agent>/waits/<pid>` (JSON: pid, `start` from `/proc/<pid>/stat`, `expires`, `anchor`) on start and removes it on every exit it controls. `read` prints a last line `WAIT none` or `WAIT armed <n>`, counting only records whose pid is alive with the same start time, and deletes the others.
5. **Expiry.** `--max` defaults to DRAFT-mail-wait-max, 14400 s. At expiry: `MAIL idle <s>s`, exit 0, record removed.
6. **Orphans.** `anchor` is the chat process: `OM_MAIL_ANCHOR_PID` when set, else the first ancestor that is not a shell, `python*`, `setsid`, `timeout` or `env` (the builder checks on this box which ancestor that is for a real armed wait: `ps -o pid,ppid,comm` up the chain of any pending `mail.py wait`). Every 2 s the wait checks the anchor is alive with the same start time; if not it removes its record and exits 0 with no output, taking no flag and reading no mail.
7. **Deploy.** `station.py` is a running service: the landing clerk runs `systemctl --user restart om-station` after the push and checks `station.log` for a line within a minute. `mail.py` is used at once by every chat; waits already pending keep the old code until they end.

## Tests (`tests/method/test_mail_waits.py`, written first by a Sonnet who does not build, red on main)

All with `OM_PUSH_DIR` pointing at a temp dir, the temp registry, and the fakes of `tests/method/mailfix.py`; nothing touches the real mailboxes or the real station.
- A 1,500-character mail prints in full by `read` and by `wait` (red on main); a short mail prints the same line as today (control).
- Station raises a flag for an `ask`; `read` leaves no flag and then `wait --max 2` prints `MAIL idle 2s` and does not return at once (red); with the flag file present and no mail, `read` still removes it.
- Station takes the agent lock: with the test holding `mail/<agent>/.lock`, a `station --once` started in the background is held; the test drains the inbox and releases; no flag is raised and no log line written (red on main); control: with the mail left unread the flag is raised.
- Three waits armed, one flag: exactly one returns with the mail, the other two still block until `--max` (red on main: two return); a second flag then wakes exactly one more (control).
- `read` prints `WAIT none` with none armed and `WAIT armed 1` with one; a wait killed with `SIGKILL` leaves a record that the next `read` drops and reports `WAIT none` (red on main: no WAIT line).
- Without `--max` the wait ends at the default; the test sets `OM_MAIL_WAIT_MAX=2` and expects `MAIL idle 2s` (the env var is the test's way to shorten the default; production never sets it).
- Orphan: a wait with `OM_MAIL_ANCHOR_PID` of a helper process that is then ended exits within 4 s with empty output and exit 0; a raised flag and an unread mail are untouched afterwards (red on main). Control: with the helper alive the wait keeps waiting and takes the flag when it is raised.
- Old tests in `tests/method/test_mail.py` and `test_station.py` stay green unchanged; if one cannot, stop and report (a Test-defect ruling, `rulebook.md`).
