# H-062: plan-reread-after-compaction

"After a compaction the chat re-reads every plan file it is executing before it acts, and the method check says so when it did not."

Flag harness; tool Workflow; no scene. Ready 2026-11-02 (Westley 2026-11-02: "does the method drift check after compact enforce that the new session re-reads every plan file being executed? This is particularly important for your chat, you're executing two plans in parallel"). Channel: lab.

## Why

Today `scripts/specfactory/method_check.py` runs at `SessionStart` with matcher `compact` (the hook in `.claude/settings.json`) and tests six rules against the chat's transcript: wakeups, polling, gate_runs, live_tree, code_edits, context. None of them asks whether the chat re-read its plans. The only thing that makes a compacted chat re-read them is the written advice in the role's context file. Two more findings the same morning: (1) the `context` rule text still says "Restart from memory past 400k context; the compaction is not the restart", which the guard removal of 2026-11-01 (DEC-context-guard-off) made false: the rule now says compaction at 400k is the only rule, so a turn past 400k is drift only if the chat failed to compact; (2) `role_of` decides the role from the model name, so a Fable chat switched to Sonnet is checked as a runner and loses the Fable-only `code_edits` rule.

## Change

- `docs/method/reading_list.toml` (new): `[architect]`, `[runner_lab]`, `[runner_beta]`, each `files = [...]` of repo-relative paths. First contents: architect = `docs/northstar/ROADMAP.md`, `docs/northstar/plans/2026-11-02-beta-staircase.md`, `docs/northstar/story_reviews/westley/decisions.md` (tail), `docs/method/architect.md`, plus the lab staircase plan file path `docs/northstar/plans/2026-10-31-lab-staircase.md` (the Architect's records push copies `~/.claude/plans/cheerful-baking-codd.md` there first, so the plan lives in the repo, not only in a home folder); runner_lab = `docs/method/runner.md`, `docs/northstar/ROADMAP.md`, the lab staircase plan, `docs/northstar/plans/2026-11-02-beta-dispatcher-context.md` is NOT in it; runner_beta = `docs/method/runner.md`, `docs/northstar/ROADMAP.md`, `docs/northstar/plans/2026-11-02-beta-staircase.md`, `docs/northstar/plans/2026-11-02-beta-dispatcher-context.md`. Whoever starts or ends a plan edits this file in the same commit as the ROADMAP row (added to the ROADMAP rules).
- `method_check.py`: a seventh check `plan_reread` (both roles, DRIFT): in the part of the transcript after the compaction boundary the check is run for, any mutating tool call (Edit, Write, a Bash command that is not a reader per the existing `READERS`, Agent, SendMessage) that comes before every file of the chat's reading list has been read (a `Read` of the file, or a reader command naming its path) is one drift turn; the DRIFT line names the unread files. Which list: `architect` for an Architect chat; for a runner, `runner_beta` when the chat's session name contains `beta`, else `runner_lab`. The compaction hook output also prints the chosen list as its first line: `METHOD read first: <files>`. For an Architect chat the hook prints, after that line, one paragraph per plan file being executed (every file of the architect list whose path is under `docs/northstar/plans/` and is named in a ROADMAP section 1 row; today two: the lab staircase and the beta staircase), in Westley's words (2026-11-02), with the file path filled in:

`PLAN RE-READ <path>: this plan needs to be re-read, fully, because you are the architect and the plan execution depends on your ability to guide the dispatchers in their work and collaborate between them and help them when they get stuck. If you don't have full context of the plan, guesses will be made, and the output will not be what the plan file required, verifications will fail, and we'll waste time and effort on issues that could have been avoided.`

The wording is his; the builder changes nothing in it but the path. `NEXT` keeps its wording.
- The `context` rule becomes: "Compaction at 400k is the only context rule; a turn past 400k without a compaction is drift (docs/method/architect.md)". The check counts a turn whose context exceeds 400k by more than the window plus one turn (DRAFT-context-grace 20k).
- `role_of`: the role is the model of the chat's first assistant entry, not a mix; the role card names the chat, so a later `/model` switch does not change it. (Fix for finding 2; tests below.)
