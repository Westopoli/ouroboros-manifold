## Change

1. `review.py apply` accepts exactly the seven words A, B, draw, deny, hold, redraw and out. The word cell is trimmed of whitespace and otherwise compared exactly, case-sensitive (`Deny` is not `deny`). A word with quotes or punctuation (`"deny"`, `deny.`, `deny: reason`) is an unknown word: it is refused loudly, never read as the nearest word.
2. When a layout id has several rows, the last row wins (the amended-row rule that `verdicts.md` already states and `ruled.md` relies on). Every row must still be good: a bad word in a row that a later row for the same id amends is refused all the same, so the file must be clean before anything is written.
3. `apply` writes the winning verdict and feedback into each layout toml's `verdict` and `feedback` fields (it already does so through `write_layout`; the change is that it now reaches that line for the real file). For each applied row it prints `APPLIED <id> <word>` on stdout, one line per row in file order, the same line for all seven words.
4. An unknown id or an unknown word is refused: the exit status is non-zero, stderr names the line number of each bad row in the verdicts file as a standalone integer (not glued to other digits), and nothing is written: no layout toml changes and none of the sibling `<id>.json` files that `write_layout` writes beside it.
5. `review.py denied` then lists the round-two denies (L-0039, L-0047 and the batch-one rows) from the tomls.
6. The usage text that names the verdict words is rewritten to the seven words (stale-doc rule): the sentence in the page that `review.py build` writes (today "with verdict A, B, draw or deny") and every place in `review.py` that lists the words (the refusal message is built from `VERDICTS` and follows it).

Not in this story: any change to the verdict wording of a row, the pictures, or the layouts themselves.
