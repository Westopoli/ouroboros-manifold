# H-074: gate-scratch-on-disk

"A gate never fails because a temporary file had nowhere to go."

Flag harness; tool Workflow; no scene. Ready 2026-11-02 (the test writer's questions ruled by the Architect); Channel: lab; the builder starts 2026-11-02 and lands after the stack, H-068 first. Found by the Architect 2026-11-02, from the beta Dispatcher's H-067 gate on the beta channel (DEC-gate-scratch-2026-11-02).

## Why

Evidence 2026-11-02: `/tmp` is a 16 GB tmpfs mounted with `usrquota` (a per-user quota; the limit cannot be read without the quota tools). It bit at about 10 to 11 GB used by uid 1000 across all sessions: `/tmp/claude-1000` alone held 4 GB of session scratch (one old session 2.1 GB). During the H-067 gate on the beta channel the playthrough stage failed with `om_pipe.c:2053 fatal error: error writing to /tmp/cc....s: Disk quota exceeded` (gcc writes its temporary assembly into TMPDIR, default `/tmp`), and five other stages (gd_reach, rule_pins, control_liveness, placeholder_controls, acceptance) rejected with empty reasons in the same window. Very likely the same cause; not proven. A second failure the same evening, `index_array_create` / `ERR_CANT_CREATE`, was graphics memory (H-073), a different cause.

The real disk under `~/Projects/om-push/tmp` has about 240 GB free. It is the scratch root of the gate stages only when the caller happens to set `TMPDIR` there (see the next section); nothing in the gate scripts sets it. A full scratch reads as a code red (`red outside known-red list`, or an empty reject reason) although no code is at fault; the story goes back to its builder for nothing (CLAUDE.md: an environment fault is never a code red).

## Where scratch is made today (read 2026-11-02; the builder confirms)

- `scripts/specfactory/merge_gate.sh` line 94: `SCRATCH_ROOT="$(mktemp -d -t merge_gate.XXXXXX)"`. `mktemp -t` uses `$TMPDIR`, else `/tmp`. Every log and the scratch `XDG_DATA_HOME` live under it; the regression suites at lines 758 to 844 set their own `TMPDIR="$SCRATCH_ROOT/<suite>"`, so those follow the gate's root. The `make` stages (lines 255, 501, 666, 675, 678) and the stages that set no `TMPDIR` of their own (playthrough, lane_plays, gd_reach and the rest) inherit the caller's `TMPDIR`; gcc therefore writes its `cc....s` into `/tmp` when the caller set none.
- `scripts/specfactory/pre_gate.sh` line 39: `OUT="$(mktemp -d -t pre_gate.XXXXXX)"`, the same rule.
- `scripts/specfactory/land_push.sh` makes no scratch itself; it calls `pre_gate.sh` and inherits. `scripts/specfactory/sweep.sh` makes none itself (it logs beside the worktree under `om-push/wt/`); `merge_gate.sh` and `wt.py` inherit.
- `scripts/specfactory/merge_gate_support.py`: line 523 `tempfile.mkdtemp(prefix="control_liveness.")` (only when no `scratch_root` is passed), line 910 `tempfile.gettempdir()` as the default `worktree_root` of the regression check, line 931 `tempfile.TemporaryDirectory(prefix="merge_gate_junit_")`. All follow `TMPDIR`. The kept-evidence root (line 1172) and the baseline cache already live on the disk under `~/Projects/om-push/`.
- No gate script or `merge_gate_support.py` names `/tmp` literally. Literal `/tmp` defaults exist only in `scripts/specfactory/control_liveness.py` (lines 300 and 324, `/tmp/om_control_liveness`, used when `--scratch-root` is absent; the gate always passes it), `scripts/specfactory/escalator_fix_probe.py` line 1069 and `scripts/specfactory/draft_e2e.py` line 8 (a docstring example); the last two are not on the gate path.
- The convention today is the caller's: `docs/method/clerk.md` says to use a `TMPDIR` under `~/Projects/om-push/tmp/` (step 8, for the sweep), and `scripts/play.sh` defaults `TMPDIR` to `om-push/tmp` itself.
- There is no push-root override variable in the gate scripts: `land_push.sh` and `sweep.sh` hard-code `$HOME/Projects/om-push`. `merge_gate.sh` has `MERGE_GATE_RUNS_CSV` and `MERGE_GATE_EVIDENCE_ROOT`, nothing for the scratch.

## Change (a builder reads the scripts, reports where each scratch directory is made, and confirms or amends each part that the rulings below do not settle)

1. `scripts/specfactory/merge_gate.sh`, `pre_gate.sh`, `land_push.sh` and `sweep.sh` export `TMPDIR` to `${OM_PUSH_ROOT:-$HOME/Projects/om-push}/tmp` (creating it) before any child process starts, so gcc, pytest, mktemp and Godot's scratch inherit it. A caller's `TMPDIR` is kept only when it is NOT under `/tmp` (the path `/tmp` itself or any path starting `/tmp/`); unset, empty, or under `/tmp` it is overridden, because a caller `TMPDIR` that points into the quota-limited tmpfs (a session scratch directory under `/tmp/claude-1000/` would) defeats the purpose (Architect ruling 2026-11-02). `merge_gate.sh` prints the value in force, kept or overridden, once, as `GATE tmpdir <path>`, right after the `GATE tier <name>` line (`tests/specfactory/test_gate_base_stage.py` and `test_gate_tiers.py` pin `GATE tier` as the first GATE line; they are not re-pinned). The other three scripts print nothing new (their output formats are pinned by existing tests; the builder confirms). `OM_PUSH_ROOT` does not exist today: the builder either adds it, or drops the name and lets the tests point `HOME` at a scratch directory, whichever keeps the test hermetic.
2. The stages that name `/tmp` literally (the builder greps `/tmp` in the gate scripts and the harness helpers they call; the read above found only `control_liveness.py`) use `${TMPDIR:-/tmp}`.
3. `Disk quota exceeded` or `No space left on device` (the text of `EDQUOT` and `ENOSPC`) in a stage log is classified `SCRATCH-FULL`, reported as retryable and never as a reject of the story, in both places: the support module's detail for `lane_plays_check` and `playthrough_check` (in `merge_gate_support.py`, which build the `red outside known-red list` message today), and a shell-stage line `GATE <stage> RETRY SCRATCH-FULL`. Retryable means exit 3 (the gate's existing harness-error status; the clerk tells it from a compile error or a make timeout by the GATE line) and, in the support module, `ok` False with a detail starting `SCRATCH-FULL`, the same as H-073's `GPU-MEMORY`. The builder says which shell stages carry the line, and whether the stages that rejected with an empty reason (gd_reach, rule_pins, control_liveness, placeholder_controls, acceptance) can carry it.
4. `docs/method/clerk.md` and `docs/method/gate.md` get one sentence each: scratch lives on the disk under `om-push/tmp`, and a `SCRATCH-FULL` result is retried after the space is freed. The clerk.md sentence must contain neither the literal `HEAD:main` nor a bare retired lock name (`tests/specfactory/test_gate_channels.py::test_t4e` bans both in clerk.md).

Ruling (Architect 2026-11-02, closing the open point): a caller's `TMPDIR` is kept only when it is not under `/tmp`; otherwise the scripts override it with `$HOME/Projects/om-push/tmp`.

Not in this story: cleaning `/tmp` or `/tmp/claude-1000`, setting a quota, and any change to what the stages assert.

## Tests

`tests/specfactory/test_gate_scratch.py` (written by a different Sonnet; red on main; branch `origin/push/h074-tests`).

1. With `TMPDIR` unset, `merge_gate.sh`, `pre_gate.sh`, `land_push.sh` and `sweep.sh` (stubbed so no real gate runs) export a `TMPDIR` under the push root (hermetic: the file points `HOME` at a scratch directory, so the push root `$HOME/Projects/om-push` is scratch and `OM_PUSH_ROOT` is optional), and `merge_gate.sh` prints `GATE tmpdir <path>` with that path, right after `GATE tier <name>`.
2. With `TMPDIR` set by the caller to a directory outside `/tmp` (the file uses a directory under `~/Projects/om-push/tmp-gatescratch`, not `tmp_path`), the scripts keep it and `GATE tmpdir` prints the caller's value.
3. With `TMPDIR` set by the caller to `/tmp`, a path under `/tmp` (for example `/tmp/claude-1000/x`) or the empty string, the scripts override it with the push root's `tmp` and `GATE tmpdir` prints the override. Positive control: the same stubbed script with a caller `TMPDIR` outside `/tmp` (test 2) keeps its value.
4. A stubbed `lane_plays` log containing `Disk quota exceeded` is classified `SCRATCH-FULL`, not a story reject; the same for `No space left on device`. Positive control: an ordinary assertion failure in the same stubbed log still rejects.

Ruled 2026-11-02 but not pinned by the writer's file (the builder honours each and names it in the landing record): the `SCRATCH-FULL` classification in `playthrough_check` and the shell-stage line `GATE <stage> RETRY SCRATCH-FULL` with exit 3, the `${TMPDIR:-/tmp}` default in `control_liveness.py`, the two docs sentences.

Test defect owed: the writer's file asserts in `test_t1_merge_gate_prints_gate_tmpdir_line_with_push_root` that the `GATE tmpdir` line is the first GATE line; the ruling above makes it the second, after `GATE tier <name>`. That assertion is corrected under `docs/method/rulebook.md` (a `Test-defect:` trailer), not by the builder.
