# H-039: arena-snapshot-contract

Stage 1 of the simulation-lab staircase (DEC-lab-staircase-2026-10-31), the contract piece. Lands first; the four H-040 parts build against it.

"A fight the lab runs is written down as a small file of snapshots that any reader (the game scene, the page, me) can open: who stood where, facing where, with how much health, every few seconds, and who won against who I said would win."

Flag harness; tool Workflow; no scene (a file format and its checker). Every number below is an Architect draft dated 2026-10-31; Westley rules.

## Why a contract first

Westley, 2026-10-31: "Each stage of the plan will have a verified, tangible, visible, testable result." The snapshot file is the one thing every stage-1 part shares (runner writes it, replay scene reads it, page reads it, tests fixture it). Under the architecture rules a shared interface lands first and its consumers build after. Keeping it a file, not a Python object, lets the Godot scene and the page read it with no import of the lab.

## The file: `fight.json`

One fight, one file, JSON, UTF-8, keys sorted, two-space indent (so two runs of the same fight diff to nothing). Written by the arena runner (H-040 part 2) beside the layout it ran, name `<layout id>-s<seed>.fight.json`.

Top-level keys:
- `schema`: the string `om-fight-1`.
- `layout_id`: the layout file's `id` (H-025 schema, `L-NNNN`).
- `layout_path`: repository-relative path of the layout TOML.
- `seed`: int, the sim seed.
- `tick_rate`: int ticks per second of sim time (20 today, `scripts/skilllab/contract.py:161`).
- `snapshot_every`: int ticks between frames (DRAFT-snapshot-seconds 5 s, so 100 ticks).
- `sight`: `"off"` or `"on"` (stage 1 writes `"off"`: `OM_TP_TARGET_BY_SIGHT` set to 0, `csrc/unit.c:1175`; stages 4 and after write `"on"`).
- `frames`: list, in tick order. Always includes tick 0 and the last tick simulated; between them one frame every `snapshot_every` ticks. DRAFT-snapshot-count: a runner that would write more than 20 frames doubles `snapshot_every` until it does not (Westley 2026-10-30: 10 to 20 snapshots); fewer than 10 is allowed when the fight is short.
- `result`: table, below.

A frame:
- `tick`: int.
- `alive`: `[a, b]` ints.
- `units`: list, one row per unit spawned (dead units stay in every frame), sorted by `id`: `id` (int, engine unit id), `side` (`"A"` or `"B"`), `role` (roster name, `scripts/skilllab/engine.py:16`), `x`, `y` (float, world units, 2 decimals), `layer` (int), `facing` (float radians, 3 decimals), `hp` (float, 1 decimal, 0.0 once dead), `alive` (bool), `target` (int unit id or `null`; from `engine.unit_target`).

Stage 4 adds `seen` (list of enemy ids the unit's side sees) per unit; stage 5 adds `climbing` (float 0 to 1, `transition_progress`). Those keys are absent until their stage; a reader ignores keys it does not know; the checker rejects keys it does not know (so a stage cannot grow the file silently).

`result`:
- `winner`: `"A"`, `"B"` or `"draw"`. DRAFT-winner: the side with survivors when the other has none; both alive at the cap, or both dead, is `"draw"`.
- `survivors`: `[a, b]`.
- `ticks`: int, last tick simulated.
- `capped`: bool, true when the DRAFT-fight-cap 600 s (12,000 ticks) stopped the fight.
- `predict`: the layout's `predict` (`"A"`, `"B"`, `"draw"`), copied.
- `agree`: bool, `winner == predict`.

## Module `scripts/skilllab/arena/snapshot.py` (new; `scripts/skilllab/arena/__init__.py` empty)

- `SCHEMA = "om-fight-1"`; `MAX_FRAMES = 20`; `MIN_FRAMES = 10` (advisory, not enforced); `CAP_SECONDS = 600`.
- `validate(doc: dict) -> list[str]`: every rule above as one message each (`missing frames[3].units[7].hp`, `unknown key frames[0].units[0].seen`, `frames not in tick order`, `frames[0].tick is not 0`, `result.agree disagrees with winner and predict`, `units sorted by id`), empty list when valid.
- `write(doc: dict, path: Path) -> None`: validates (raises `ValueError` with the messages joined) then writes sorted keys, indent 2, trailing newline.
- `read(path: Path) -> dict`: loads and validates.
- `frame_ticks(last_tick: int, tick_rate: int, every_seconds: int = 5, max_frames: int = MAX_FRAMES) -> list[int]`: the tick list the runner must snapshot, with the doubling rule, always ending in `last_tick`.
- A fixture builder for tests `example(frames: int = 3, units_per_side: int = 2) -> dict` returns a valid document.

## Tests (`tests/skilllab/arena/test_snapshot.py`, red at the branch base)

- `example()` validates clean; `write` then `read` round-trips byte-identically on a second write.
- Positive controls: a frame with `hp` removed from one unit gives exactly one message naming `hp`; an extra key `seen` gives `unknown key`; frames out of order; first frame tick not 0; `agree` wrong.
- `frame_ticks(12000, 20)` has at most 20 entries, first 0, last 12000, spacing a power-of-two multiple of 100; `frame_ticks(300, 20)` is `[0, 100, 200, 300]`.
- `write` refuses an invalid document and writes nothing.
