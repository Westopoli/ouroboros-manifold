# H-023: unit-scale-comparison-scene

"a prototype to show unit scale in comparison to several 'strategic positions', with metrics for me to be able to understand how big each individual unit will be relative to other landscape pieces and buildings/cities and strategic positions, before we run the simulation engine with locked in unit scales."

Flag client; tool Workflow; a prototype under the Prototype gate (`docs/method/requirements.md`): judged by eye, Westley approves. Westley, 2026-10-30, verbatim: "Before we start running the simulation lab, I want to tune specific unit sizes relative to the landscape. I have specifics in mind for specific units, and would like to spend a decent amount of time working with a sonnet chat tuning scales or specific units given their roles (currently that's been chosen for me and I want to have a hand in it)" and "a method with which I can either talk to claude or scale the units with a slider myself (whichever is more efficient)". Blocks the simulation lab (H-008 and after). Done when Westley hands over final values at the end of his tuning session and they are written to the values file.

Facts found before writing (read-only):
- Roster: six baseline types, Raider, Interceptor, Vanguard, Warden, Bombard, Bastion (`scripts/skilllab/engine.py:16`; shapes `docs/bible/epics/E-18-visual-style-and-combat-visuals.md:32`; speeds Raider 150, Bastion 40 at `docs/bible/epics/E-01-layer-system.md:91`). - Radius today: one number for every type, `OM_UNIT_COLLISION_RADIUS 15` world units (`csrc/om_constants.h:581`; collision pushes pairs closer than 2 x 15, `docs/bible/algorithms.md` ALG-68). There is no per-type radius.
- Positions the bible names (node kinds, `docs/bible/epics/E-17-map-generation.md:59`): objective, staging, transit, chokepoint, flank_route, vantage, hazard_anchor, spawn_point, extraction; plus cover obstacles (`E-01-layer-system.md:136`), height bands and slopes, and cities and bases (`E-17:20`). Radii in play: chokepoint obstacle 600, vantage 700, capture radius 300 (ALG-71, ALG-75).

## Scene

One Godot scene, a comparison stage at true game scale, side by side:
- Every unit role above standing beside a human-height reference.
- The strategic positions: every E-17 node kind on land (objective, staging, transit, chokepoint, flank_route, vantage, hazard_anchor) plus a cover obstacle, a slope with height bands, and a city footprint. Land only (DEC-lab-land-first-2026-10-30).
- A city or building footprint.
- A sliders panel, one per role, that scales the unit live and writes the values file on change.
- A metrics panel per role: radius in world units, units abreast across the narrowest choke on stage, units needed to ring the city footprint, seconds to cross the stage at walk speed.

## Values file

`data/unit_scale.toml` (DRAFT path): one table per role, keys radius and visual_scale. The sim's runtime radius reads from it (E3 runtime radius), so the number he picks is the collision radius, not only a look. The read-through is its own contract piece after the file is approved; this story writes the file only.

## Session

A Sonnet chat drives it with him: it reads the values file, he moves sliders or asks the chat to set numbers, a screenshot per change, and the final file is committed as his decision (a `decisions.md` row).

## Tests

`qa_state()` element inventory: every role present, every position present, a slider change writes the file. Positive control: a role removed from the scene fails the inventory test.
