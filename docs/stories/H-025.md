## Layout file

Every number in this section is an Architect draft dated 2026-10-30; Westley rules.

Path `docs/northstar/research/layer_dynamics/catalogue/<id>.toml`, id `L-0001` upward, and a sibling `<id>.json` with the same content (Godot reads JSON). Keys:
- `id` (string).
- `situation`: one of the closed list DRAFT-situation-kinds: chokepoint, vantage, cover, objective, staging, transit, flank_route, hazard_anchor, slope, city, trap, open_field.
- `landscape`: a stage preset name from the producer's closed list `presets.toml`; each preset is a land piece with bounds and layer count.
- `seed` (int).
- `predict`: "A", "B" or "draw"; `predict_why`: one sentence.
- `verdict`: "" until Westley; then "A", "B", "draw" or "deny". `feedback` (string).
- `[side_a]` and `[side_b]` tables, each with `headcount` (int, 8 to 256) and rows `[[side_a.units]]` / `[[side_b.units]]` with `role` (one of Raider, Interceptor, Vanguard, Warden, Bombard, Bastion, the roster at `scripts/skilllab/engine.py:16`), `x`, `y` (float, world units), `facing` (float, radians), `layer` (int, 0-based, below the preset's layer count).

## Producer

Module `scripts/skilllab/catalogue/produce.py`; CLI `python3 -m scripts.skilllab.catalogue.produce --out <dir> --situations <comma list or all> --pairs <"16:16,16:32,32:16"> --seed <int> [--plant <rule id>]`.
- `produce(situations: list[str], pairs: list[tuple[int,int]], seed: int, out: Path) -> list[Path]`: one layout per situation per pair, deterministic from the seed.
- `check_layout(layout: dict, presets: dict, rules: dict) -> list[str]`: the rule ids violated, empty when valid.
- A layout with violations is not written; the producer prints `REJECT <id> <rule id> <detail>` on stderr per violation and exits 2 if any layout was rejected, 0 otherwise.
- Rules live in `scripts/skilllab/catalogue/rules.toml` (closed list, machine-checkable): R1 every unit inside the preset's bounds; R2 no two units closer than 30 world units (two radii of `OM_UNIT_COLLISION_RADIUS` 15, ALG-68, `csrc/om_constants.h:581`); R3 every layer below the preset's layer count; R4 each side's headcount within 8 to 256 and equal to its unit row count; R5 roles from the roster.
- `--plant <rule id>` makes the producer emit one extra layout that breaks that rule on purpose (the positive control): the test asserts the REJECT line names it and no file for it exists.
- Batch one, DRAFT-batch-one: every situation kind at pairs 16:16, 16:32 and 32:16, 36 layouts (replaces the earlier 30).

## Shot

Scene `res://scenes/proto/layout_shot/layout_shot.tscn`, built on `scenes/ground3d/`. It reads the layout JSON path from the environment variable `OM_LAYOUT` and, when `OM_SHOT_OUT` is set, saves a PNG there after 30 frames and quits. Sides coloured (A blue, B red), a facing arrow per unit, layers drawn as stacked translucent planes, role shown as a glyph with a legend.

`qa_state()` keys: `scene` (the scene path), `layout_id`, `unit_count`, `units` (list of {id, side, role, layer, x, y, facing}), `legend` (list of role names drawn), `layers_visible` (bool).

PNG name `<id>.png` beside the layout file when the clerk runs the batch.

Note for the builder (read 2026-10-30): `scenes/ground3d/` has no scene file. `ground3d.gd` (`class_name Ground3D`) is a Node that builds its own SubViewport in `_ready()` and is fed by its owner through `set_terrain(t)` and `set_frame(frame, mission)`; its camera rig is driven by the owner, and it reads no environment variable. `ground_units.gd` `set_units(units, terrain, layer_floors_wu, flyer_types)` draws bodies, arrows and shadows. The shot scene therefore does the env read itself (`OS.get_environment("OM_LAYOUT")`, as `scenes/tactical_c/tactical_view.gd:295` does for `OM_SPACE_VIEW`), builds a terrain dict and frame from the layout and feeds `Ground3D`; it adds its own layer planes, glyphs and legend. Its root `qa_state()` is its own (the ground3d one has other keys), reached through `autoload/qa_daemon.gd:77`.

## Review

`scripts/skilllab/catalogue/review.py build --dir <catalogue> --out <catalogue>/review.html` writes one static page: per layout its PNG, situation, pair, predict and predict_why, and a verdict cell.

Westley answers in `docs/northstar/research/layer_dynamics/catalogue/verdicts.md`, a table `| id | verdict | feedback |` he edits (or dictates in chat and a clerk fills). `review.py apply --dir <catalogue> --verdicts <file>` writes `verdict` and `feedback` into each layout's TOML and JSON and prints `APPLIED <id> <verdict>` per row. A denied layout is listed by `review.py denied --dir <catalogue>` for the producer's next batch.

## Round two (2026-10-31, after Westley denied batch one)

Westley's words are in `docs/northstar/research/layer_dynamics/catalogue/verdicts.md`. The defect is round one's spec: the layout carries no landscape geometry, so every picture is two clusters on a flat plane. Round two is Ready; nothing from batch one is deduced or kept except the producer, the review tooling and the scene skeleton.

Layout format gains `[[features]]`, each `kind`, `x`, `y`, plus the kind's geometry, from the H-023 stage's values (DRAFT until H-023 locks them): `chokepoint` (two walls with `gap` 200 wu, `radius` 600), `vantage` (a raised disc `radius` 700, `height_band` 1), `cover` (two to four obstacle boxes `w` 120 `h` 60), `objective` (capture ring `radius` 300), `staging` (a marked square), `transit` (a route polyline and a destination marker), `flank_route` (a polyline), `hazard_anchor` (a disc `radius` 500, drawn as a hazard), `slope` (a band 600 wu long joining two height bands, R-001-06), `city` (footprint disc `radius` 400 with a 3 by 3 building grid), `trap` (a pocket of walls with one mouth), `open_field` (no feature). The producer places both sides relative to the feature (the defending side on or behind it, the other side approaching), writes `predict_why` naming the feature, and rule R6 (new, `rules.toml`) requires every layout except `open_field` to carry its situation's feature and every unit to stand off its walls by the collision radius.

Ground era terrain, not planes: a landscape's `layers` is the number of height bands on the land, drawn as terrain tiers joined by slopes (R-001-06, R-001-07: a walker has exactly one layer with ground under it at any point, so no stacked translucent planes in a ground preset). The stacked-planes drawing is kept only for a future space preset; none exists in `presets.toml` today, so the shot scene draws no planes.

The picture: the camera frames the bounding box of all units and features plus a 15% margin, never the whole land piece; a unit glyph is at least DRAFT-glyph-min-px 14 pixels across at that framing (the camera backs off until the box fits, then the glyph size is enforced by scaling the glyphs, not by moving the camera), with the role glyphs of the legend and a facing arrow; every unit draws its weapon range as a thin ring in its side's colour (range per role from the sim roster the lab uses, `scripts/skilllab/engine.py`, read at run time; a role without a range draws none and the legend says so); the feature is drawn in its own colour with its label; the legend names the situation and the predicted winner. `qa_state()` gains `features` (list of {kind, x, y}) and `ranges_visible` (bool); the test asserts both and that the PNG's unit glyph bounding boxes are at least the minimum size (read from `qa_state`'s `glyph_px`).

Review: the Architect opens every picture before it is copied to `docs/northstar/story_reviews/westley/` and rejects it itself when the feature, the glyphs or the ranges are not visible; a picture reaches Westley only after that look, and the README row says the Architect looked (DEC-architect-views-shots-2026-10-31). Batch two is 12 pictures again, one per situation kind, on `small_flat` and `small_tiered` only, with headcounts spread 8 to 64 a side (the 16 against 16 of batch one is one point; Westley: both sides vary).
