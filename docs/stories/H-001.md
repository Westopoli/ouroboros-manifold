## Behaviour

`scripts/play.sh [--scene <res path>] [--seed N] [--story <id>] [--tree <path>] [--check] [--dry-run] [--keep]`:

1. Tree: `--tree` names a checkout to play (the clerk passes the merged worktree). The script never imports or builds inside that tree: it makes a scratch copy `git clone -q --shared <tree> <TMPDIR>/play-<sha>` at the tree's HEAD and does every later step there, so Godot's rewrite of tracked `.import` and `.uid` files never dirties a landing worktree; the scratch copy lives under `${TMPDIR:-$HOME/Projects/om-push/tmp}` (never a bare `/tmp` default: it is a 16 GB tmpfs and one clone is about 450 MB) and is removed on exit unless `--keep` is given, since a game handed to a human in `--tree` mode is the only reason to keep it (the first landing attempt was rejected by the pre-gate's noise check on 224 such files). Without `--tree` the script refreshes `~/Projects/om-push/main` to `origin/main` (`git fetch -q origin && git reset -q --hard origin/main`; the checkout is made on first use with `git clone --shared` and is pinned, never built in by any other script).
2. Build: `scripts/build_pipe_linux.sh` in the tree; copy `dist/linux/ouroboros_pipe` to `pipe/ouroboros_pipe` if the client reads it there (the test writer dumps which path `autoload/c_bridge.gd` opens and the builder uses that one). A non-zero build exits non-zero with the last 20 compiler lines.
3. Story: with `--story <id>`, read the `Scene:` line of `docs/stories/<id>.md` in the tree (format `Scene: <res path> [args...]`); the line's path and arguments replace `--scene` and `--seed`.
4. Import once: `~/.local/bin/godot.real --headless --path <tree> --import` with `timeout 600`.
5. Launch on the real display (`$DISPLAY` must be set; exit non-zero with `no display` otherwise): `~/.local/bin/godot.real --path <tree> [<scene>] -- [--seed N] [the Scene line's other arguments]` (nothing in `autoload/` reads `--story`, so it is never passed to Godot; the story's state comes from the Scene line's arguments alone), detached, stdout and stderr to `<tree>/.play.log`.
6. Window: poll `xdotool search --name Ouroboros` (or `wmctrl -l` if xdotool is absent) every second up to DRAFT-play-window-s 60; print `PLAY window <seconds>s` and exit 0 when it appears; past the limit print `PLAY REJECT no window after 60s` plus the last 20 lines of `.play.log` and exit 2.
7. `--check` (used by the clerk): after the window, wait DRAFT-play-settle-s 10, read `qa_state()` through the QA port (`--qa-port`, `autoload/qa_daemon.gd`), print `PLAY scene <scene name> reached` when the `scene` key equals the story's scene, else `PLAY REJECT scene <got> wanted <scene>` exit 3; then close the game. Under `--check` Godot runs with `XDG_DATA_HOME=<scratch>/xdg`, so a stored profile cannot change the scene reached (DEC-play-check-scratch-userdir-2026-10-30); the `Scene:` line stays the privacy modal, the boot scene on a fresh profile.

8. `--dry-run`: print the tree, the build line and the launch line, then exit 0 without building or launching.

Every number here is a draft registered in `docs/method/README.md` Numbers; Westley owns them.

## Tests (red first, positive control)

- Control: `scripts/build_pipe_linux.sh` on the test tree exits 0 (green today).
- After any `--tree` run, `git -C <tree> status --porcelain` is empty (the tree is never dirtied).
- After a `--tree` run without `--keep`, the scratch directory it printed no longer exists; with `--keep` it does (positive control).
- A scratch worktree with a broken `project.godot` makes the script exit non-zero with the Godot error line in its output.
- With `--story H-001` and a story file whose `Scene:` line names `res://scenes/privacy_modal/privacy_modal.tscn`, the launch line printed by `--dry-run` carries that path.
- Without `$DISPLAY`, the script exits non-zero with `no display`.
- On the real display (marked display-bound in the test's docstring, run by the clerk, not by pre_gate): `scripts/play.sh --tree <worktree>` prints `PLAY window` under 60 s.
