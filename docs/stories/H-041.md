## Contract change (lands first, documented here)

- `csrc/ouroboros_sim.h`: `int om_roster_set_collision_radius(om_world *w, int unit_type, double radius);` beside `om_roster_set_reach` (line 2008). Returns 0, or -1 for an unknown type or a radius outside DRAFT-radius-bounds 1 to 200. Recorded in `signatures.toml`.
- The per-type radius replaces `OM_UNIT_COLLISION_RADIUS` at its eleven use sites (`csrc/unit.c:2579`, `tactical_move.c:95,96,390`, `mission.c:2470,2743`, `enemy_macro.c:964,965`, and the spacing comments); a site that has no unit type in hand (grid cell size, margins) uses the roster's largest radius. `OM_TP_UNIT_COLLISION_RADIUS` (world-wide tuning knob, `ouroboros_sim.h:1021`) keeps working as a multiplier on the per-type value; its reading is documented at the knob.
- Determinism: the radius is read once at `om_roster_*` time, never from the file inside the tick.
- When a type's radius is never set, its value stays `OM_UNIT_COLLISION_RADIUS` 15, so every existing trace, golden and lab fight is byte-identical (a test pins this).

### Size rulings (Architect 2026-11-02, from the code read)

- (a) One source, one lookup. `scenes/tactical_c/unit_visuals.gd` line 12 `MAX_VISUAL_SCALE := 1.0` caps every unit at 1.0, so Westley's Bombard 1.44 and Bastion 2.00 could never draw at his size. `UnitVisuals` reads the era manifest's `visual_scale` (default 1.0) while `EraThemeResolver.get_unit_visual_scale` (default `EraConfig.UNIT_VISUAL_SCALE` 2.0) is called by nothing: two unrelated defaults. Ruling: the file wins and there is ONE lookup. The cap is removed (the file's own bounds apply), `UnitVisuals._vscale` goes through the single lookup, and neither the manifest `visual_scale` nor the era default decides unit size any more (the era default survives only as the lookup's missing-file fallback, see Tests).
- (b) Meaning. His `visual_scale` is the scale of the H-023 scene (`scenes/proto/unit_scale/`), where a unit's drawn radius is `visual_scale` x 15 wu, equal to the file's `radius`; so a unit's ground footprint radius in the game must equal the file's `radius` (4.05 Raider to 30.00 Bastion). The builder measures each model's native footprint radius, derives the factor per type, and REPORTS the table (type, native footprint, factor, resulting footprint) before editing. A model that cannot match (a mesh whose footprint is not roughly circular) is reported as a question for Westley, who owns looks. `drawn_scale` in the `qa_state` `unit_scale` key is the factor actually applied; the QA test asserts the resulting footprint equals the file's `radius` within a tolerance the test writer proposes (Westley owns tolerances).

## Tests

- `tests/csim/test_collision_radius.py`: two roles with radii 15 and 30 push apart at the sum of their radii (ALG-68); unknown type and out-of-bounds radius return -1 (positive control); same seed and command stream give a byte-identical trace when every value is 15 or the function is never called.
- `tests/qa/test_unit_scale_readthrough.py` (headless). QA seam (Architect ruling 2026-11-02, the beta Dispatcher's question): there is NO radius getter in C; the contract adds only the setter, and a getter would widen the frozen header for a fact `tests/csim/test_collision_radius.py` already proves. `scenes/tactical_c/tactical_view.gd` `qa_state()` gains an additive key `unit_scale`, one entry per role `{radius, visual_scale, drawn_scale}`: `radius` is what `c_bridge` pushed to the roster at boot (15 on the missing-file fallback), `visual_scale` is `EraThemeResolver.get_unit_visual_scale(role)` after the file is applied, `drawn_scale` is the factor actually applied to the unit's model (`UnitVisuals._vscale[type]`), present only while the tactical view is up, null otherwise; the key exists for the QA harness only (qa_state keys are not a frozen contract, so no contract story). The file asserts: with Westley's file each role's `radius` and `visual_scale` equal the file's; the resulting footprint (the model's native footprint radius times `drawn_scale`) equals the file's `radius` within a tolerance the test writer proposes (Westley owns tolerances; see the size rulings above); with the file missing the `radius` stays 15, `visual_scale` is the era default and exactly one warning line is printed on stderr.
