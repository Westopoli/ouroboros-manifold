# H-069: loading-screen-requests-once

"The beta's start does not shout at itself: asking for the same scene twice is not a replacement."

Flag client; tool Workflow; no scene. Ready 2026-11-02; Channel: beta. Findings: beta Dispatcher B0 note (137 `SceneRouter: queued 'main_menu' replaced by 'main_menu'` warnings in 12 s) and the editor-debug log (`docs/northstar/plans/editor_debug/log.md`, still red).

## Why

`scenes/loading_screen/loading_screen.gd:47` (`_process`) calls `SceneRouter.go_to(_target_scene)` every frame once `_skip_to_main` is set. `autoload/scene_router.gd:43` (`go_to`) warns `SceneRouter: queued '%s' replaced by '%s'` when a request arrives while a transition runs and another request is already queued. So the loading screen, which stays alive until the swap in the middle of its own fade, replaces its own queued request with itself on every frame until it is freed.

The per-frame request is, in the Architect's reading, a retry for the privacy-flag race: the harness comments in `tests/qa/desktop/daemon_client.py` `GodotGame.start` document that once `user://privacy_accepted` exists, `SimBridge`'s `sim_ready` fires while `SceneRouter` is still mid-transition from `privacy_modal`, `go_to` drops the request (the `_transitioning` guard) and nothing else ever calls `go_to` again, so the loading screen never leaves. (Today `go_to` keeps one pending request in `_pending` instead of dropping it, `tests/test_scene_router_queue.gd`; the comment may predate that. The builder confirms the reading by reading both files, and reports.)

## Change (the Architect's draft; the builder reads the code and reports before editing)

`SceneRouter` returns silently when the incoming request names the same scene as the one already queued (nothing is replaced), and keeps the warning for a request naming a DIFFERENT scene. The loading screen's retry stays. No change to the privacy-race behaviour.

The builder also reports, before editing, what a request does when it names the scene the router is already transitioning TO (`_current_scene_name` is set when the transition starts): with only the change above, the first such request is queued (nothing was queued yet) and runs a second `main_menu` transition after the first one finishes. If so, the builder says it and proposes whether that request returns silently too; the story does not decide it.

## Tests (`tests/qa/test_scene_router_dup.py`, new; a different Sonnet writes it, red on main)

- Two requests for the same scene while a transition runs produce no warning and one transition.
- A request for a different scene while one is queued still warns (control).
- Counting `go_to` calls from the loading screen is not asserted.
