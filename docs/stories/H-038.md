# H-038: present-on-boot

"The game draws its first scene on my desktop whatever size the window comes up at, fullscreen included; I never see the splash and nothing else."

Flag client; tool Workflow; branch `s/H-038-present-on-boot`; blocks H-028 (stable beta: the shipped fullscreen default is the failing case). From the measured finding of 2026-10-31 (H-031 Piece two): on GNOME Wayland the project boots fullscreen (`window/size/mode=3`), is switched to windowed when `--windowed` is given, and then presents nothing after the splash when the window's requested size equals the project viewport or when it stays fullscreen; Godot reports windowed mode with the monitor's size; a one-pixel `window_set_size` after boot unsticks presentation; minimal projects do not show the fault, so something in this project's startup (first suspects: the autoloads `qa_daemon`, `scanline_overlay`, `debug_overlay`, and the privacy modal's first frame) interacts with the fullscreen-then-windowed flip.

## Two parts, in order

1. Diagnosis (read-only Sonnet engineer, scratch clone, Westley's session env, portal capture per H-031): bisect the autoloads and the first scene by removing them one at a time from a scratch copy of `project.godot` and launching `--windowed --resolution 1920x1080`; report which removal makes the game draw, with the capture. STOP at twelve launches. The result names the file the fix goes in. No code change from this part.
2. Fix (builder, after the Architect names the file from part 1): the smallest change in that file that makes the 1920x1080 windowed launch and the fullscreen default draw, with a comment naming this story and the finding. If part 1 finds nothing, the fallback is a one-pixel `DisplayServer.window_set_size` nudge DRAFT-nudge-delay-s 0.5 s after the first process frame in `autoload/ui_data_bus.gd` `_ready()` (the autoload that already owns window mode), commented as a workaround with the open question.

## Tests

`tests/qa/test_present_on_boot.py` (Xvfb, Wayland is not available there, so the test pins the mechanism, not the desktop): with the fix in place, a launch at `--windowed --resolution 1920x1080` reaches `qa_state()` with the first scene and `DisplayServer.window_get_size()` equal to the requested size within 3 s (red today: the probe reports the monitor size); positive control: 1280x720 passes today. The desktop proof is the clerk's portal capture under Westley's session env (H-031), on both the windowed 1920x1080 launch and the fullscreen default.
