# H-038: present-on-boot

"The game draws its first scene on my desktop whatever size the window comes up at, fullscreen included; I never see the splash and nothing else."

Flag client; tool Workflow; branch `s/H-038-present-on-boot`; blocks H-028 (stable beta: the shipped fullscreen default is the failing case). From the measured finding of 2026-10-31 (H-031 Piece two): on GNOME Wayland the project boots fullscreen (`window/size/mode=3`), is switched to windowed when `--windowed` is given, and then presents nothing after the splash when the window's requested size equals the project viewport or when it stays fullscreen; Godot reports windowed mode with the monitor's size; a one-pixel `window_set_size` after boot unsticks presentation; minimal projects do not show the fault, so something in this project's startup (first suspects: the autoloads `qa_daemon`, `scanline_overlay`, `debug_overlay`, and the privacy modal's first frame) interacts with the fullscreen-then-windowed flip.

Fix (builder, after the Architect names the file from part 1): the smallest change in that file that makes the 1920x1080 windowed launch and the fullscreen default draw, with a comment naming this story and the finding. If part 1 finds nothing, the fallback is a one-pixel `DisplayServer.window_set_size` nudge DRAFT-nudge-delay-s 0.5 s after the first process frame in `autoload/ui_data_bus.gd` `_ready()` (the autoload that already owns window mode), commented as a workaround with the open question.

## Part 1 result and part 2 (2026-10-31)

Part 1 (read-only engineer, eight launches, every verdict from a portal capture): the fault is not an autoload in general; it is the stored display settings. The project uses a custom user dir (`project.godot` `config/custom_user_dir_name="data"`), so Westley's settings live at `~/.local/share/data/settings.cfg` (the Architect's earlier search under `app_userdata/` was the wrong directory; "stored settings ruled out" in DEC-display-fault-measured-2026-10-31 is withdrawn). His file has `resolution_index=2`, `fullscreen=false`. With it present, `_apply_stored_settings()` (`autoload/ui_data_bus.gd` lines 122 to 126) runs inside `_ready()` before the first frame and calls `window_set_mode(WINDOWED)` then `window_set_size(RESOLUTIONS[2])` = 1920x1080, the project viewport: splash only, windowed or fullscreen (launches 3, 4, 7). With no file, or with the UIDataBus autoload removed, or with the stored index changed to 1600x900, the game draws (launches 1, 2, 5, 6, 8). The earlier `--resolution` finding fits: a request equal to the stored size leaves nothing to change.

Part 2, the file is `autoload/ui_data_bus.gd`, function `_apply_stored_settings()`. The fix: the display half (mode, size, vsync) runs after the first rendered frame, not inside `_ready()`: `_apply_stored_settings()` applies the audio buses at once and defers the display block to a new `_apply_display_settings()` called after `await get_tree().process_frame` DRAFT-display-apply-frames 2 times; and the size is applied only when it differs from `DisplayServer.window_get_size()`. Comment names this story and the finding. No other file changes; `_settings` keys and `save_settings` are untouched. The autoload order and `project.godot` stay.

Tests (`tests/qa/test_present_on_boot.py`, Xvfb, scratch `XDG_DATA_HOME` with a planted `data/settings.cfg` holding `resolution_index=2`, `fullscreen=false`, as DEC-play-check-scratch-userdir allows): with the planted file and `--windowed --resolution 1920x1080`, `qa_state()` reports the first scene and a new key `display_settings_applied_frame` (an int, the engine frame at which the display block ran) of at least 1 within 3 s; red today because the key is absent (the block runs at frame 0 inside `_ready()`). Positive control: without the planted file the same launch reaches `qa_state()` today. Negative control: a planted file with `resolution_index=1` yields `window_get_size()` 1600x900 after the apply (the setting still takes effect). The desktop proof is the clerk's portal capture under Westley's session env with his real settings file in place, on the windowed 1920x1080 launch and on the fullscreen default (H-031 piece two's `screen_capture.sh`).
