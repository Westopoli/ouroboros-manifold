# H-067: beta-in-the-editor

"I'd like to set up the beta to be a godot project I open in the ouroboros directory. Something I can open in the editor myself, not run through a command." (Westley, 2026-11-02)

Flag harness; tool Workflow; no scene. Spec'd 2026-11-02, waits on Westley's go; Channel: beta.

## Why

The repo root is already a Godot 4.7 project whose F5 chain is the approved screens (main menu, galaxy view, mission preparation). Four things stand in the way, each measured by an engineer on 2026-11-02:

1. Beta mode needs a flag the editor run does not set. H-060 ruling 7 makes beta mode one helper, `BetaMode.active()`, which reads the environment variable `OM_BETA`, the `--om-beta` argument, or `beta_build.txt` beside the executable; an editor F5 sets none of these.
2. The C sim pipe `pipe/ouroboros_pipe` is git-ignored, and his checkout's copy dates from Oct 9, before 72 `csrc/` commits, so a fresh clone or a stale pipe makes the galaxy view show "pipe binary missing" or protocol errors (`autoload/c_bridge.gd` `_pipe_path()` uses `res://pipe/ouroboros_pipe` when the `editor` feature tag is on).
3. The `addons/godotsteam/` libraries are git-ignored, so the editor prints two harmless ERROR lines on every open and run. Every Steam use is guarded by `Engine.has_singleton("Steam")`; the beta chain never touches Steam.
4. Which folder he opens. His checkout at 761c36cd has an EMPTY intersection between its dirty paths and the 23 files changed upstream, so `git pull --ff-only` works today; future landings that touch `README.md` or `.claude/settings.local.json` would block it. A clone he owns avoids that.

## Change

- (a) New `scripts/setup_editor.sh`. It runs `scripts/build_pipe_linux.sh` and copies `dist/linux/ouroboros_pipe` to `pipe/` only when `csrc/` is newer than the copy; fills `addons/godotsteam/` from `$HOME/Projects/om-push/cache/godotsteam/` with `cp -a`, falling back to `scripts/fetch_godotsteam.sh`; prints `EDITOR READY <tree>` or `EDITOR SETUP FAILED <step>`. `--check` prints the steps and changes nothing.
- (b) README gets an "Open in the editor" paragraph: Godot 4.7.2 from `~/Apps`, run `scripts/setup_editor.sh` once and after any pull that changes `csrc/`, open `project.godot`, F5. It also says which engine version the gate uses (`godot.real` is 4.6.3) versus the editor.
- (c) galaxy_view's "pipe binary missing" text names `scripts/setup_editor.sh`.
- (d) A committed way for an editor F5 to be beta mode: the project setting `editor/run/main_run_args` set to `-- --om-beta` in `project.godot` (only the editor applies it; exports and `godot --path` runs do not). UNVERIFIED by the engineer: where the argument lands (args or user args) and the exact stored key spelling in `project.godot`; a first step of the builder is to confirm both in a real editor open and report. Fallback: start the editor with `OM_BETA=1` in the environment. The `project.godot` line is its own last commit (shared file).

Depends on H-060 ruling 7 (`BetaMode.active()`).

## Tests (a different Sonnet writes them, red on main)

- `tests/method/test_setup_editor.py` (new): `--check` lists the steps and changes nothing; a stubbed build route produces `EDITOR READY`; a failing build prints `EDITOR SETUP FAILED pipe`; a stale pipe (older than `csrc/`) is rebuilt, a fresh one is not; a missing cache falls back to the fetch script (stubbed); a positive control for each.
- `tests/qa/test_editor_open_headless.py` (new, runs only after the sweep and never during a sweep): `godot --headless --import --path <tree>` (the 4.7.2 editor binary, path from the environment variable `OM_EDITOR_GODOT`, test skipped with a visible reason when unset) exits 0 with zero `ERROR` or `SCRIPT ERROR` lines on a tree set up by the script; positive control: a tree without the Steam libraries must fail the check.
