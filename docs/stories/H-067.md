## Why

Westley's editor-debug chat found no project source bug. His own checkout (`~/Projects/ouroboros-manifold`, main at 761c36cd) ran the whole chain (privacy, menu, galaxy, a mission, Deploy, a 2D match, end of mission) under Godot 4.6.3 once he REBUILT his stale pipe; no project source file changed. His editor and `godot.real` are the same version, 4.6.3 (the earlier remark that the editor was 4.7.2 was wrong). `project.godot` says `4.7` in `config/features` since 2026-09-16 and is left as it is. What stood in the way was environment state, and three things of it need a committed answer:

1. A stale pipe. `pipe/ouroboros_pipe` is git-ignored and untracked, so nothing compares it to `csrc/`. His copy was 123 KB from 2026-10-09; the current build is 1.69 MB, and `OM_ABI_VERSION` became 9 on 2026-10-29. The error he saw at Deploy, `Invalid access to property or key 'done' on a base object of type 'Dictionary'` (`scenes/tactical_c/objective_markers.gd:43` reads `o["done"]`, a candidate site; the log did not capture the `at:` line), disappeared with the rebuilt pipe. The cause is inferred, not proven: forcing a stale binary in the worktree gave `live snapshot failed: timed out waiting for the first snapshot` from `galaxy_view` and `mission_briefing` (log row 1b), not `'done'`. Nothing in `autoload/` or `scenes/` checks the pipe's `abi`: `docs/architecture.md` (the hello frame, line ~217) says the pipe's first frame carries `"abi"` (`om_abi_version()`), but `git grep -n -i -E '\babi\b' -- autoload scenes` finds no read of it, and `autoload/c_bridge.gd` `pump()` has no `hello` branch (read at origin/main a964e12d), so the frame is queued and ignored. A stale pipe therefore fails late, in a way that looks like a game bug.
2. A first import leaves the tree dirty. A fresh tree imported with `godot.real --headless --import --path .` ends with 222 dirty entries (`git status --short` in the spike worktree `om-push/wt/ed-run`, kept there as reference): 47 tracked `.import` files rewritten by 4.6.3 and 175 untracked `.uid` sidecars (173 `.gd.uid`, 2 `.gdshader.uid`). CLAUDE.md says a Godot `.uid` sidecar is committed with its script; these never were. Before any import the same tree shows 98 distinct `Cannot open file 'res://.godot/imported/...'` lines (log row 2).
3. The `addons/godotsteam/` libraries are git-ignored, so a checkout prints benign ERROR lines on every open and run (log row 3: the GDExtension 'dynamic library not found' line, 'Error loading extension' and two `os_unix.cpp:1061` ERR_FILE_NOT_FOUND lines). Every Steam use is guarded by `Engine.has_singleton("Steam")`; the beta chain never touches Steam.

Still red and NOT in this story: the exit-time renderer leaks (`Pages in use exist at exit`, shaders and RIDs never freed, ObjectDB instances leaked; the owner scene is not found) stay a finding in the log; the `SceneRouter: queued 'main_menu' replaced by 'main_menu'` warning is H-069; the editor's beta flag (`main_run_args`) is H-060 ruling 8, its last commit. The leaks print ERROR lines at quit, so the done-when counts ERROR and SCRIPT ERROR lines while the chain runs, before quit, until a story takes the leaks.

## Change

Six parts, in this order; none waits for H-060.

1. New `scripts/setup_editor.sh`. It builds the pipe with `scripts/build_pipe_linux.sh` and copies `dist/linux/ouroboros_pipe` to `pipe/ouroboros_pipe` (atomic: `cp` to a temporary name beside it, then `mv`, because a running binary is busy) when `csrc/` is newer than the copy or the copy is missing; fills `addons/godotsteam/` from `$HOME/Projects/om-push/cache/godotsteam/` with `cp -a`, falling back to `scripts/fetch_godotsteam.sh`; runs `godot.real --headless --import --path .` once; prints `EDITOR READY <tree>` or `EDITOR SETUP FAILED <step>` (steps `pipe`, `steam`, `import`). `--check` prints the steps and changes nothing.
2. The client refuses a stale pipe. Where the pipe's `abi` is read at session open, a mismatch with the expected value shows the ErrorPanel text `pipe binary is out of date (abi <n>, expected <m>): run scripts/setup_editor.sh`. The expected value lives in ONE GDScript constant, and a test pins it equal to `OM_ABI_VERSION` in `csrc/ouroboros_sim.h`, so a header bump without the client fails the gate. No change to the pipe frames: the contract is frozen and `abi` is already in the hello frame. The builder reads the code first (the likely sites are `autoload/c_bridge.gd` `open_session` and `pump()`, with `scenes/galaxy/galaxy_view.gd` `_show_load_error` showing `last_error()` in the ErrorPanel) and reports where the abi is available; if it is not exposed to GDScript the story STOPS for a contract ruling, and nothing is changed in `csrc/` or the frames.
3. Commit the import outputs once, from a clean 4.6.3 import of the merged tree: the 175 `.uid` sidecars and the 47 regenerated `.import` files (the list is `git status --short` in `om-push/wt/ed-run`, reference only; the builder regenerates it, because other landings add scripts). After this commit a first open or `--import` leaves `git status` clean. Commit it after parts 1, 2 and 5 and re-do the import after merging main, since every landing that adds a script or an asset adds its own sidecar or `.import`.
4. README gets an "Open in the editor" paragraph: run `scripts/setup_editor.sh` once and after any pull that changes `csrc/`; open `project.godot`; F5. It says the editor, the gate and the beta export are all 4.6.3.
5. The "pipe binary missing" text (set in `autoload/c_bridge.gd` `open_session` and shown by `scenes/galaxy/galaxy_view.gd`; the builder says which file carries the string) names `scripts/setup_editor.sh`.
6. A hand-over file for Westley, `docs/northstar/story_reviews/westley/beta_stage0/editor-setup.md`, written by the builder after the story is green: exactly what he types in his own checkout `~/Projects/ouroboros-manifold` to get from its current state to a running editor chain (what to do about his untracked sidecars and modified `.import` files that the import already created and that will now arrive from main: the builder verifies the procedure on a fresh clone and READS his checkout's `git status --short` read-only, and writes commands that touch only the import outputs, never his `README.md`, `.claude/settings.local.json` or other uncommitted work), plus what to expect and what approve and deny mean.

## Tests (a different Sonnet writes them, red on main)

- `tests/method/test_setup_editor.py` (new): `--check` lists the steps and changes nothing; a stubbed build route produces `EDITOR READY`; a failing build produces `EDITOR SETUP FAILED pipe`; a stale pipe (older than `csrc/`) is rebuilt and a fresh one is not; a missing cache falls back to the fetch script (stubbed); a positive control for each.
- `tests/qa/test_pipe_abi_check.py` (new): a stub pipe reporting a wrong abi gives the ErrorPanel text with both numbers; control: a matching abi shows no error; the GDScript constant equals `OM_ABI_VERSION` in `csrc/ouroboros_sim.h`.
- `tests/qa/test_editor_import_clean.py` (new): a fresh clone after `scripts/setup_editor.sh` has an empty `git status --short`; skipped with a visible reason when `godot.real` is missing; never run during a sweep; positive control: a tree with one script's `.uid` removed reports it.
