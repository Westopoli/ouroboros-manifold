# H-050: status-check-row-scope

"The status check counts a story only when a commit changed that story's own row, not when its id is mentioned inside another row."

Flag harness; tool Workflow; no scene. Ready 2026-11-01 (DEC-status-check-row-scope-2026-11-01); built the same day on `s/H-050-status-check-row-scope`.

## Why

`scripts/specfactory/status_check.py` decided whether a story "counts" (is subject to the trailer checks after the anchor) with `git log <anchor>..<ref> -S<id> -- stories.md harness.md`, which matches any commit that changed the number of mentions of the id anywhere in those files. The H-049 finding row said "S-110 diagnosis", so S-110's September `Seen` row suddenly needed a `Seen S-110` commit and H-038's gate was rejected (`STATUS seen_without_commit DRIFT S-110`). The same pickaxe also misses a plain status edit of a story's own row when the mention count does not change (Ready to Seen on one line).

## Change

In `status_check.py`, the "counts" test becomes a diff of the row files between the anchor and the ref filtered to lines that start with `| <id> |` (the row whose first cell is the id); a story counts when such a line was added, removed or changed. No other check changes. Comment at the site names this story and the two cases above.

## Tests (`tests/specfactory/test_status_check.py`)

- A commit that adds a row mentioning another story's id in its text does not make that other story count (the H-049 case; positive control: the same commit does make the new row's own story count).
- A commit that edits only the status cell of a story's own row (Ready to Seen, no `Seen <id>` commit) makes it count and the check reports `seen_without_commit` for it (the pickaxe-miss case; this is the third red test and is wanted).
- The existing checks (`land_trailer`, `tested_without_land`, `seen_without_verdict`, `seen_without_commit`, the sweep line) are unchanged on the existing fixtures.
