# H-068: qa-pollers-self-connect

"A proof run never mistakes a socket talking to itself for a game that is up."

Flag harness; tool Workflow; no scene. Ready 2026-11-02, after H-066 lands and a sweep is green; Channel: lab. Follow-up to H-066 (DEC-h066-self-connect-2026-11-02): H-066 fixes the shared Python helper `wait_for_port`; three other places poll the same way and are not covered.

## Why

On Linux a `connect()` to a closed 127.0.0.1:P, with P inside the ephemeral range 32768 to 60999, can be given source port P and connect to itself (TCP simultaneous open): `getsockname()` equals `getpeername()`, nothing is listening, and the poller sees "ready"; the game's own listen on P then fails (err 22, ERR_ALREADY_IN_USE). H-066 part 6 fixes this in `wait_for_port` (`tests/qa/desktop/daemon_client.py`) for its roughly 25 call sites; the three places below poll the same way and the fix does not reach them (sites verified against origin/main 2026-11-02).

1. `scripts/qa_harness.sh`, the `LIVENESS_PY` heredoc (lines 149 to 260): the loop at lines 192 to 198 polls `socket.create_connection` (line 194) every 0.25 s until the port opens, and treats any successful connect as the game being up. The port comes from `pick_qa_port` (line 102; the range is at line 106, 47400 to 47499), inside the ephemeral range. A self-connect passes the loop and the first real call then fails or reads its own echo.
2. `scripts/play.sh`: `qa_scene` (lines 111 to 118; its `create_connection` is line 115) is called in the Wayland `until` loop at line 125 and once at line 151, the check that reads the scene for the Played proof. The port is `bind(0)` at line 102, kernel-chosen from the ephemeral range. A self-connect echoes the request back; the `["result"]` index then fails on the echoed list and `2>/dev/null` hides the error. In the loop at line 125 that retries (milder than the test case); at line 151 there is no retry, so by reading the code an empty scene would print `PLAY REJECT scene` (exit 3). This is the proof-capture path of every Played proof.
3. `tests/specfactory/test_gate_userdir.py`: fixed ports 47590 to 47593 (the `_make_game` default at line 468, then lines 519, 521 and 547). They sit inside the ephemeral range, and they collide across parallel runs, which H-059 makes normal.

Not exposed: `autoload/qa_daemon.gd` (connects once to an already-confirmed listener), `tests/method/test_play_proof.py` (server side), `simulation/perf_probe_client.py` (a single connect), the UDP lobby tests.

## Change (harness only; new code in a new file, the shell edits are the wiring commit and come last)

1. A new small file `scripts/qa_wait_port.py` with `listening(port)`, which returns True only for a connect whose `getsockname()` differs from its `getpeername()`, and a `main()` so shells call `python3 scripts/qa_wait_port.py <port> [timeout]`: exit 0 when the port is listening, exit 1 on timeout; it prints `PORT READY <port>` or `PORT TIMEOUT <port>`.
2. `scripts/qa_harness.sh` and `scripts/play.sh` call it instead of their embedded Python polling: the connect loop in `LIVENESS_PY` (lines 192 to 198) is replaced by the call, and `qa_scene` in `play.sh` asks the helper before it sends its state request. The request-and-reply code that talks to a confirmed listener stays.
3. `tests/specfactory/test_gate_userdir.py` uses `pick_free_port` from `tests/qa/desktop/daemon_client.py` (already imported there as `dc`) in place of the fixed 47590 to 47593 (a clerk, under `docs/method/rulebook.md` with a Test-defect trailer, since the file is a test).
4. A `# See also:` comment at each changed site, pointing at `docs/stories/H-066.md` and `docs/stories/H-068.md`.

`scripts/play.sh` is the Played-proof path of every landing, so it is changed under this story's own gate (DEC-h068-qa-pollers-2026-11-02).

## Tests

`tests/method/test_qa_wait_port.py` (new; a different Sonnet writes it, red on main).

1. A socket bound to (127.0.0.1, P) and connected to (127.0.0.1, P) makes `listening(P)` False; control: a normal listener on P gives True.
2. The CLI prints `PORT READY` and exits 0 for a listener, and prints `PORT TIMEOUT` and exits 1 for a port nobody holds (timeout 1 s).
3. `scripts/play.sh` and `scripts/qa_harness.sh` call `scripts/qa_wait_port.py` and no longer contain their embedded `create_connection` polling loops (grep-based; positive control: the same grep finds the old loop in the base version of each script, held as a string fixture).
4. `tests/specfactory/test_gate_userdir.py` no longer names the literal ports 47590 to 47593.
