# H-004: the 30B plays main nightly

"Every night the 30B plays today's main through the same command I use and what it finds shows up as harness stories, never as edits."

Gate flag harness; tool Workflow; Branch `s/H-004-nightly-play`. After H-001.

## Files

- `scripts/method/nightly_play.sh` (new, about 40 lines): `scripts/play.sh --check` on `~/Projects/om-push/main`, then keeps the game open for DRAFT-nightly-play-minutes 20 and closes it; every `PLAY REJECT` line and every Godot `ERROR`/`SCRIPT ERROR` line in `.play.log` becomes one `FINDING <words>` line in `~/Projects/om-push/nightly/<date>.log`. The 30B driving the session is H-007 (no identifiable 30B runner exists under `scripts/` today: `scripts/qa/` is a detector library and `scripts/qa_harness.sh` takes no model); `--dry-run` prints the play line without running it.
- `scripts/specfactory/systemd/om-nightly-play.service` and `.timer` (23:00, before the sweep at 23:30).
- `scripts/method/file_findings.py <log> <harness.md> [--push]` (new, about 60 lines): reads the log's `FINDING <words>` lines and appends one `H-` row per new finding to the harness file given (status `Spec'd`, words quoted from the line, depth `nightly/<date>.log` with the date from the log's file name); without `--push` it touches no git; with `--push` (the timer's call) it commits on a branch `s/H-nightly-<date>` from `origin/main` and pushes it for the Architect to triage. It never edits a story or a test.
- `tests/method/test_nightly_play.py` (new).

## Tests

- A fixture log with two `FINDING` lines yields two rows with the next free `H-` ids (positive control: a log with none yields no diff).
- The timer units parse.
- `nightly_play.sh --dry-run` prints the play line and the QA line without running them.
