# H-004: the 30B plays main nightly

"Every night the 30B plays today's main through the same command I use and what it finds shows up as harness stories, never as edits."

Flag: harness. Tool: Workflow. Branch `s/H-004-nightly-play`. After H-001.

## Files

- `scripts/method/nightly_play.sh` (new, about 40 lines): `scripts/play.sh --check` on `~/Projects/om-push/main`, then the existing QA daemon session (`scripts/qa/` runner with the 30B, same arguments the QA clone used on 2026-09-28) for DRAFT-nightly-play-minutes 20, log to `~/Projects/om-push/nightly/<date>.log`.
- `scripts/specfactory/systemd/om-nightly-play.service` and `.timer` (23:00, before the sweep at 23:30).
- `scripts/method/file_findings.py` (new, about 60 lines): reads the log's `FINDING` lines and appends one `H-` row per new finding to `docs/method/harness.md` (status `Spec'd`, words quoted from the log, depth `nightly/<date>.log`), on a branch `s/H-nightly-<date>` pushed for the Architect to triage; it never edits a story or a test.
- `tests/method/test_nightly_play.py` (new).

## Tests

- A fixture log with two `FINDING` lines yields two rows with the next free `H-` ids (positive control: a log with none yields no diff).
- The timer units parse.
- `nightly_play.sh --dry-run` prints the play line and the QA line without running them.
