# H-047: userdir-home-guard-scope

"The gate's user-settings isolation tests run wherever the gate puts its temp files, and still refuse to plant anything in my real home."

Flag harness; tool Workflow; no scene. Ready 2026-11-01. Repairs the last two new reds of the sweep at 5ff4aa38 (`tests/specfactory/test_gate_userdir.py::test_6_planted_settings_in_the_home_do_not_change_the_era`, `::test_6b_detector_control_planted_settings_change_the_era_when_visible`).

## Diagnosis (read-only Sonnet engineer, 2026-11-01)

Both fail in setup, at the `_plant` helper's guard (`test_gate_userdir.py:622`): `AssertionError: fake home ... is inside the real home`. The gate runs the specfactory arm with `TMPDIR=~/Projects/om-push/tmp/merge_gate.XXXX/specfactory` (the clerk card forbids bare `/tmp`, a 16 GB tmpfs), so every fake home the fixture makes is under `/home/westopoli` and the guard, which rejects any path under the real `HOME`, fires. With `TMPDIR=/tmp` both pass 3 of 3 alone and 22 of 22 in the file; no flake, no order dependence, no culprit commit (the guard came with c9d58ea8, 2026-10-13). The tests never boot Godot before failing, so there is no link to H-038 or the display fault. Real `~/.local/share/data/settings.cfg` is not involved.

## Ruling

Test defect in the fixture, under the rulebook: the guard's purpose is that a planted `settings.cfg` never lands where the real game reads (`$HOME/.local/share/data`, the project's custom user dir). Its check is wider than its purpose. It becomes: the fake home is not the real `HOME`, and the real `HOME/.local/share/data` is not under the fake home, and the fake home is under `TMPDIR` (or `tmp_path`). Same assertion message shape; the positive control stays (a fake home equal to the real `HOME` still fails the guard; the test writer adds that one-line control if it is absent). Nothing in the gate's environment changes; `merge_gate.sh` is untouched. Trailer: `Test-defect: test_gate_userdir _plant guard rejected any path under the real HOME, which is where the gate keeps TMPDIR; narrowed to the real HOME and its .local/share/data, planted file still never touches them`.

Also found, not fixed here (H-048): the gate's baseline arm ran these two as SKIP (no pipe built in the baseline tree) while the candidate arm ran them, so "new red" depended on each arm's pipe presence, not on the code.
