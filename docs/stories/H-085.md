# H-085: proof-on-a-hidden-desktop

"A landing's play proof runs the game on a real GNOME desktop that has no monitor, so it works through the night with my screens dark, with a notification up or the session locked, and still catches a game that opens and shows only its splash; checking the game on my real desktop is a separate command I run when I am at the desk."

Flag harness; tool Workflow; no scene; Channel: lab; branch `s/H-085-proof-on-a-hidden-desktop`. Spec'd 2026-11-04 on Westley's choice after two measurements (DEC-proof-hidden-desktop-2026-11-04, "approved, go"); it replaces the Xvfb version of this story. Builds after H-084 lands: both change `scripts/play.sh`, and no two in-flight stories share a file. The part of DEC-play-proof-screen-capture-2026-10-30 that made every landing's proof a capture of the real desktop is superseded; the rule it protects (a human-visible window, not a viewport capture) is kept by the separate real-desktop command and by the look reviewer.

## Measured (2026-11-04, Sonnet engineers; evidence and the working scripts in `~/Projects/om-push/gate-evidence/dark-room/` and `.../xvfb-measure/`)

- Xvfb (X server, no window manager) draws the scene but did NOT reproduce the old splash-only fault (planted trigger, pre-fix build `5aa357be`): it is a Wayland/Mutter fault.
- A second GNOME compositor with no physical monitor (`gnome-shell --headless --wayland --no-x11 --wayland-display wayland-dark --virtual-monitor 2560x1440`) started in about 2 s without touching the real session. The game (`--display-driver wayland --windowed`) reached the qa port in 3 to 4 s. A capture by Mutter ScreenCast through a private pipewire (`gst pipewiresrc` to PNG) gave its first frame in about 0.5 s. On the pre-fix build with the planted trigger the old fault showed (splash only, blank-fraction 0.062) in 3 of 4 launches; the fixed build drew its scene (0.45 to 0.79) in 3 of 3 plus a control. So one launch can miss the fault: this is a net across landings, not a guarantee per landing.
- NVIDIA userspace and kernel libraries mismatch today: `gnome-shell --headless` fails on the GPU ("No EGL display"); software EGL works (`GBM_BACKEND=dri GBM_ALWAYS_SOFTWARE=1`, the Mesa EGL vendor file, `LIBGL_ALWAYS_SOFTWARE=1`). The fault was seen on software rendering only; whether it depends on the real GPU path is untested.
- The private shell starts in its Overview: an Escape key through the private `org.gnome.Mutter.RemoteDesktop` leaves it. `org.gnome.Shell.Screenshot` returns AccessDenied and the private portal is denied; ScreenCast is the capture path.
- One measuring run used the real HOME and the real system bus: it registered with GDM and the real session's services read home directories (nothing changed). Isolation is therefore a hard requirement below, tested.
- The blank metric does not separate a splash (0.062) from a drawn scene by a rule: its threshold is Westley's and not given. The existing rule stays (reject only at 0); the look reviewer, not the metric, is what rejects a splash.

## Change

Files: `scripts/specfactory/hidden_desktop.sh` (new), `scripts/specfactory/hidden_capture.py` (new, the ScreenCast capture and the Escape key), `scripts/play.sh`, `docs/method/clerk.md` (step 5), `docs/method/gate.md` (Stage 4 line), tests (the writer's). The reference implementation, measured and working, is in `gate-evidence/dark-room/` (`dark_session2.sh`, `dark_game.py`, `dark_capture.py`, `dark_keys.py`); the builder reads it and writes the repo version, not a copy of the scratch.

1. **`hidden_desktop.sh <rundir> <WxH>`** starts the hidden desktop and prints `HIDDEN up <rundir>` with an env file. Isolation is the contract: it runs under `env -i` with its own `HOME`, `XDG_RUNTIME_DIR`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_DATA_HOME` under `TMPDIR`, `GSETTINGS_BACKEND=memory`, its own session bus (`dbus-run-session`), a private empty system-bus socket, a private pipewire and wireplumber, and software EGL. It refuses to start (`HIDDEN REJECT not private <what>`, exit 6) when any variable it would hand on names the real `/run/user/<uid>` bus or the real HOME. It is started through `proc.py start` with a TTL and ends by `timeout`, never by hand. Virtual monitor `2560x1440` (DRAFT-hidden-monitor, the size of Westley's primary).
2. **`play.sh --check` runs the game inside it by default**: Wayland driver, `--windowed --resolution $RESOLUTION`, the Escape key, `SETTLE_S`, then `hidden_capture.py` takes two frames about 3 s apart; the proof is the second. Blank rule as today (reject only at fraction 0). It prints `PLAY proof <path> hidden` and keeps `play.lock` (load stays as today).
3. **`play.sh --check --real`** is today's behaviour unchanged: the real display, the portal capture, `PLAY proof <path> portal`. It is the separate real-desktop command, run once per stage with Westley at the desk before that stage's pictures go to him (interim idle precheck of the DEC applies), and whenever he asks.
4. **Cards**: `clerk.md` step 5 runs `play.sh --check` for every landing; the `Played:` line carries `hidden`. The look reviewer's question is unchanged and it is what rejects a splash; the reviewer is told the picture is the whole hidden desktop. `gate.md` Stage 4 names both modes.

## Tests (written first by a Sonnet who does not build, red on main)

Same fakes as `tests/method/test_play_proof.py` (stub Godot, stubs for `gnome-shell`, `pipewire`, `wireplumber`, `dbus-run-session`, `gst-launch-1.0`, the fake portal from piece two to prove it is NOT called). Nothing opens a window or touches the real session.
- `hidden_desktop.sh --dry-run` prints an environment with no `/run/user/` bus, a `HOME` and `XDG_*` under `TMPDIR`, `GSETTINGS_BACKEND=memory`, the software-EGL variables and `--virtual-monitor 2560x1440`; handed a real `DBUS_SESSION_BUS_ADDRESS` or the real `HOME` it prints `HIDDEN REJECT not private ...` and exits 6 (positive control: a private one starts).
- `play.sh --check --dry-run` shows the Wayland driver with `WAYLAND_DISPLAY=wayland-dark`, no portal call; `--real` dry-run output is byte-identical to main's.
- With stubs reaching the scene `--check` prints `PLAY proof <path> hidden`; the fake portal got no call (control: `--real` calls it and prints `portal`); a planted flat frame prints `PLAY REJECT proof capture failed` (control: a busy one passes).
- One slow-tier integration test boots the real hidden desktop on this box, runs the repo's stub scene in it and gets a non-blank frame; it is skipped, never failed, when `gnome-shell` or software EGL is missing, with the reason printed.

## Rulings (2026-11-04, on the test writer's report; DEC-h085-rulings-2026-11-04, Westley may veto)

1. **Old tests that run `play.sh --check` for the real display** are re-pinned by the landing clerk to `--check --real` under `rulebook.md` with a `Test-defect:` trailer per file, quoting Change item 3 as the replacing line: the named tests of `tests/method/test_play_proof.py` (`test_dry_run_check_prints_the_capture_step`, the portal tests, the Wayland check test) and `tests/specfactory/test_gate_channels.py` (`_play`, `test_c3_play_sh_check_launches_with_no_holder`, `test_t3_play_lock_blocks...`). Nothing else in those files changes and no control is weakened. `nightly_play.sh` keeps `play.sh --check` (the hidden default); `gate.md` and `clerk.md` name both modes.
2. **Scrub.** `play.sh` starts `hidden_desktop.sh` and the game with a clean environment: only `PATH`, `TMPDIR`, `LANG`, the software-EGL variables and the hidden session's own values; never the caller's `HOME`, `DBUS_SESSION_BUS_ADDRESS`, `XDG_RUNTIME_DIR`, `WAYLAND_DISPLAY`, `DISPLAY`, `XAUTHORITY`. `hidden_desktop.sh`'s REJECT stays as the second line of defence. "Real HOME" is the passwd home of this uid.
3. **Hidden mode needs no real session.** `play.sh --check` (hidden) works from a shell with no `DISPLAY` and no `WAYLAND_DISPLAY` (a clerk at night); only `--real` still exits `play.sh: no display`. New tests: hidden mode with both unset runs and proves (red on main: it exits "no display"); `--real` with both unset exits "no display" (control).
4. **Escape timing.** Escape is sent after the qa port answers and before the first frame; the reference sent it about 2 s after the port and then waited `SETTLE_S`. Tests accept any Escape inside that interval, not "at least `SETTLE_S` after launch".
5. **Frames.** Two captures about 3 s apart (no tolerance pinned); the proof is the second; a flat first frame with a busy second passes, a flat second rejects. `hidden_capture.py`'s command line, the env file name and the dry-run format are the builder's, tested only through `play.sh` as the writer did.
6. **Register.** The register record names `hidden_desktop.sh` with a TTL, as the writer pinned.
7. **Integration test.** No new slow-tier marker: it skips at run time with the printed reason when a tool is missing, and runs in the pre-gate (about 15 s) when the tools are there; accepted.
8. **Left to the builder, untested:** the 3 s gap tolerance, the daemons' life after `play.sh` ends (they end by `timeout`), `--real` without `--check`.
