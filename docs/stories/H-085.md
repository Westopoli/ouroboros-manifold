## Measured (2026-11-04, Sonnet engineer, evidence in `~/Projects/om-push/gate-evidence/xvfb-measure/`)

- A game run on a private Xvfb display with software GL draws its scene (HUD included), the window is mapped, and a capture of that display is byte-identical across repeats, 0.2 to 0.6 s, with `import -window root` or ffmpeg `x11grab`. Nothing in it depends on his monitors, notifications or session lock.
- It does not reproduce the old splash-only fault: with the trigger planted exactly as H-038 describes, the pre-fix build still draws on Xvfb. That fault is a Wayland and Mutter configure sequence an X server with no window manager never makes. So an Xvfb proof shows "the game launches and reaches the scene", not "the real desktop presents it".
- The splash scores blank-fraction 0.0077 and a drawn scene 0.56 to 0.79; the near-uniform threshold between them is Westley's and not given, so the existing rule stays: reject at exactly 0.
- Traps found: `import` writes a 1-bit PNG for an all-black or all-white screen, which makes the gate's `frame_busyness` raise `ValueError: unsupported PNG layout`; the Xvfb screen must equal the requested window size or the window can be cropped inside a "drawn" result; a fresh worktree needs the Godot import first; the capture must wait until the scene is up (the splash lasts about 1 s).

## Change

Files: `scripts/play.sh`, `docs/method/clerk.md` (step 5), `docs/method/gate.md` (Stage 4 line), `tests/method/test_play_private.py` (new, the writer's). No change to `screen_capture.sh`, the gate or `proc.py`.

1. `play.sh --check` runs the game on a private display by default: `xvfb-run -a -s "-screen 0 <W>x<H>x24"` with W and H exactly the requested window size (`RESOLUTION`), the X11 driver and the existing X11 window check (xdotool and xwininfo, IsViewable), software GL, the scratch user dir as today. 2. `play.sh --check --real` is today's behaviour unchanged: the real display, the Wayland driver, the portal capture, `PLAY proof <path> portal`. It is the separate real-desktop command.
3. Cards: `clerk.md` step 5 runs `play.sh --check` (private) for every landing; the `Played:` line carries `xvfb`. The look reviewer's question is unchanged. The real-desktop check runs once per stage, with Westley at the desk, before that stage's pictures go to him (the interim idle precheck of DEC-proof-private-display-2026-11-04 applies), and whenever he asks; its proof is kept under `gate-evidence` and its reviewer line goes in the stage's README row. `gate.md` Stage 4 names both.

- Dry run of `--check` prints a `launch:` through `xvfb-run` with a screen size equal to `RESOLUTION`, the X11 driver and no `--display-driver wayland`; the `capture:` line names `import -window root PNG24:`.
- `--check` with a stub that reaches the scene prints `PLAY proof <path> xvfb`, the fake portal receives no call (control: `--real` does call it and prints `portal`), and a planted flat capture prints `PLAY REJECT proof capture failed` (control: a busy one passes).
