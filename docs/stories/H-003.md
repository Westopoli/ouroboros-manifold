# H-003: the four numbers, nightly

"Every night the token report writes the four numbers for the week, and the share of spend that went into building and testing is the first of them."

Gate flag harness; tool Workflow; Branch `s/H-003-token-report`.

## Files

- `scripts/method/token_report.py` (new, about 150 lines, stdlib only).
- `scripts/specfactory/systemd/om-token-report.service` and `.timer` (nightly 23:50; the service refreshes `~/Projects/om-push/main` to `origin/main` and runs the script from there, never from the live checkout); the existing `om-method-metrics.timer` (Sunday 23:00) is disabled in the same story, `method_metrics.py` stays callable by hand.
- `tests/method/test_token_report.py` (new).

## Behaviour

Reads every transcript under `~/.claude/projects/-home-westopoli-Projects-ouroboros-manifold/*.jsonl` (resolved through `Path.home()`) and the sub-agent transcripts under `<session>/subagents/agent-*.jsonl`, for the window given: `--week 2026-W44` (ISO week, default the current week) or `--day 2026-10-29` (one UTC day). Only lines with `type == "assistant"` count; one API call is one `requestId` (several assistant lines share one, one per content block), so calls and tokens are counted once per `requestId`. Weighted tokens per API call: input plus output plus cache-create, plus cache-read at a tenth (the 2026-10-10 retro's weighting). Each call is classed once:

| Class | Rule |
|---|---|
| builder | sidechain whose first prompt names `builder.md` or `subagent_type: doer` |
| tests | sidechain whose first prompt names `test_writer.md`, or a Workflow phase labelled `tests` |
| clerk | sidechain whose first prompt names `clerk.md`, or a landing or records brief |
| fable | main-chat calls with model `claude-fable-5-1` |
| runner | main-chat calls with a Sonnet model |
| other | anything else, listed by first-prompt line in `--verbose` |

Writes one row to `~/Projects/om-push/metrics/<week>.csv` (or `<day>.csv` for `--day`; the directory is outside the repo so the nightly timer commits nothing; `status.sh` reads it there) with the header `window,calls,weighted_tokens,builder_share,tests_share,build_plus_tests_share,fable_share,landings,seen,tokens_per_landed_line`, shares as percentages with one decimal; landings and seen come from `git log` as in H-002; landed lines are the `--shortstat` insertions of the week's `Land` merges outside `docs/` and tests. Prints the row. The 50% and 25% thresholds are printed as `OK` or `UNDER` beside the shares; the script never fails on them.

## Tests

- Fixture: three small transcripts under `tmp_path` (one Fable main chat, one doer sidechain, one engineer sidechain) with known token counts; the shares match a hand sum (positive control).
- `--day 2026-10-29` on the real transcripts exits 0, prints one row whose class shares sum to 100 within 0.2 and whose `fable_share` equals, within 0.5 point, an independent count the test makes itself (weighted tokens of assistant lines with `message.model == "claude-fable-5-1"`, once per `requestId`, over the same files and day). The engineer's 2026-10-29 figures (2,812 calls, 80.4M, builders 8, tests 9, Fable 48) are not a fixture: their method was not recorded and the script measures 3,188 calls and 40.1M on the same day (DEC-token-report-fixture-2026-10-30). Old briefs name no card, so builder and tests shares are 0 for days before 2026-10-30; from this day on every brief names its card.
- The timer unit parses (`systemd-analyze verify`).
