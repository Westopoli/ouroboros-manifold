# H-061: beta-b2-layout-no-units

"Start simple just like the simulation lab, with just a layout and no units, and show several versions."

Flag client; tool Workflow; beta stage B2. Ready 2026-11-02; builds when B1 (H-060) is Seen. Every number is an Architect draft.

## What it is

After Launch in `om-beta`, the mission's layout drawn flat on the ground as shapes: the layout engine's output (pads, gaps, plateaus, pockets, routes, the map edge) as coloured flat regions and lines on the plane, the camera rig live, no relief, no units, no places. Five variants in the picker: one layout of each kind from the catalogue (open field, chokepoint, vantage, city, trap; DRAFT: the round-three catalogue's first LOOK OK layout of each kind, pinned by id in the story at build time).

## Change

- `scenes/beta/stage_field.gd` gains the layout drawing: it reuses `scenes/proto/layout_shot/layout_shot.gd`'s terrain and feature drawing helpers (the H-025 shot scene), no copy; reads a catalogue layout file by id from `OM_LAYOUT_ID` (the picker sets it and reloads the field).
- The picker (H-060's OptionButton) lists the five ids with their kind.
- No sim call: the field is a drawing of the layout file. Wiring commit last.

## Tests (`tests/qa/test_beta_b2_layout.py`, new; red on main)

1. Headless with `OM_BETA=1` and each of the five ids: `qa_state()` names the layout id and lists the feature kinds drawn, matching the file; positive control: a planted layout with one feature removed lists one fewer.
2. The picker has five entries, each switching the field (the id in `qa_state()` changes).
3. Screenshots of the five via `OM_SHOT_OUT` are not blank (the look metric), and differ from each other.
4. The story play reaches the field with the first id.
