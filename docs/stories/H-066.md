# H-066: qa-port-unique

"Two gates running at the same time never play on each other's game."

Flag harness; tool Workflow; no scene. Ready 2026-11-02; Channel: lab. Finding by the lab Dispatcher 2026-11-02 (while diagnosing the replay flake on push/b-h063); made urgent by DEC-two-gate-channels-2026-11-02 (two gates and so two pytest runs at once are now normal).

## Why

`tests/qa/desktop/daemon_client.py` `pick_free_port()` picks a random port in 47500-47599 by binding and closing a socket; Godot opens that port later. Two concurrent pytest runs can pick the same port in the gap, and `wait_for_port` would then connect to the other run's Godot (wrong state, or a timeout). Not reproduced in six concurrent runs; scratch dirs and the xvfb display are already per-run, so the port is the one shared name left.

## Change (test infrastructure only; a clerk, under `docs/method/rulebook.md` with a Test-defect trailer, since the file is under tests/)

`pick_free_port()` tries the ports 47500 to 47599 in random order; for each it takes a non-blocking `flock` on `<push root>/tmp/qa_ports/<port>.lock` (the push root is the one the sibling scripts use, `$HOME/Projects/om-push` unless overridden), keeps the file descriptor open for the life of the process, then checks that the port binds; a lock it cannot take means the next port; when none is left it raises with the message `QA PORT REFUSED no free port`. `wait_for_port` and every caller stay unchanged. Add a one-line `# See also:` comment at the pick site pointing at this story.

## Tests

`tests/specfactory/test_qa_port_pick.py` (new; a different Sonnet writes it, red on main):

1. Eight processes started together, each calling `pick_free_port` with the same random seed, return eight distinct ports.
2. Positive control: the old picker (bind, close) called by the same eight processes with the same seed returns the same port in at least two of them.
3. When all 100 ports are locked, `pick_free_port` raises with `QA PORT REFUSED no free port`.
4. A lock file left behind by a dead process does not block a port (flock is released on process exit).
