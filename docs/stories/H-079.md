# H-079: one-workflow-per-landing

"A story goes from Ready to landed on one launch; the runner hears about it once."

Flag harness; tool Workflow; no scene; Channel: lab. Spec'd 2026-11-03 from the plan "the mail-and-station communication method" (Westley approved 2026-11-03). After H-077.

## Why

Build and landing are two launches today (`runner.md` steps 2 and 5), and each sub-agent's stop wakes the runner: 686 completion wakeups for 38 landings in the week of 10-27, four to six per landing, each a 168k re-read. The Workflow tool returns once, when its script returns; its `agent()` stages are fresh small-context sub-agents.

## Change

`scripts/specfactory/workflows/land_story.js` (beside the `vg-wave*.js` scripts; same `args.skip` resume keys; launched with `scriptPath` and `args: {id: "H-0NN", channel: "lab"}`):

- `meta`: name `land-story`, phases Build, Land, Review.
- Stage Build: `agent()` with the builder brief (card `builder.md`, the story file path, STOP rules, model `claude-sonnet-5-5`, "spawn nothing"), schema `{ok: bool, pushed_sha: string, blocked: bool, reason: string, test_defect: string}`. `blocked` or `test_defect` returns at once with the stage's fields: `{landed: false, blocked: true, stage: "build", reason}`.
- Stage Land: `agent()` with the clerk brief (card `clerk.md`), schema `{ok: bool, landed: string, summary: string, played: string, worktrees: string}`. The clerk does everything `clerk.md` says, including the look reviewer it spawns (one level, allowed by `clerk.md`) and, after H-080, the gate ticket.
- Stage Review: none when the story has `Scene: none`; else the Review phase is the clerk's look-review line copied into the result.
- Return: `{landed: bool, sha, blocked: bool, stage, reason, played, summary}`.
- `args.skip` holds stage names already done, for a resume after an `ask` is answered: `Workflow({scriptPath, resumeFromRunId, args: {..., skip: ["build"]}})`.

Cards: `runner.md` step 2 becomes "launch `land_story` with the story id and channel"; step 4 becomes "a `blocked` result is one `ask` mail to the Architect naming the result's reason; when the ruling is in the story file, relaunch with `resumeFromRunId` and `skip`"; step 5's "a clerk lands it" is removed (the workflow did). `builder.md` and `clerk.md` Report sections state the schema above as the StructuredOutput fields.

## Pre-flight (2026-11-03)

61 scripts with `export const meta` exist under `scripts/specfactory/workflows/`; the newest, `vg-wave16-harness-pregate-pins.js` (2026-10-29), ends with `next: 'a landing clerk lands ...'`, so no script lands today. `clerk.md` "Look review" lets the clerk spawn one read-only engineer. The Workflow runtime has no filesystem access: every wait (gate, play) happens inside the clerk's Bash, never in the script.

## Tests (`tests/method/test_land_story.py`; a different Sonnet writes them, red on main)

The Workflow runtime cannot run offline, so the test loads the script as text and as a module with a stub `agent()`, `phase()`, `log()`, `pipeline()`, `parallel()` injected:

1. `meta` is a pure literal with name `land-story` and the three phase titles; the file parses as JavaScript (`node --check`).
2. A stub builder returning `blocked: true` yields `{landed: false, blocked: true, stage: "build"}` and the clerk stage is never called.
3. A stub builder `ok` and clerk `ok` with `landed: "<sha>"` yields `{landed: true, sha: "<sha>"}`.
4. `args.skip = ["build"]` calls no builder and goes to the clerk.
5. Positive control: the previous wave script's `meta` also parses with the same loader.
6. Pre-flight record: the story file gains, before Ready, one line with the sha and wall time of one real launch on a stub story in a worktree.
