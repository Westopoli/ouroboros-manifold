# H-002: status from git

"One command prints what is in flight, what landed this week, what waits on me and the four numbers, from git alone."

Flag: harness. Tool: Workflow. Branch `s/H-002-status`. Builds after H-006; H-003 feeds its NUMBERS section.

## Files

- `scripts/method/status.sh` (new, bash plus git, about 100 lines).
- `scripts/specfactory/status_check.py`: replace the twelve checks with the trailer schema (below); about 80 lines remain.
- `tests/method/test_status.py` (new).

## status.sh output, in order

1. `IN FLIGHT`: every `origin/s/*` branch not yet merged into `origin/main` (`git branch -r --no-merged origin/main 's/*'` pattern), with its last commit age and subject. Older than 14 days: suffix `stale`.
2. `LANDED <iso week>`: first-parent commits on main this week whose subject begins `Land `, with the `Story:`, `Played:` and `Gate:` trailers (`git log --first-parent --since=<monday> --grep='^Land ' --format='%h %s%n%(trailers:key=Story,valueonly)...'`).
3. `WAITING ON WESTLEY`: every `Land <id>` on main with no later commit whose subject is `Seen <id>`, oldest first, with the story's `Play:` trailer as the run line, and `(stub)` from the subject when present and the story's words from `stories.md` or `harness.md`.
4. `TEST DEFECTS <week>`: commits this week with a `Test-defect:` trailer, file and why.
5. `SWEEPS`: the last three `Sweep ` subjects and any `Revert Land` since the last green.
6. `DECISIONS <week>`: commits this week with a `Decision:` trailer.
7. `NUMBERS <week>`: the last row of `~/Projects/om-push/metrics/<week>.csv` (H-003), or `no report yet`.
8. `LAST PLAYED`: the sha `~/Projects/om-push/main` sits at, from `git -C ~/Projects/om-push/main rev-parse HEAD`.

## status_check.py

Exit non-zero and print one `DRIFT` line per failure: a `Land` commit on main (first-parent, since the base sha written as `Base:` in the first sweep commit after the method lands; before any such commit, since the commit that landed `docs/method/`) missing any of Story, Tests, Scene, Played, Gate, Flag; a story marked Tested in `stories.md` or `harness.md` with no `Land <id>` commit; a `Seen <id>` commit with no `Verdict:` trailer; a story marked Seen with no `Seen <id>` commit. Nothing else is checked.

## Tests

- Fixture repo built by the test under `tmp_path` with two `Land` merges (one with all trailers, one missing `Played`), one `Seen` commit, one `Test-defect:` commit: `status.sh` prints each section with the expected lines; `status_check.py` prints exactly one DRIFT naming the second landing (positive control: the first landing passes).
- On the real `origin/main` the script exits 0 and its IN FLIGHT section matches `git branch -r` by hand on three branches.
