## What must happen when one of these rules is rewritten

When a rule here is rewritten, four things happen together. First, the rule text changes in its epic, in the same change as every doc claim it makes wrong, and the "Direction changed 2026-10-02, rewrite pending" line under its story is deleted (or kept for the siblings still waiting). Second, each test, code comment and script in that rule's row is classed: either the test is still right (the rewrite did not move what it proves), or it is a test-defect because the spec moved. Third, a row is added to the project's ledger for each test that is changed, naming the rule, the test file and the reason; a test is not edited without that row, and builders never edit tests. Fourth, Westley owns every threshold and tolerance in those tests: narrowing an invariant's scope is allowed, but widening a threshold, extending a window or loosening a tolerance needs him, and a real finding is never reclassified as a skip. Rows whose flags are still open stay unwritten until the flag closes, since the bible's rule is that an epic with an open flag is not built.
