# Shared RULES blocks for lane briefs and wave scripts

Cited by briefs, not pasted. Source wording: vg-wave5-laneE1.js line 12, vg-resume-laneC-land2.js line 8, plus the 2026-10-09 lessons, method rev 2 (2026-10-10, `retro_2026-10-10/README.md` section 4) and method rev 3 (sections (c) and (d), Westley 2026-10-11: "#14: approved"; the lint is lane H part 3 of the spec). Six roles: Builder, Landing clerk, Scout or auditor, Test writer, Ruler, Dispatcher.

## (a) Builder (Doer)

- Model Sonnet 5.5; never spawn sub-agents; think tersely; the last message is the report, no interim notices.
- Worktree ONLY by absolute path: `git -C ~/Projects/ouroboros-manifold fetch -q && git -C ~/Projects/ouroboros-manifold worktree add -b <branch> ~/Projects/om-push/wt/<suffix> origin/main`. Every command names its absolute path; never cd into, or touch, `~/Projects/ouroboros-manifold`.
- No stash, rebase, amend, force, `make clean`; never push to main; never kill another process's gate.
- Build: `make && make pipe/ouroboros_pipe pipe/ouroboros_pipe_dbg`; run `godot.real --headless --import` once first. Python `~/Projects/ouroboros-manifold/.venv/bin/python`; Godot `~/.local/bin/godot.real` (4.6.3).
- Godot tests: `timeout 1800 scripts/run_godot_tests.sh <file>`. Display-needing files: `xvfb-run -a -s '-screen 0 1920x1080x24' godot.real --path . --resolution 1920x1080 -s <file>`. Wrap every Godot or xvfb run in `timeout 1800` (two wave-1 runs hung 8 h).
- Long runs: `systemd-run --user --scope -q -p MemoryMax=6G -p MemorySwapMax=0 -- nice -n 10 <cmd>`. Gates run detached, polled every 5 min.
- Renderer split (2026-10-09): Godot tests and desktop tests run under the DEFAULT renderer. `OM_QA_RENDERER=vulkan` is for story plays only (Xvfb vulkan washes colours out). The galaxy pixel tests and the plays are pinned to that split. Desktop plays run one at a time: `xvfb-run -a timeout 900 .venv/bin/python -m pytest <play> -q`.
- Determinism: integer or plain double arithmetic, no libm transcendentals (libm_lint), no wall clock, no hash-order iteration; new world state is hashed (checksum_full) and saved.
- Builders never edit tests. A test that looks wrong stops the piece with `stop_reason` starting `test-defect:` followed by the test id, the failing assertion line and the spec line it contradicts; the script's ruler (section (e)) takes it from there. A Westley threshold lives in a `*_park_*` file.
- Pre-gate before the push (method rev 2): `scripts/specfactory/pre_gate.sh <worktree> origin/main <piece ids> [<test paths>]` must end `PRE_GATE verdict OK`; until that script lands, run `scripts/specfactory/merge_gate.sh --revert <worktree> origin/main <piece ids>` (make, every lint, footprint, owner rows, about one minute) and `git -C <worktree> status --porcelain` with no `*.uid`, `*.import` or `.glb.import` line other than a `.uid` beside a new script of yours. A REJECT here is yours to fix; it never reaches the clerk.
- Liberties named in the spec are taken as written and marked in a code comment; anything else undecided stops the piece.
- Stop and report (ok=false, stop_reason) on a file outside your list, a number nobody gave (named mockup drafts allowed: cite), or a new public C symbol not in the frozen header.
- Never stage `*.import` or `*.uid` noise. `godot --import` leaves untracked `*.uid`: delete them before any checkout or merge. (Exception: a `.uid` beside a new script you wrote is committed per NOTE-uid-files.)
- Push your branch, write `.wt-done` (date, branch, pushed sha). Stop past 120k context.

## (b) Landing clerk (Engineer)

- Gate, run from the worktree, detached into `<TMPDIR>/gate.log`: `flock -w 14400 ~/Projects/om-push/gate.lock env TMPDIR=<dir> MERGE_GATE_SUITE_TIMEOUT=2400 MERGE_GATE_PLAYTHROUGH_TIMEOUT=2400 MERGE_GATE_PLAY_TIMEOUT=900 MERGE_GATE_PIECES=<worktree>/docs/northstar/plans/push/pieces.toml bash -c 'cd <worktree> && git fetch origin && git merge --no-edit origin/main && scripts/specfactory/pre_gate.sh <worktree> origin/main <comma piece list> && scripts/specfactory/merge_gate.sh <worktree> origin/main <comma piece list>'`. Three positional arguments to each script. The merge of origin/main happens inside the lock, because main moves while a clerk waits hours for it; the script rejects a candidate that lacks the current origin/main (stage 0 `base`), so a forgotten merge costs seconds, not a gate. See also: `scripts/specfactory/merge_gate.sh` stage 0; ledger row FINDING-gate-base-before-lock.
- Wait: poll `gate.log` for the `^GATE look ` line, one foreground command under 10 minutes at a time. Then `pgrep -f '^bash scripts/specfactory/merge_gate.sh'` to confirm no gate for the worktree still runs; never pgrep your own command line. There is no VERDICT line: the verdict is the set of `GATE <stage> REJECT` lines.
- Flake rule: a lone playthrough or lane_plays red that passes twice alone gets one re-run.
- Known-red: `scripts/specfactory/lane_plays_known_red.txt` holds exact ids with reasons; `scripts/specfactory/playthrough_known_red.txt` stays empty (a gate test enforces it).
- Known-red rule (Architect 2026-10-12): plays and GD tests that are red for a ruled reason with a ledger or finding row are listed with that row id, plays in `lane_plays_known_red.txt` (read by the gate) and GD tests in `gd_tests_known_red.txt` (read by the clerk: one exact test id, ` :: `, the row id), so unrelated landings are not rejected on them; the row keeps each visible and the entry leaves when the row closes. A play or test is never listed without a row. The clerk pushes main when every `GATE <stage> REJECT` line names a test listed in `gd_tests_known_red.txt` or a play in `lane_plays_known_red.txt`; a reject outside the two files is a branch-only landing.
- Ownership: every file in the diff is owned by a listed piece (`owns` or `owns_glob`; acceptance does not count). Two in-flight pieces sharing a file need `depends_on`. Park files (`*_park_*`) stay off the candidate and are listed.
- Push: branch first. `git push origin HEAD:main` only on a clean gate and only when the brief authorises it; merge origin/main first if it moved and say so (ledger appends keep both sides).
- Snapshot cleanup: delete only the `merge_gate_before_*` directories under your own TMPDIR, never a glob over /tmp.
- Test-defect rule: a test changes only under a rulebook or ledger row. Thresholds, windows and tolerances are Westley's. A determinism golden moves once, with a ledger row naming old and new values.
- Pre-gate before the lock (method rev 2): after merging the landing branches, run the pre-gate line of section (a) on the landing worktree; only a `PRE_GATE verdict OK` (or a clean `--revert` run plus a clean noise check) takes `gate.lock`. This early run is a cheap check on the tree as it stands; pre_gate runs again inside the lock (see the Gate bullet) because it reads the tree after origin/main is merged there. A full gate is never spent on a lint, footprint, owner-row or noise reject.
- Every lane's test files go to the pre-gate; display-bound ones are named once in the waiver (FU-B22-pregate-display) so the pre-gate's silence is explained, never left out of the list quietly.
- Shots to the queue (method rev 2): for every player-facing piece in the landing, run its story play on the merged tree (xvfb, `OM_QA_RENDERER=vulkan`, timeout 900), copy the png and qa_state json to `docs/northstar/story_reviews/shots/<run id>/` (run id `YYYYMMDD-HHMM-<sha7>`), add the row to `docs/northstar/story_reviews/<lane>.md` (reviewer verdict yes/no/unclear with one line of evidence, Westley pending), and name every shot path in the report under `shots`. Beside the queue row, copy the png to `docs/northstar/story_reviews/westley/<lane>-<story>-<what it shows>.png` and add its row to that folder's `README.md` (file, story, lane, run id, original, what to judge); the verdict clerk deletes both (Westley, 2026-10-13). At most one shot per lane in that folder at a time; the next waits in the queue file until his verdict.
- Status row (method rev 2): in the landing commit, flip the lane's row in the programme file's lane table (On main sha, Next piece) and the pieces rows; write nothing about status anywhere else (no ROADMAP lane rows, no journal line: the commit subject is the journal, `scripts/journal.sh` prints it).
- A records clerk that touches stories.md, a story_reviews queue file or the programme lane table runs status_check.py and owner_lint before pushing and never pushes a new DRIFT (Architect, 2026-10-21, after the seen DRIFT of that day).
- Stacked build (Architect 2026-10-14; Westley 2026-10-14: "Claude compute used consistently"): a build may stack on an unlanded predecessor branch (spec text read from specRef origin/main, baseRef = the predecessor's pushed branch); the landing queue keeps the order; if the predecessor changes in its gate, the stacked piece's clerk merges the landed predecessor and re-runs its Check before its own gate (rework, no re-draft). It changes no gate rule, only where builds start.
- Report schema: ok, branch, sha, summary (stage lines verbatim), red_ids, stop_reason, shots. Write `.wt-done` after the push.

## (c) Read-only scout or auditor, method rev 3 addition below

- Detached worktree (`git worktree add --detach <abs path> origin/main`); remove it after, even if removal is slow. Change nothing; no commits, no pushes, no ledger edits.
- Evidence as file:line plus the sha read. Mark what was not run (Godot, pytest) as unverified.
- Report once, at the end, findings numbered, with a blocking yes or no.
- Audit provenance column (method rev 3): an audit of a spec carries a table with one row per behaviour sentence (a number with a unit, a bare number outside code spans, or the words when, then, shows, sees, draws, refuses, accepts, default) and the column `provenance`: `[W Q-... ]` or `[W <date>: "..."]` (Westley's words), `[B R-...]` (a bible rule that exists), `[P <path>:<line>]` (a prototype or mockup read), or `[DRAFT-<name>]` (a named draft with a ledger or register row). The auditor reports every untagged sentence as a finding, blocking, quoting the sentence and its section. Words that stand in for a source ("liberty", "as the builder drafted", "Architect default") are findings too. `scripts/specfactory/spec_provenance.py` does the mechanical half once it lands (HARNESS-provenance); until then the auditor does it by reading.

## (d) Test writer (Engineer), method rev 2 and rev 3

- Section (a)'s worktree, build and Godot lines apply. Write ONLY the test file the brief names; never a source file.
- On the built tree, not from the spec alone: merge the branch that holds the stub or the previous piece (the brief names it; else `origin/main`), build, run the file. It must be red for the missing-feature reason the brief states, and the report pastes the failing assertion line verbatim (file:line and the message).
- Positive control green first: before the new assertions, one assertion that passes today on the same scene or fixture (the node instantiates, the helper returns a value, the getter reads the fixture), so a red means the feature is missing and not that the harness is broken.
- Scene premises are dumped, not assumed: a test that reads qa_state, a frame or a sim scene runs the scene once and pastes the keys and the values it relies on (region owner, economy, tick, era, unit count) into the report; a premise that does not hold (the economy is 0, no units so the tick returns early, the clock is stopped before `om_mission_begin`) is fixed in the test now, on the test branch, and said in the report. The 2026-10-10 part a run stopped six of seven builders on premises nobody had run.
- Thresholds, windows and tolerances are Westley's: a value nobody gave goes in a `*_park_*` file with a comment naming the register row.
- Quote the rule (method rev 3): the brief for each test quotes, word for word, the bible rule `R-###-##` (or Westley's recorded words) the test proves, and the test file names the same id in its docstring or header comment. A test whose behaviour no quoted rule states is not written; the writer reports the gap and a register row is raised.
- Prototype copies ship a parity test (method rev 3): a piece that copies numbers, geometry or behaviour from an approved prototype or mockup ships a test that reads each copied constant from the live script or scene and compares it to the prototype's as-run value, with the prototype file:line beside each row (the B23 table in `tests/test_vg_b_b23.gd` is the model). Rows already equal are the positive control (green today); the rest are red until built. Copying the prototype's pre-rescale values and changing only one of them is the failure this guards against (galaxy B22, 2026-10-11).
- Report ok, branch, sha, summary (the failing line, the control line, the dumped premises), red_ids.

## (e) Ruler (Engineer), method rev 2

- Spawned by the script when a builder stops with `test-defect:`. Read-only on sources; edits ONLY the one test file the stop names, on a branch `push/vg-<lane>-rulings`, under a ledger row.
- Apply `docs/northstar/plans/2026-10-07-visible-game-rulebook.md` "Decision procedure" word for word: a defect only if (1) the failing assertion matches a rulebook row or its pattern, (2) the spec names the replacing line and you quote it with file:line, (3) the edit changes only the pinned literal, key list or scene parameter, (4) no threshold, window or tolerance moves and no positive control is weakened, (5) the file is not on the do-not-touch list. Then edit, run the touched test alone and its control, append the ledger row (`TD-VG-<lane>-<n>`, the rulebook's template, old and new values named), push, report `ruled: true` with the row id and branch.
- Anything else: `ruled: false` and a brief for the Architect, under one page: the test id and failing line, the builder's claim, the spec and bible lines that bear on it, two or three options with what each changes. No edit, no ledger row.
- Never reclassify a real finding as a skip; never widen anything; never touch a second file.

After every compaction the first thing in context is the `method_check.py` report on the chat's own transcript (`method_check.md`): its DRIFT lines go to Westley in the next message, before any other work.
