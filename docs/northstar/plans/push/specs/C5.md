## What to build

`scenes/tactical_c/tactical_view.tscn` root, methods exact per the fenced
test's `CONTRACT_METHODS`:

- `load_frame(frame: Dictionary) -> void` — replaces whatever was loaded
  before, synchronous.
- `qa_state() -> Dictionary`, JSON-safe: `tick`, `canvas` (from
  `map.canvas`), `units` (`{id: {faction,type,tier,hp,layer,facing,state,
  x,y}}` — ground truth, every unit the loaded frame carries, regardless
  of visibility), `units_px` (`{id: [x,y]}`, screen space — **only** for
  ids in `visible[str(local_faction)]`; an id present in `units` but
  absent from `units_px` proves R-089-04's "no memory of last-seen
  positions"), `local_faction` (fixed `0`), `selected` (current selection
  set), `camera` (`{x,y}`).
- `qa_plant(id: String) -> bool` — `PLANTS := ["facing-fixed",
  "camera-unbounded"]`. `facing-fixed`: when active, a unit's reported
  `facing` stops updating across `load_frame` calls (freeze at whatever
  it was). `camera-unbounded`: when active, `qa_pan`'s canvas-edge clamp
  is disabled. **`"select-all-exists"` is a permanent negative** — R-105-04
  forbids a select-all command outright, so this id must return `false`
  unconditionally, always, with no fault site ever wired to it (not a
  normal off→on plant; it never turns on). Any other unknown id returns
  `false`.
- `issue_command(cmd: Dictionary) -> Dictionary` — takes
  `{"kind":"move"|"attack_move","unit_ids":[...],"x":F,"y":F}` or
  `{"kind":"attack_target","unit_ids":[...],"target":N}`, returns
  `{"type":"cmd","name":"command_move"|"command_attack_move"|
  "command_attack_target",...same fields carried through...}`. Never
  actually sent anywhere (no pipe write) — this is pure JSON construction
  the test inspects directly.
- `qa_box_select(x0, y0, x1, y1: float) -> Array` — screen-space rect
  select over the currently drawn `units_px` positions; sets `selected`
  and returns the newly selected ids.
- `qa_pan(x, y: float) -> void` — pans/recentres the camera, **clamped to
  `[0, canvas]`** on both axes (R-103-02) unless `camera-unbounded` is
  active.

Rendering: units as flat-colour blocks (placeholder primitives — box/quad
per unit, no imported models), a fixed top-down camera (no rotation — the
test's `_check_moved_unit_and_facing_R100_01` expects a pure +x world move
to read as one dominant screen axis, which only holds under a
non-rotated, consistent-axis-mapping projection). Map `nodes`/`cover`/
`obstacles` can render minimally (placeholder shapes) or not at all — no
fenced check inspects them, only `units`/`units_px`/`camera`/`canvas`.
