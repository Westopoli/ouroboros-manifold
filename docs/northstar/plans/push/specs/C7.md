  acceptance = `tests/test_qa_daemon.gd` plus the liveness precheck; line 105 gate

## What C7 builds

- `autoload/qa_daemon.gd`: a `Node`-derived (or plain `RefCounted`-safe — the fenced
  test frees it only `if daemon is Node`, so either works, but it must run as a real
  autoload once `QADaemon=` is added, so make it `extends Node`).
  - `state() -> Dictionary`: returns at minimum `{"scene": <current scene name or
    path>, "tick": <int tick counter, 0 if the sim isn't running>}`. Must not throw
    when there is no `SceneTree` (the fenced test instantiates it outside a running
    tree via `Script.new()`), so `state()` cannot assume `get_tree()` is non-null —
    guard it and fall back to `""`/`0`.
  - Dev-only gate: in `_ready()`, check `OS.get_cmdline_user_args()` for `--qa-port`
    or `--qa-script`; if neither is present, the daemon does nothing beyond existing
    (no socket, no polling, no side effects) — mirrors the mockup `QADriver`'s inert
    pattern in `2026-09-22-mockup-qa-harness.md` line 50.
  - Verb surface when active: `state`, `tree`, `seed`, `fixture`, `pause`,
    `step <n>`, `screenshot`, `inject <bug-id>`, `input` — the desktop analogues of
    the mockup `qa_driver.gd` verb table, adapted to the real game (no mockup root
    contract, no plants; `inject <bug-id>` takes the place of `plant <id>` for real
    QA fault injection hooks other systems may add later — a stub that records the
    id and returns true/false for known/unknown is enough here; nothing downstream
    calls it yet). `--qa-port N` opens a local TCP listener (127.0.0.1 only) and
    speaks line-delimited JSON requests/responses, one verb per line, in the same
    shape as the verb table above; `--qa-script PATH` replays a JSON action array
    exactly like `qa_driver.gd`'s `_run()` (read file, `JSON.parse_string`, iterate,
    quit(0) when done). Reuse `scenes/mockups/_shared/qa_driver.gd`'s verb
    implementations (`move`, `click`, `key`, `wait_frames`, etc.) by `preload`,
    do not duplicate the input-synthesis code — only `state`, `tree`, `seed`,
    `fixture`, `pause`, `step`, `inject` are new here.
- `scenes/harness/harness.tscn` (+ backing script if needed): a minimal scene
  `scripts/qa_harness.sh run`/`liveness` can launch — the main menu or a thin
  wrapper around it — with `QADaemon` reachable. `scripts/qa_harness.sh liveness`
  needs a window titled so `xdotool search --name '^QA:'` finds it (see
  `qa_driver.gd`'s `DisplayServer.window_set_title("QA:" + _root.name)` pattern);
  do the same here.

## Adapter test deviation (ground-rules line 9)

`tests/test_qa_daemon.gd` is a Godot `SceneTree` script, not a pytest node id, so
the shard-test-writer's adapter `tests/push/test_leaf_c7.py` cannot run it through
`pytest.main([...])`. Instead the adapter shells out:
`subprocess.run(["scripts/run_godot_tests.sh", "tests/test_qa_daemon.gd"], cwd=repo_root)`
and asserts return code 0. Record this deviation in the Phase 7 report per the
common brief.
