## `scenes/mission_briefing/mission_briefing.gd` (leaf-01)

- `load_frame(mission: Dictionary) -> void` — the rebind entry point,
  independent of `setup()`. Stores `archetype`, `region`, `deadline_ticks`,
  `objectives[]`, `force` from the frame. Calling it again (e.g. with a
  frame differing only in `archetype`/`region`/`deadline_ticks`) must fully
  replace the stored state — the test calls it three times in sequence
  with different frames and checks the read-back state each time.
- `qa_state() -> Dictionary`, JSON-safe: `archetype` (int, straight from
  the frame — no interpretation), `deadline_ticks` (int, straight from the
  frame — the "no digits in rendered prose" reading of R-079-04 applies to
  displayed text, not this canonical data field), `objectives` (list of
  `{i, kind, node, primary, marker_name}` — one entry per frame objective,
  same order or any order, the test only checks size and primary-count,
  then filters for the primary one specifically).
- **`marker_name` is the one real design point**: it must come from a
  **client-side node→name table keyed on `node` alone** — a `const
  Dictionary` mapping tactical node indices to display names is enough (the
  spec doesn't require this to be exhaustive or connected to any other
  system; a small hardcoded table covering at least node ids 3, 7, 12 — the
  fixture's own node ids — satisfies the fenced test, though a broader
  table costs nothing extra). It must **not** be derived from the frame's
  other fields (region/archetype/deadline) and must **not** just restate
  the node number (`"Node %d" % node` is explicitly the wrong,
  frame-echoing answer the fenced test guards against — see the plant
  below). Proof required: loading two frames that share the primary
  objective's `node` id but differ in every other field must yield the
  same `marker_name` both times, and that name must not equal `str(node)`
  or `"Node %d" % node`.
- `qa_plant(id: String) -> bool`, `PLANTS := ["marker-from-frame"]`. Fault
  site: when active, the primary objective's `marker_name` becomes the
  literal `"Node %d" % node` instead of the table lookup — one `if`
  branch at the point `marker_name` is computed. Unknown id returns
  `false`.

## `scenes/debrief/debrief.gd` (leaf-02)

- `load_frame(debrief: Dictionary) -> void` — the rebind entry point,
  independent of `setup()`. Stores `band`, `achieved`, `brought_home`,
  `region_delta` from the frame.
- `qa_state() -> Dictionary`, JSON-safe: `band` (String — see the exact
  mapping table below), `achieved_pct`/`brought_home_pct` (the frame's 0–1
  floats × 100.0), `region_delta` (exactly the frame's 4 fields —
  `military`, `economy`, `tension`, `population` — unchanged, no
  recomputation; this piece owns display only, the band **threshold math**
  already ran server-side and is proven by `tests/csim`).
- **Band int → string mapping, exact, worst to best** (R-077-02's own
  ordering, not a guess):
  ```
  BAND_NAMES = ["total_failure", "partial_failure", "partial_success",
                "strong_success", "total_success"]
  ```
  index by the frame's `band` int directly (`BAND_NAMES[band]`).
- `qa_plant(id: String) -> bool`, `PLANTS := ["band-off-by-one"]`. Fault
  site: when active, shift the mapping index by +1 before lookup, clamped
  to the last band (`mini(band + 1, BAND_NAMES.size() - 1)`) — so band 2
  (`partial_success`) reads as band 3 (`strong_success`). Unknown id
  returns `false`.
