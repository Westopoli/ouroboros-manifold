## Summary

Today every arena fight runs with `OM_TP_TARGET_BY_SIGHT` set to 0 (`scripts/skilllab/arena/run.py:124`), the fight file writes `sight: "off"`, and `--sight on` only leaves the engine default in place and writes the word. Stage 4 makes `--sight on` a real rule set: units fire only at what their side sees, high ground sees down and fires down, the holder of a `hold:` layout is on guard, and the fight file, the replay and the page show who saw whom first. Three file-disjoint leaves; the overlord writes the parent-owned documents in the landing commit.

Pre-flight (2026-11-05, main `4fa618ce`, read by `git show` and `grep`): `csrc/fog.c` `om_fog_can_see_at`: sight is the distance within the type's sensor radius (Raider 800, Interceptor 1000, Vanguard 700, Warden 800, Bombard 300, Bastion 300, `csrc/om_constants.h:483-514`); in a ground era (`om_set_era_kind(w, 1)`) a cross-layer pair follows R-005-09 (`om_fog_cross_layer_factor` is 1.0 looking down, 0.0 looking up) and the elevation-tier bonus is skipped; blocked route cells and cover discs block the line; terrain blocks it only when terrain is generated. `OM_TP_TARGET_BY_SIGHT` 1 is the default (`csrc/unit.c:1189-1195`, R-093-02). `om_tac_in_reach` (`csrc/unit.c:573`) allows a cross-layer target only within the reach set by `om_roster_set_reach`; unset is 0 up, 0 down. `om_unit_spawn_internal` keeps the layer a walker is given when no terrain exists, so a layout's `layer = 1` rows stand one band up with no terrain built. A flyer in a ground era is seen from 1.5 times the sensor radius regardless of band (`OM_TP_GROUND_FLYER_SEEN_MULT`), which is why stage 4 fights walk. `om_command_guard` (R-096-08): the unit's position is its post, it engages what its side sees, steps at most `GUARD_RADIUS` 200 wu, never walks off. Bindings present in `scripts/skilllab/engine.py`: `type_stats` (206), `set_reach` (223), `seen_by_sight` (263), `order_guard` (289), `can_see` (300), `unit_alive` (328), `set_param` (385), `set_canvas` (399), `set_era_kind` (453); `features.walk_on_ground` (`features.py:102`). ## Inputs / Outputs / Constraints / Out of scope

- Inputs: a layout TOML/JSON from the catalogue, a seed, `--sight on`, `--control-dir`, `--control sight`.
- Outputs: fight files (`schema om-fight-2`, additive optional keys `seen`, `sights`, `result.first_seen`, `orders.guard`), control fight files (same layout, `--sight off`), `results.md` with two `first seen` columns, a page, replay frames.
- Constraints: `csrc/` untouched; `om-fight-2` name unchanged (additive optional keys, DEC-fight-file-landscape-2026-11-05's precedent); the fight-file schema is a lab artifact, not a game contract; determinism: same layout, seed and flags give byte-identical fight files; `--sight off` output is byte-identical to before this cascade.
- Out of scope: facing and fire cones, height bands as terrain (the climb, stage 5), the vantage plateau as generated terrain, eye height (no terrain is built, so `OM_TP_SIGHT_EYE_HEIGHT` plays no part; the staircase's "eye height" is stage 5's with the bands), interference zones, the ping, any `csrc/` change, a `fight.json` schema version bump, a change to R-164-01, running fights on the Mac, staging layouts, L-0079 and L-0081 and L-0082 (no `predict_rate`).

## Acceptance criteria

Leaf A, `scripts/skilllab/arena/run.py`, `snapshot.py`, `scripts/skilllab/arena/SNAPSHOT.md` (the stage 4 rule set and the file)
1. `--sight on` is the stage 4 rule set (DEC-stage4-sight-bundle): the engine keeps `OM_TP_TARGET_BY_SIGHT` 1; `engine.set_era_kind(w, 1)`; the canvas is set and every role walks (`features.walk_on_ground`, as the control twin does) whether or not the layout has features; every role gets `engine.set_reach(w, type_id, 0, 1)` (DRAFT-stage4-reach-down); with `hold:A`/`hold:B` the holder's units get `engine.order_guard` after spawning (DEC-stage4-guard-holder) and the fight document's `orders` gains `guard: true` (`false` for `both_same_point`). The fight document carries `movement_kind` 1 whenever its units walk (so for every `--sight on` fight). `--sight off` changes nothing from today. Test: the H-063 chokepoint fixture with `--sight off` writes a byte-identical file before and after the leaf (the test pins the file's sha256 recorded on main `4fa618ce` in the fixture).
2. Frames gain per unit `seen`: the sorted list of living enemy unit ids this unit sees (`engine.can_see`), `[]` for a dead unit. The document gains `sights: {role: sensor radius}` (from `engine.type_stats`, as `ranges`). `result` gains `first_seen: {"A": tick | null, "B": tick | null}`, the first sampled tick (every `CHECK_EVERY`, one sim second, tick 0 included) at which that side's living units see any living enemy (`engine.seen_by_sight`). With `--sight off` none of the three keys is written.
3. `snapshot.validate` accepts `seen` (list of ints), `sights` (dict of non-negative numbers), `result.first_seen` (the two keys `A` and `B`, int or null) and `orders.guard` (bool) on `om-fight-2`, absent or present, and rejects each on `om-fight-1` naming the key; `SNAPSHOT.md` documents them and the sight-off control.
4. `--control sight` (with `--control-dir D`; default `ground`, today's twin) writes `D/<id>-control-s<n>.fight.json`, one per seed, as the same layout and seed run with the stage 4 rule set except that targeting by sight is off (`OM_TP_TARGET_BY_SIGHT` 0): ground era, walking units, reach 0 up 1 down, the holder guarded, so it differs from the main fight by sight only (DEC-stage4-control-sight-off, amended 2026-11-05: the stage 3 rule set stalls on the vantage fixture because reach up is 0 and nobody fires). The control document has `sight` `"off"`, `movement_kind` 1, `orders.guard` as applied, and none of `seen`, `sights`, `first_seen`. No twin layout is written; `layout_path` is the original. `--control sight` without `--control-dir` writes nothing (as `--control-dir` absent today); `--control ground` is allowed with `--sight on`. `fight()` takes `sight` `"control"` internally for this (the contract); the CLI keeps `off|on`. `--control sight` writes the control for every layout, whether or not `features.bound(layout)`. `results.md` with `--sight on` gains two final columns `first seen A` and `first seen B` (tick or `-`), header `| id | a:b | predict | winner | survivors | ticks | agree | blocked | first seen A | first seen B |`; with `--sight off` the header and rows are exactly stage 3's (`RESULTS_HEAD` unchanged, pinned by `tests/skilllab/arena/test_stage3_control.py:23`). `--control sight` is only meaningful with `--sight on`; with `--sight off` it is a usage error (exit 2).

## Scale & Boundary Profile

- **N typical / N peak:** 16 to 72 units a fight typical; 256 a side (512) peak (R4 maximum); frames at most 20 per fight (`snapshot` DRAFT-snapshot-count).
- **Growth claim per hot path:** `seen` per frame is `quadratic` in units per frame (512 x 256 `can_see` calls peak, 20 frames, about 2.6 M calls peak); `first_seen` is sampled once a sim second with `engine.seen_by_sight` per side, `linear-ish` in ticks over the tick rate times units; `page.build` is `linear-ish` in fights. The quadratic term is bounded by the 20-frame cap and the R4 maximum.
- **Memory posture:** bounded-buffer: frames are at most 20 per fight and kept in memory per fight only; `seen` lists are at most 256 ints per unit.
- **External call budget:** the engine library is built once per process; one world per fight; no network.
