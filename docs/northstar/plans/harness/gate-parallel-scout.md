## 4. Designs
A) Two gates at once, private dirs. Change: land HARNESS-userdir (XDG_DATA_HOME=$SCRATCH_ROOT/xdg in merge_gate.sh before first GODOT use; run_godot_tests.sh; daemon_client.py godot_env() so QA_SHOT_DIR/saves/privacy flag follow it; plays' QA_SHOT_DIR must read the same env rather than Path.home()/.local/share/data/qa: plays/A play_support.py:25, B _play.py:28, C _play.py:25, F _play.py:37, K _k_common.py:28, test_flow_spine.py:85,91 are NOT in the userdir piece list: spec :316 owns 4 files only, so they need adding); unique `.json.tmp` (pid suffix) in merge_gate_support.py:~611; replace the one lock by `flock` on a 2-slot semaphore (gate.lock.1/.2, try -n each) AND a short repush lock. Cost: 1 small harness piece + 6 path edits. Risk: load-sensitive tests above; /tmp tmpfs (~3.6G per gate ~ fine at 2); doubled CPU for playthrough software GL. Correctness: each gate result is "candidate merged onto main@S passes" for the S it started from, independent of concurrency.
B) Parallelise stages inside one gate (cheapest to reason about). Background-job: csim(+baseline), specfactory, transport (needs pipe build first), qa_t1; then playthrough/lane_plays after. Estimate cached: max(csim 800, specfactory 750, transport 245) + playthrough 370 + plays ~ 1,300-1,900 s vs 2,200-3,300 s; uncached drops 4,900 -> ~3,000. Needs: do the make once up front (conftest.py:41 make is a no-op when built, verify); gate_line ordering logs (outputs printed after wait, in fixed order); verdict set identical. Risk: csim timing asserts and qa_t1 WALL_BUDGET 2.0 s share CPU with 3 other pytest; mitigated by running the timing-sensitive suites (qa_t1: 27 s) first/alone. File: scripts/specfactory/merge_gate.sh (+ gate test). No Godot concurrency, no user-dir change.
C) Optimistic parallel: gates run concurrently from different base shas; only `fetch + merge origin/main + pre_gate + push` serialised by a short lock. Argument: a gate proves the candidate merged on main@S passes the full suite; push is then main@S' with S'!=S; the re-merge + pre_gate covers lints/footprint/owners/compile (~1 min) but NOT csim/specfactory/playthrough on the true merge (semantic conflict between two landings both green alone; files are owner-disjoint by pieces.toml but behavioural interaction: e.g. tests pinning counts/checksums goldens, save format). This weakens the "gate on the tree you ship" invariant; recommend it only for disjoint diffs (docs/tests-only/different csrc modules) and a post-push main smoke gate run behind. Needs A (or at least userdir) anyway.
