## Wave 2: the escalator seat (new `scripts/escalator.py`; `build.py` calls it through one function)

1. **A seat, not a model.** `projects/<slug>/profile.toml` `[escalator]` lists models in order with transport (`api-deepseek`, `api-anthropic`, `agy`), a daily call cap and a dollar cap each; the seat tries them in order on quota, timeout or empty reply, logs which answered, and reports `seat-down` when the list is exhausted (wave 1 item 1 consumes it). Order for ouroboros: DeepSeek API, Anthropic API, agy last (audit: agy shares Westley's quota and logs $0). Agentic CLIs are not a transport for fix tasks (B F-4-6): the seat sends prompts to model APIs only; the agy transport is hint-only.
2. **Canned positive control.** Before the first real task of a day, the seat runs the R7d case (byte-identical body fix, `escalator_fix_probe.py`'s fixture) through the first available model; a failure is a harness error, never a model finding. Not R7a (includes are hoisted anyway).
3. **Parent-patch fix task.** Input: a diagnosis naming one function (from the plateau call or a confirmed finding), the function body, the contract text, the `card_slice` header slice for that function's file (run the ouroboros tool by path; it is a project tool named in the profile as `slice_command`). Output contract as in `escalator_fix_probe.py`. Gates, in order: build; the named failing test green; the whole suite on exact failing-id sets (wave 1 item 4); diff-scoped mutation of the patched function against the tests that name it (PX-06's mutator by path, `mutation_command` in the profile); the parent-patch fence (PX-14, both checks, capture rule: a captured card whose symbol is still a STUB is a violation); control liveness of the story's controls. A diagnosis naming more than one function, or a reply returning more than the fenced function, becomes a repair-card request (item 5), never a second attempt.
4. **Test-fix task** (`test-defect` findings only). Allowed when the fix is a filter, a guard or one number. Gates: assertions preserved, still red at stub, fixture-defect detectors clear (all three from `escalator_fix_probe.py`), plus mutation of the function under test against the edited test must still kill, plus, for a filter, the excluded records asserted explicitly (count and reason) or the task is refused. A scenario that must be re-derived (R7l class) is written to `projects/<slug>/ledger/test-authoring.md` for Westley, with the detector report attached, and the card is parked with reason `awaiting-test-authoring`. Diagnoses are generated from the detector's report; no example numbers from any other configuration; the reply must state the pair it separates and the gate checks it.
5. **Repair-card request.** A confirmed finding on merged code that the seat cannot take becomes a file under `projects/<slug>/repair-requests/<id>.md` (finding, failing test or the test to write, function names) for the day side; the ledger shows it; nothing is generated into the queue (E3: Westley authors). Fingerprint dedupe so one defect makes one request.
6. Every seat edit writes a ledger row (`runs/ledger.jsonl`: task, model, transport, cost, gates passed, diff sha) for the epic architecture review.

## Wave 3: the scheduler and the two-slot process model (`next.py`, profile data)

1. **Chain from the graph.** `projects/<slug>/profile.toml` names `graph_command` (for ouroboros: the committed `chain_graph.py` invocation) and `next.py` reads its `graph.json` (shape frozen by the executor brief): a card is eligible when every edge into it points at a DONE card and its own errors list is empty; `RELEASE_CHAIN` is deleted; `errors` of kind `cycle`, `double_owner`, `missing_file`, `abi_gap` make a card ineligible and are listed in the ledger, never escalated. The graph refreshes after every merge.
2. **Escalate and continue.** A parked or seat-waiting card never blocks its siblings; the next eligible card runs. Idle with eligible work is a harness alarm (once); an empty graph runs the empty-chain list (item 5).
3. **Two slots, two processes.** The dispatcher runs a GPU-slot loop (one worker call at a time, `flock` on `/tmp/agora.gpu.lock`) and a CPU-slot loop (`/tmp/agora.cpu.lock`) for prep, gates, merges, seat calls and gate cards; `build.py`'s intervene call moves out of the worker process into a CPU-slot task so a 300 s seat timeout never idles the GPU. The systemd unit gains a second `ExecStart` or a second unit; the 60 s sleep stays for now (PX-19: not the bottleneck).
4. **Slot priority as data.** `[slots]` in the profile: build first, QA only on an empty graph or in a named window; `QA_INTERVAL_MIN` and the director-first order in `next.py:617-641` become profile values; explorer campaigns require their prerequisites present (hook scene exists, positive control green today) or they do not run (B F-10-2).
5. **Empty-chain list and runway.** `[empty_chain]` in the profile lists work in priority order (whole-suite mutation sweep, sanitizer and memcheck runs when a recipe exists, determinism soak, planted-build campaigns, refiner scoring); each writes ledger rows, never cards; a daily cloud call cap covers the whole list. Runway is written daily to `runs/ledger.jsonl`: eligible cards times rolling measured wall per DONE (including fix stretches), and buildable counts from the fuel lint; below 24 h of eligible work the alarm fires once per day (D3).
6. **The honest interrupt list** (E2): seat outage, harness-error cap, gate red and merge conflict have machine owners after waves 1 to 3 (pause and retry; ineligible with reason; red gate parks the subtree and continues siblings; merge conflict re-queues the card with reason). The other eight stay and are written into `projects/<slug>/README.md` as the interrupt budget.

Wave 3 replay set: PX-16's window through the real scheduler on a scratch queue (S1 numbers must reproduce within 10 percent); a cyclic cut ineligible with reason; a parked head not idling the GPU with two eligible cards; a red gate parking only its subtree.
