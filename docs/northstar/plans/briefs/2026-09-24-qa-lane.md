# QA lane: play the game and file bugs (open in a Sonnet 4.6 chat, cwd `~/Projects/ouroboros-manifold`)

You test. You do not build, merge, edit tests, write register rows, or touch memory files. One deliverable per run: a look report with screenshots and a bug backlog, in player language, that M0 (Claude session `parallel-backend-client-mvp`) and Westley read.

## Setup (every run)

1. `git pull --ff-only origin main` in `~/Projects/ouroboros-manifold` (Westley's live checkout: never stage, commit, stash or checkout anything there; if the pull refuses, stop and report the reason).
2. `make -j8 && make pipe/ouroboros_pipe`; `~/.local/bin/godot --headless --import --path . --quit` once.
3. `export OM_SAVE_DIR="$(mktemp -d)"` so nothing touches the real save directory; Xvfb the way `scripts/qa_harness.sh` starts it (never `:0`) unless Westley asked for a visible window.
4. `scripts/qa_harness.sh liveness` must print `LIVENESS OK`; if not, the report's first line is its failure line and you stop.
5. `~/Projects/agora/.venv/bin/python -m pytest tests/qa/desktop -q -p no:cacheprovider` — record counts; a red here is a finding, not a blocker for the play run.

## The play run (look-N)

Play like a person, through the real menu, with real input: the daemon (`autoload/qa_daemon.gd`, `--qa-port`, verbs `["state"]`, `["tree"]`, `["input",…]`, `["screenshot",name]`, `["plant",id]`, `tests/qa/desktop/daemon_client.py`) is your hands and eyes. Sequence: boot → main menu (Continue enabled only when a save exists) → New Game → galaxy (80 systems, coloured by owner, edges; let 200 ticks run through the session's step verb and watch for an owner change and a recolour) → pick the mission → briefing (situation, objective, band) → Deploy → tactical view (units present, fog, one move command through the session) → mission end → debrief (band, deltas) → chronicle after a jump (entries) → back to the galaxy → Continue from the autosave in a fresh boot at the saved tick. At each screen: one screenshot named `lookN_<screen>.png`, the `["state"]` dump saved beside it, and every plant id the scene exposes: plant, screenshot, pixel-difference versus the clean shot (PIL), unplant. Time each transition with the wall clock; note anything that stalls, flickers, draws wrong, or lies to the player.

## What you write

`docs/northstar/proving_ground/evidence/push_2026-09-22/first_look/lookN/README.md` (caveman prose): per screen what the player sees, the state numbers, the plant table, the timings; every visual claim is held with its screenshot path, never marked pass. And the backlog: `docs/legacy/agora_era/qa_backlog.md`, one row per bug: `| id | screen | severity (blocks play / wrong / ugly) | what the player sees | exact repro (verbs and inputs) | evidence path | suspected owner (sim, pipe, client) |`. Append, never rewrite others' rows; ids `QA-###` continue from the last one. Commit both on a branch `push/lookN` (worktree of `~/Projects/om-push/m3`, never the live checkout), push, and append `docs lookN push/lookN` to `~/Projects/om-push/queue.txt`. Then message M0 once with: liveness line, desktop counts, the number of backlog rows by severity, the three worst.

## Rules

Bugs are recorded, never fixed by you. A test that cannot fail (goes green when the game clearly did not do the thing) is a backlog row with owner "tests". Kill your Xvfb and Godot processes when done. git-guard denies rebase, reset --hard, clean, -D, --amend, force push, and any command text containing both "push" and "-f".
