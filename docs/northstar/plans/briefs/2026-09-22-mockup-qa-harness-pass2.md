# HANDOFF BRIEF — Mockup self-QA harness, pass 2: play it like Westley

Self-contained. Continues `scenes/mockups/_shared/` and `scripts/mockup_qa.sh` (harness brief `2026-09-22-mockup-qa-harness.md`, merged). Rules of that brief apply (bash and GDScript only, never `:0`, touch only `scenes/mockups/_shared/**`, `scripts/mockup_qa.sh`, `scripts/mockup_verify.sh`, and for the positive control `scenes/mockups/landscape/qa/**`).

- If you are an Opus or Fable chat: plan and review, Sonnet sub-agents build. If you are a Sonnet chat: do the work yourself, spawn no sub-agents.

## Why

Westley flew the mockups and found, in three of them, that nothing moved (the sims start paused), that buttons did nothing (they act on a selection that a click could not make), that the seed and reset did nothing, and that edge scroll only worked toward the top-left (the mouse is compared in canvas space against window pixels, which only diverge on a screen larger than 1920x1080). Every one of those passed the builders' QA and the screenshot reviewers because the smoke scripts drove the mockups through `call qa_*` verbs at 1280x720 with the sim stepped by `qa_tick`, never through the real buttons, keys and edges at his resolution with the clock running. His words: "I thought the QA from claude would catch major things like what I noticed from the layer one, how was claude QA'ing godot? Was it not opening its own window and clicking around?"

## What to build

1. **`scripts/mockup_qa.sh firstlook <mockup> <outdir> [--res 2560x1440]`**: runs `scenes/mockups/<mockup>/qa/firstlook.json` at 2560x1440 by default (his desktop is 4480x1440; 2560x1440 has the same 1440 height and exceeds the 1920x1080 canvas in both axes) with the sim NOT paused: the driver passes a new user arg `--qa-live` and the boot script exports it so a mockup's "paused under QA" rule does not apply. The script may use only real-input verbs (`move`, `click`, `click_node`, `drag`, `wheel`, `key`, `key_down`, `key_up`, `wait_frames`, `screenshot`, `state`); `firstlook` refuses to run a file containing `call`, `seed`, `plant` or `pause` (exit 2 with the offending line). `wait_frames` is real time here: run without `--fixed-fps` so the sim's own clock advances.
2. **Driver `expect` verb**: `["expect", "<state key path>", "changed" | "increased" | "equals", <value>]` compares against the previous `state` dump and prints `QA_EXPECT ok|FAIL <path>`; `scan` counts `QA_EXPECT FAIL` lines into `errors.txt`. This is how a first-look script asserts "clicking Regenerate changed the hash", "ten seconds of nothing advanced `tick`", "moving to the right edge increased `camera.x`".
3. **The first-look convention**, written into `scenes/mockups/_shared/README.md` under a "First look" heading, with a template `qa/firstlook.json` every mockup copies: launch and wait 5 s of real time, `expect tick increased` (the sim runs by itself); `move` to each of the four screen edges for 2 s each, `expect camera.x/z changed` in the right direction; `move` onto a HUD control for 2 s, `expect camera unchanged`; `click_node` every button the README lists, each followed by `expect` of the state key that button owns (regenerate changes `hash`, reset returns `tick` to 0, play toggles `playing`, kit toggle changes `kit`); `key` every hotkey the README lists with the same expectations; a real `click` on a unit's projected pixel taken from the previous `state` (allowed: the script author reads `units_px` from a prior run and writes the literal), `expect selected changed`; a `drag` box, `expect selected changed`; a screenshot after each group. The README's "Running it" line is the contract the first look tests.
4. **Rules added to the README's contract section**: a mockup's sim runs on an interactive launch and pauses only under `--qa-script` without `--qa-live`; every mouse comparison happens in one coordinate space (document the two correct patterns: canvas everywhere via `get_viewport().get_mouse_position()` against `get_viewport().get_visible_rect().size`, or window pixels everywhere via `get_final_transform()`); no edge scroll while `gui_get_hovered_control()` is non-null; buttons that act on a selection act on all friendlies when nothing is selected and say so.
5. **Positive control**: write `scenes/mockups/landscape/qa/firstlook.json` and run it; it must pass on the current landscape mockup, and it must fail (an `expect` FAIL for the right edge) when run with `XVFB_EXTRA` unchanged but the landscape camera rig temporarily compared against `window_get_size()` (do that in a scratch copy or a throwaway commit you then revert; do not leave the landscape broken).
6. **Reviewer protocol**: add a "Reviewer" paragraph to the README: a fresh-eyes reviewer runs `firstlook` itself and reads its screenshots and `QA_EXPECT` lines before reading the builder's checklist.
