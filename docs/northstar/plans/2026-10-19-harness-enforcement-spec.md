Westley picked all five checks of `2026-10-19-enforcement-and-redirect.md` section 2 on 2026-10-19 ("I like all of C1 through C5, let's do it"). This spec is written from the read-only pre-flight of origin/main 3c85c949 (scratchpad `harness_preflight.md`; every file:line below is from it or from audit round 1, which read d16be5c7) and rev 2 folded the twelve must-changes and nine should-fixes of audit round 1 and rev 3 the five remaining musts of round 2 (`harness_audit.md`). Every design choice here is implementation (Architect, 2026-10-19; Westley may veto); Westley owns which checks exist, and he has said all five. Two recorded deviations from the picked text, both forced by the code: C4's "the script hashes its own source" becomes a shell tool at launch plus a code check at the landing, because the Workflow runtime gives a script no file access (fact 10); C5's open flag is carried as `[OPEN Q-id]`, not `[W Q-id]`, because reason 5 of the lint requires a `[W]` row to be closed. ## 0. What the pre-flight found that changes the plan

1. **The lint cannot see the tags on main.** `spec_provenance.py` blanks every backtick span before it looks for a tag (`CODE_SPAN` :25, `Unit.plain` :42); the visible-game spec writes 29 of its 39 `[B` tags, 22 of 23 `[W` tags and all 37 of its `[P` tags inside backticks (fact 6; 39 `[P` across three files). Run on that spec it prints 191 findings; it runs nowhere on main except `pre_gate.sh:116` under `PRE_GATE_SPEC`, which no launch sets. Pins (C1) cannot be computed or checked until the tags are bare; a tool unwraps them, on an explicit list of live specs, never a glob (documentation that quotes a tag as an example stays in backticks).
2. **`status_check.py` is not run by anything** (fact 3) and does not read the register. It becomes a gate stage, and its new checks start as WARN so the first landings are not rejected by the drift they exist to find (audit M1).
3. **No workflow script hashes anything** (fact 10). See the deviation above.
4. **The rule text the lint keys on is wrong for a pin**: `load_context` concatenates every epic line that mentions an id (:160-161). A pin hashes the one line starting `- R-###-##` (1188 ids, 0 duplicates, one physical line each; fact 8).
5. **Owner lint allows a shared file only along a `depends_on` chain** (fact 4), and a `landed` row counts as in flight. The pieces below are a serial chain, one workflow, one landing each; the records piece adds its own row in its own landing.
6. The review queue header is tested as nine fixed columns (`test_story_reviews_format.py`), so the review-row fields go inside the verdict cell as labelled fields.
7. **Pins in tests cannot be a 523-file edit** (audit M8): fenced tests are not touched by a clerk in advance, and a line added to each would shift 298 `tests/...:N` citations in 44 files. Existing tests get their pins in a sidecar generated by the tool; a test file changed after the cutoff carries its own `Rule pins:` line, so files migrate as they are touched.
