## Rulings needed from Westley before launch

- **W1 the window.** The bible and the reference disagree. E-10 R-073-01 says "this window" three times (Defensive Stand: "targeted by an enemy attack this window"; Reconquest: "lost by conquest this window"; Multi-Front: "two or more factions this window"); the reference never windowed (its harness lists grew for the whole run, `mission_generator.py:37-73` filter by region only). Storage is a ring either way (oldest overwritten; caps `DRAFT-log-attacks` 4,096, `DRAFT-log-conquests` 1,024, `DRAFT-log-events` 4,096, enough for three to six 50-tick jumps at 400 regions: the 2026-10-15 sweep wrote 12,327 attacks and 22,683 events over 25 jumps). The ruling is what the readers count: (a) **the bible's window: entries with `tick >= window_start`, where `window_start` is the tick of the previous mission's end (the jump that led here), held on the store and set by `mission_end` and `mission_refuse`; the first chapter counts from tick 0**; (b) the reference: every entry the ring still holds; (c) a fixed tick count behind the pool-build tick (a number of Westley's). Lean (a): it is the bible's word, and "the galaxy has visibly changed" reads the jump, not the campaign.
- **W2 the Defensive Stand trigger.** The reference let Defensive Stand into the pool only when the attack log held an attack on the region by a non-player faction (`mission_generator.py:81-96`); the C arm adds "or any hostile neighbour" (`mission.c:558-561`), and `tests/csim/test_E10_S072_orders_come_from_where_the_world_hurts.py:60-100` pins that OR. (a) drop the OR, as the reference and E-10 R-073-01; that test is ruled a test-defect (`TD-SIM-1`) and rewritten to log an attack; (b) keep the OR and give an unattacked stand the R-074-01 "otherwise" power (`region.m × 2000`) so it composes; note (b) has no attacker budget for ALG-57's "committed budget × 300", so the force would be sized as an insurgency, not a defence. Lean (a): the sim's "highly active regions" come from urgency (which the attack and chain terms now feed), not from a trigger that admits empty missions.
- **W3 chain length.** (a) parity: stays 0, the reference's effective behaviour (`chain_length` was never set in the Python); (b) filled per jump: `chain_length` of an event is the number of events in the jump sharing its `chain_tag` (tag 0, untagged, counts as length 1; ALG-50 applies its term only when L > 1), taken from the per-jump chain table `generational.c:2008-2022` (`chains[].n_events`), not from the ring, so no draft cap moves a score. Lean (b): E-09 R-066-02 and R-066-04 and ALG-50 say it; the reference silently disagreed with the bible.

**State** (`simlog_internal.h`, included by `om_internal.h`):
```c
typedef struct om_log_attack   { int64_t tick; int32_t attacker, target_region; double commit; int32_t conquest; } om_log_attack;   /* 32 B */
typedef struct om_log_conquest { int64_t tick; int32_t region, old_faction, new_faction; int32_t by_attack; } om_log_conquest;  /* 24 B; by_attack 1 from resolve, 0 from lifecycle */
typedef struct om_log_event    { int64_t tick; int32_t region, template_id; uint32_t chain_tag; int32_t chain_length; } om_log_event;  /* 24 B; chain_length per W3 */
#define OM_LOG_ATTACK_CAP 4096   /* DRAFT-log-attacks */
#define OM_LOG_CONQUEST_CAP 1024 /* DRAFT-log-conquests */
#define OM_LOG_EVENT_CAP 4096    /* DRAFT-log-events */
typedef struct om_simlog_state {
    uint32_t attack_head, attack_n;     om_log_attack   attacks[OM_LOG_ATTACK_CAP];
    uint32_t conquest_head, conquest_n; om_log_conquest conquests[OM_LOG_CONQUEST_CAP];
    uint32_t event_head, event_n;       om_log_event    events[OM_LOG_EVENT_CAP];
    int64_t  window_start;              /* W1 (a): tick of the previous mission's end or refusal; 0 at campaign start */
    uint16_t times_run[OM_SIMLOG_MAX_LINEAGES][OM_MISSION_N_ARCHETYPES];   /* OM_MISSION_N_ARCHETYPES is 10 (mission.c:104); OM_SIMLOG_MAX_LINEAGES is new, 512, the value of generational.c's private GEN_MAX_LINEAGES (:181), moved to simlog_internal.h with a _Static_assert in generational.c that the two are equal */
} om_simlog_state;   /* 131,072 + 24,576 + 98,304 + 10,240 + 32 = about 264 KB */
```
Ring rule: `head` is the next write slot, `n` saturates at the cap; iteration oldest to newest is `i = (head - n + k) mod cap`. No heap, no hash order, no wall clock. The lineage key of `times_run` is the **lineage slot**, the index `i` into `gs->lineages[i]` (`generational.c:252`), not the lineage id: `simlog.c` gets it through a new internal `int32_t om_lineage_slot_of(const om_world*, uint32_t lineage_id)` in `generational.c` (a linear scan of `lineages[].used && .id == id`, -1 if none). "The seated lineage" everywhere in this spec means `om_campaign_lineage(w)` (`generational.c:1552`); the reader at `mission.c:2224-2226` currently uses `om_lineage_id_at(nl - 1)`, the last lineage, and is changed to the seated one in this piece (one line; `test_E10_S072_a2_refresh_lost_quiet_lineage.py:75` keeps its value because its one lineage is both). A slot of -1 reads and writes nothing.
