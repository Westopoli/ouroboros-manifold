# skilllab-harness

Cascade A of `docs/northstar/plans/2026-10-02-skill-lab-cascade.md` (the brief, section 3). Where this file and the brief disagree, the brief wins and the disagreement is a finding to report.

## Summary

A Python package, `scripts/skilllab/`, that drives the production C library (`csrc/`, built as a shared library) through ctypes, runs tactical fights of one setup against another, and measures them: who wins, by how much, how many units could fire at each moment, and where the break-even enemy headcount is. It calls the production library only. No engine edit. Tests live in `tests/skilllab/` (pytest), not under `tests/csim/`.

## Acceptance criteria

Contract and engine
1. `scripts/skilllab/contract.py` defines the frozen dataclasses `Group` and `Setup`, the dataclasses `FightResult`, `CellResult`, `ScanResult`, and the call signatures of brief section 3.1, with the field names and types given there.
2. `engine.py` builds the library into a scratch directory outside the repo tree, never into the repo root, using compiler flags chosen by machine architecture: `-msse2 -mfpmath=sse` only when the machine is x86; the other flags are those of the repo `Makefile`. It loads the library once per process and binds every `om_` call the harness uses. The architecture is read from `platform.machine()` and the compiler is run with `subprocess.run`, so a test can observe the command. The `Makefile` and `csrc/` are not edited. Readings: the command includes `-O2`; a missing `scratch_dir` is created; `x86_64`, `AMD64`, `i386`, `i686` and `x86` count as x86; a compiler failure or missing `cc` raises `RuntimeError` carrying the last 2000 characters of the compiler's stderr; the library suffix is `.dylib` on macOS and `.so` elsewhere.
3. `engine.py` exposes one `Engine` object with methods: `new_world(seed)`, `free_world(w)`, `register_unit_type(w, type_id, stats)` (calls `om_roster_register_custom_unit`), `type_id(name)` for a built-in type name, `type_stats(w, type_id)` (max hp, attack range, attack interval, damage, speed, sensor radius), `disable_abilities(w)`, `spawn(w, type_id, faction, x, y, layer)`, `order_attack_move(w, unit_ids, x, y)`, `order_move(w, unit_ids, x, y)`, `step(w)`, `unit_hp(w, u)`, `unit_pos(w, u)`, `unit_layer(w, u)`, `unit_alive(w, u)`, `can_shoot(w, a, b)` (calls `om_combat_can_shoot`), and `add_blocker(w, x, y, radius)` (a map object that makes `can_shoot` false for a pair it lies between; the engine leaf finds which map call does this). `type_id(name)` maps the built-in names Vanguard, Warden, Raider, Interceptor, Bombard, Bastion to the `OM_UT_*` ids in `csrc/unit.c`; an unknown name is an error. `unit_alive` calls `om_unit_alive`. Positions and hp are read with `om_unit_get_pos` and `om_unit_get_hp`. Readings: `type_id` is case-sensitive and accepts only the six listed names (`Supply` and `Evacuation` raise `ValueError`); `type_stats` returns a dict whose keys are the stat names of AC 5; `add_blocker` with `radius <= 0` raises `ValueError`; `Engine(lib_path)` with a nonexistent path raises `OSError`; behaviour on a freed world or a nonexistent unit is undefined and untested; `new_world(seed)` is the call `fight` makes before any spawn. `type_stats` returns exactly the nine keys `category, max_hp, base_damage, attack_interval, attack_range, speed, sensor_radius, layer_transition_time, aoe_radius`.

Formations
4. `formations.place(kind, n, x, y, facing_deg, params)` returns exactly `n` `(x, y)` points for `kind` in `line`, `blob`, `concave`, `column`, `points`. Same input, same output, no randomness. `line`: `n` points abreast, perpendicular to facing, centred on the anchor, spaced by `params["spacing"]`. `column`: `params["cols"]` columns deep along the facing. `concave`: points on an arc of `params["arc_deg"]` opening toward facing. `blob`: points inside a disc of `params["radius"]`. `points`: `params["points"]` verbatim; a length other than `n` is an error. Geometry is a port of `toys/layerlab/layerlab/formations.py`. Readings: everything this line leaves open is the toy's behaviour (point order in a line, blob fill, which point of a concave arc the anchor is, what `cols` and `spacing` mean for a column), pinned in tests by literals taken from one run of the toy; `n == 0` returns `[]`, `n < 0` raises `ValueError`; `kind` is case-sensitive; a missing required parameter (`spacing` for line, column; `arc_deg` for concave; `radius` for blob) raises `ValueError`; extra parameters are ignored. Mappings of the five kinds onto the toy: `column` is the toy's `box` (`cols` units abreast perpendicular to the facing, rows deep along the facing, all `spacing` apart, a short last row centred); `concave` places units on a circle of radius `params["radius"]` whose centre is `radius` ahead of the anchor along the facing, spread over `arc_deg` centred on the axis from the centre to the anchor (the toy's `concave` with `center = anchor + radius * facing`, `R = radius`); `blob` has no toy equivalent: any deterministic fill of the disc inside radius `params["radius"]` of the anchor, centrally symmetric about the anchor (the reflection of every point through the anchor is also a point, to 1e-6; an odd `n` puts one point on the anchor), so a mirror match of two blobs is a true mirror; tested for count, containment, distinctness, determinism and that symmetry.

Fight
5. `fight(setup, seed, swap)` spawns the groups of `setup` (one world per call), registers `setup.unit_types`, calls `om_tactical_disable_abilities` when `setup.abilities` is false, and steps with `om_tactical_step` until one side has no living unit (elimination: `side0`, `side1`, or `draw` when both sides die on one tick) or `max_ticks` is reached (`cap`: a lab defect to trace, never a result; Q-LAB-03). It never calls `om_tactical_run_until_eliminated`. A `unit_types` entry is either a full stats dict (keys `category`, `role`, `max_hp`, `base_damage`, `attack_interval`, `attack_range`, `speed`, `sensor_radius`, `layer_transition_time`, `aoe_radius`, `ability_id`) or a derived one: `{"base": <built-in name>, "scale": {stat: factor}, "set": {stat: value}}`, which `fight` resolves through `engine.type_stats` of the base type, applies `scale` then `set`, and registers under a type id of 100 or more. `fight(..., engine=None)` takes an optional engine object with the methods of AC 3 (default: a new `Engine`); tests use it to inject a fake. Orders: an `attack_move`, `move` or `group_move` group goes to its group goal, else to `Setup.point` (the shared attack-move point: the midpoint of a meeting, the holder's centre of mass for an assault), else to the anchor of the first group of the other side; a `guard` group is ordered to guard and an `idle` group gets no order. With `orders_per_unit` True (a `Setup` field, True by default; the flip to group attack-move is conditional, decision 43 item 1) an `attack_move` group is ordered by one `order_attack_move` call per unit; the later timeline steps stay group-level. `Setup.firing_arc_deg` is set on the world through `OM_TP_FIRING_ARC_DEG` when it is below 360 and the library has the parameter, and `Setup.cone` is applied through `Engine.set_cone` after the unit types are registered. Re-engage (decisions 28 and 43): when a side has had no unit fire or move for `REENGAGE_SILENCE_TICKS` (DRAFT 40) and sees an enemy, each of its idle attack-move units gets its own attack-move onto the centroid of the enemies it sees (a lab-issued order, exempt from `orders_per_unit`), once per silence period; a unit has moved when it is displaced by more than `REENGAGE_MOVED_WU` (DRAFT-reengage-moved-wu, 1 wu) from its position at the last reset of the silence counter. A no-op engage (every ordered living unit still has no destination a tick later) re-arms the side at once and retries after another `REENGAGE_SILENCE_TICKS`. `FightResult.reengage` counts the events per side. Readings: a full stats entry also gets a type id of 100 or more (ids go in order of first use); an unknown unit name raises `ValueError` from `type_id`, unwrapped; a derived entry scaling or setting a stat its base lacks raises `ValueError`; a derived entry is registered with `role` equal to its base name and `ability_id` 0; a side with no units (count 0 or no group) raises `ValueError`; `max_ticks` or `sample_every` below 1 raises `ValueError`; the world is freed in a `finally`.
6. Each unit's spawn point is its formation point plus a shift drawn from `random.Random(seed)`, each axis uniform in `[-10, +10]` world units. The same `seed` gives the same shifts. The engine has no randomness; these shifts are the replicates.
7. `swap=True` spawns side 1's units before side 0's; `swap=False` spawns side 0's first. The engine acts in unit-id order, so the first-spawned side shoots first. Margins and results are always reported from side 0's point of view whichever side spawned first.
8. Strength of a side is the sum over its living units of (current hp divided by that unit's starting hp), divided by the side's starting headcount. `strength_left` is that number for each side at the end. `margin` is `strength_left[0] - strength_left[1]`. `survivors` counts living units and `heads` the starting headcounts. `ticks` is the number of steps taken. Readings: strength is not clamped (a unit above its starting hp counts above 1).
9. RETIRED (Q-LAB-03, Westley 2026-10-13): a fight ends by elimination, or structurally (LAB-REV3-C): `no_reach_stall` (from the first tick at which no living unit of either side can reach any living enemy by the reach table and the live layers, R-164-01: outcome `no_reach_stall`, winner None) and `decided_one_way_reach` (from the first tick at which every living unit of one side is unreachable by every living enemy and one of them can reach one: that side wins, `decided_tick` is the tick, the fight stops there); the tick cap is a bug detector, a capped fight is a lab defect, never a result. Rebuilt by LAB-REV2-L2 (`docs/northstar/plans/2026-10-14-skill-lab-rev2-spec.md`, ruling 1).
10. Every `sample_every` ticks (and at tick 0) `fight` records `(tick, able0, able1)` in `firing` from `firing.count_able(engine, w, units0, units1, arc_deg)`. A living unit is able when its code is 0: `om_combat_can_engage` against some living enemy reads 0. Until E0 is on main the count composes the same five gates from public queries, in the diagnostic order 1 out of reach (`profile_reach` of the unit's type at the layer offset from `unit_layer`), 2 not seen (the enemy is in `visible_enemies` of the unit's side), 3 out of range at the offset (attack range times `OM_TP_RANGE_UP_k` / `OM_TP_RANGE_DOWN_k`, planar distance `<=`), 4 outside the arc (only when `arc_deg < 360`; `|bearing - facing| <= arc_deg / 2` as an angle comparison, boundary inclusive), 5 line blocked (`can_shoot`). After E0 the code is the engine's own answer and the composition is the parity check (`firing.parity` lists the units where the two able sets differ; empty when `om_combat_can_engage` is absent or the E0 stub). The weighted prediction `firing.count_weighted` sums, over code-0 units only, `Engine.category_multiplier` of the unit's category against its target of record's category (never damage, interval, health or a cross-layer damage multiplier). The target of record, per unit per sample, is the engine's target if its code against it is 0; else the nearest living hostile with code 0; else the nearest living hostile (the code is then its first failing reason 1..5); `-1` only when no living hostile exists. `firing.states` returns `[(unit, code)]` by unit id, dead omitted. `first_contact_tick` is the first sampled tick at which any unit's code is 0, or `-1` when never. `firing_unit_seconds` is, per side, the sum over samples of `able * sample_every / 20`. Limit: the composed count assumes target-by-sight on (`OM_TP_TARGET_BY_SIGHT` 1); stealth is reason 2 only through `can_engage`; gone when E0 lands. Replaces the same-layer count of rev 1 (`ranges`, `alive` set and the engine-target-only weighted rule are gone).
11. `FightResult` fields: `outcome` (`side0`, `side1`, `draw`, `cap` or `no_reach_stall`), `winner` (the surviving side, or the decided side; None for `draw`, `cap` and `no_reach_stall`), `verdict` (None, `no_reach_stall` or `decided_one_way_reach`) and `decided_tick` (the tick a `decided_one_way_reach` fight became decided, else None), `ticks`, `margin`, `strength_left`, `survivors`, `heads`, `first_contact_tick`, `firing`, `firing_unit_seconds`, `weighted_unit_seconds`, `firing_window` and `weighted_window` (unit-seconds over the half-open window [first_contact_tick, first_contact_tick + 40), DRAFT-opening-window-ticks), `predicted_count` and `predicted_type` (`side0`, `side1` or `tie`: the larger window total, equal is `tie`; the count from `firing_window`, the type from `weighted_window`), `agreement` (`both_right`, `count_wrong_type_right`, `both_wrong`, `count_right_type_wrong`, or `n/a` for a `draw`, a `cap` or a `tie`) and `reengage` are populated on every call, including a `draw` and a `cap`; `blind_cap` is True when the outcome is `cap` and at the cap tick neither side sees any living enemy (a finding of a blind post, not a lab defect to trace). `states` (`[(tick, unit, code)]` at sample ticks) is a list when `Setup.states` is set and `[]` when it is not.

Plays
12. `plays.py` provides builder functions that return `build(enemy_heads, swap) -> Setup`: `blob_play(size, unit="Vanguard")` and `line_play(size, unit="Vanguard")` (the naive plays), `damage_play(size, unit="Vanguard", factor=1.2)` (the labelled positive control of ruling 2, the planted damage scan and the only asymmetry the lab allows: side 0's unit is `{"base": unit, "scale": {"base_damage": factor}}` named `<unit>Strong`) and `reach_play` (the same arguments), which is retired by ruling 2 (a stat variant gives side 0 a different unit from side 1; the range study is the engine's range-up multiplier by offset, the `range_up` family) and stays in the code only for the `reach` command, never as a play. Every build places two sides facing each other on flat ground, side 0 of `size` units at negative x facing 0 degrees and side 1 of `enemy_heads` units at positive x facing 180 degrees, both with the same formation kind and the same base unit type (for `damage_play` the modified type is on side 0 only; side 1's `unit_types` entry set is empty), layer 0, order `attack_move`, no group goal, `abilities` False, default `sample_every`, `max_ticks` 12000. A meeting (ruling 6): both sides are attack-moved to `Setup.point`, the midpoint of the two anchors (0, 0), as per-unit orders while `orders_per_unit` is True; `swap` does not change the Setup. Formation: `blob` (radius `80 + 12 * sqrt(count)`) for `blob_play` and `damage_play`, `line` (spacing 30) for `line_play`. Contact placement (Westley, 2026-10-02: position matters, units are not lined up and walked in from far apart): the two sides start just outside the longer sensor radius of the unit types involved. The anchors lie on the x axis, symmetric about 0, at distance `S + 1 + d0 + d1` apart, where `S` is the sensor radius of the base unit type (`plays.unit_stats(unit)["sensor_radius"]`, never a literal) and `d0`, `d1` are each side's depth along the axis (a blob's radius; 0 for a line). `plays.unit_stats(name)` returns the stats dict of `engine.Engine.type_stats` for a built-in name by making a throwaway world once per process and caching the result; `plays` imports `engine` only inside that function. Readings: `size` or `enemy_heads` below 1 raises `ValueError` when `build` is called; an unknown unit name fails in `unit_stats`; `factor <= 0` raises `ValueError` and 1.0 is allowed.

Scan
13. `cell(build, enemy_heads, replicates)` runs `fight` for both spawn orders (`swap` False and True) and for seeds `0 .. replicates-1`, and returns a `CellResult` holding every `FightResult`, the mean margin over all of them, `won` and `defect`. A cell is won when every fight is `side0` (elimination; the margin sets no threshold); a `draw` or a `cap` among the fights marks the cell `defect`, a lab defect to trace, and the scan goes on. Readings: `replicates < 1` raises `ValueError`; fights are called swap-outer, seed-inner and `CellResult.fights` keeps that order.
14. `scan(build, size, enemy_from, enemy_to, replicates=10)` returns a `ScanResult` with the cells in increasing enemy headcount, `beats` and `loses_to`, `ceiling_hit` and `multi_flip`. By default a coarse pass fights every 8th headcount and the top one, then bisection halves the first won-to-lost bracket until its two headcounts are adjacent; `full_scan` fights every headcount from `enemy_from` to `enemy_to`. When the cells, taken in increasing enemy headcount, change from won to lost, `beats` is the last won headcount before the first such change and `loses_to` is `beats + 1`. When the play wins at every scanned headcount, `ceiling_hit` is True, `beats` is the top headcount and `loses_to` is None (never read as no gain); when it loses at every headcount, `beats` and `loses_to` are both None; `multi_flip` is True when the won and lost sequence changes more than once, and the first change is the one read. (Reading: first won-to-lost change, scanning upward; no smoothing or fit, `beats` and `loses_to` come straight from the cells.) `cell` and `scan` take an optional `fight_fn` (default: `fight.fight`) called as `fight_fn(setup, seed, swap)`, and a `map_fn` that fights a list of jobs at once; tests use them to feed synthetic results.
15. RETIRED (Q-LAB-03, Westley 2026-10-13): there is no stalemate outcome and no "not won" rule for one; a cell is won when every fight is `side0`, a `draw` or `cap` marks the cell `defect`; a `no_reach_stall` is a finding, not a win and not a defect. Rebuilt by LAB-REV2-L2 and L4.
16. `sample.py` provides `grid(dims, per_dim)` and `random_samples(dims, n, seed)` ported from `toys/layerlab/layerlab/sample.py`: same arguments, same outputs for the same inputs, no use of wall-clock or hash order. Reading: `random_samples` with `n < 0` returns an empty list, as the toy does.

Rows and report
17. `write_rows(rows, path)` writes a CSV file whose bytes depend only on the rows: columns in the order of first appearance, one fixed numeric format, `\n` line ends, no timestamp. Ported from `toys/layerlab/layerlab/batch.py`. Rows are plain dicts, one per fight. `rows.fight_row(result, **labels)` flattens a `FightResult` into one such dict: the label keyword arguments first, in the order given, then `outcome`, `margin`, `strength_left_0`, `strength_left_1`, `survivors_0`, `survivors_1`, `heads_0`, `heads_1`, `ticks`, `first_contact_tick`, `firing_unit_seconds_0`, `firing_unit_seconds_1`, firing_window_0, firing_window_1, weighted_unit_seconds_0, weighted_unit_seconds_1, weighted_window_0, weighted_window_1, predicted_count, predicted_type, agreement, then `knob` (the parameter name or `none`), `knob_value` (float or empty), `baseline` (`naive_attacker`, `naive_defender`, `naive_defender_attacker_layer`, `naive_defender_play_layer` or `none`), `ceiling_hit` (0 or 1), `prefight` (`ok`, `no_fit`, `unroutable`, `no_reach` or `blind_post`), reengage_0 and reengage_1 (the re-engage events per side). A sweep row adds the labels `family`, `play`, `layout`, `kind`, `enemy_heads`, `baseline_no_fit` (1 on a scan cut by baseline_no_fit), `blind_post` (1 when the fight capped with neither side seeing any living enemy at the cap tick: `FightResult.blind_cap`) and `point`, the family-local series of the row (a cone row `half=<degrees>` with `knob_value` the range, an emitting row `vision=<value>` with `knob_value` the sight, every other family `-`). Readings: a label named like one of the fixed keys raises `ValueError`; an empty `rows` writes a 0-byte file; `nan` and `inf` are written as the text `nan` and `inf`; a missing parent directory of `path` is created.
18. `report(batch, out_dir)` writes one self-contained HTML file into `out_dir` and returns its path. No external script; fonts only from `fonts.googleapis.com`. It works in light and dark (`prefers-color-scheme`). Readings: a missing `out_dir` is created; an empty batch gives a valid page with no figures; `Batch.title` is the page's `<h1>`; a series with one point or all zeros is drawn as a flat line, never raising. The `artifact` command (`report.artifact`) writes `artifact.html` and one SVG per notable under `diagrams/`, with arrows that carry the CSV value they come from (README section 5).
19. The page has, per scan: a heading that states the finding in soldiers (when the batch has scans labelled `reach` and `identical`: "With longer reach, {size} units beat {reach.beats}. Identical sides beat {identical.beats}."; for a scan with no break-even: "No break-even found between {A} and {B} enemy units.", with the scan's own first and last enemy headcount); a line of fights by enemy size with one dot per cell, coloured won or lost, the break-even marked and labelled "beats N, loses to N+1"; a chart of units able to fire through one fight, one line per side, labelled on the chart, the gap shaded; and under each chart a table view of the same numbers. A table with a plain-words column replaces any scatter plot. Readings: when `reach` and `identical` both exist but either `beats` is None or either is a ceiling hit, the page gives one sentence per scan (the no-break-even sentence for that scan, the plain `{label}: {size} units beat {N}.` for the other) instead of the combined sentence; with only one of `reach` and `identical` present, that scan is treated like any other label; a scan labelled other than `reach` or `identical` gets `{label}: {size} units beat {N}.` or the no-break-even sentence; the firing chart's series are named `Side 0` and `Side 1`; the scan table's plain-words column has the header `In words` and each row's cell reads `{size} units beat {enemy_heads}` when the cell was won and `{size} units lose to {enemy_heads}` when it was not. A scan that wins every headcount reads "{label}: ceiling hit, {size} units beat every enemy size up to {beats}."; the artifact lists a ceiling hit with its diagram, and a scan cut by baseline_no_fit as "won through K, scan cut by baseline_no_fit" (always won) or "scan cut by baseline_no_fit at K", never a ceiling hit.

Command

The entry point is guarded by `if __name__ == "__main__":`; worker processes, if any, receive plain data only. Readings: `main` creates the output directory (parents included); the firing example of each label is the first fight of its cell at 16 enemies (the cell of `enemy_heads == 16`).

## Rev 2 decisions (LAB-REV2-L1, 2026-10-14)

- `Setup.weighted` is removed; `Setup.states` is opt-in (on for sweep and smoke, off for the controls and the speed guards); `FightResult.order_ends` is removed.
- Nearest hostile is by planar x, y distance (layer ignored), a tie goes to the lowest unit id; `states` is ordered by unit id and omits the dead.
- Arc boundary is inclusive (`|bearing - facing| <= arc_deg / 2`, an angle comparison, never a cosine compare); `arc_deg >= 360` is off.
- Parity runs at tick 0 only, on the open-ground mirror blob (16 v 16, arc 360; the smoke's `parity` key), fog on, `OM_TP_TARGET_BY_SIGHT` 1 only.
- The four `Engine` wrappers are `unit_type`, `category_multiplier`, `transition_progress` and `can_engage` (the last reads -1 when the library lacks `om_combat_can_engage`; `_bind` does not fail on it).

## Inputs / Outputs / Constraints / Out of scope

- Inputs: the production library built from `csrc/`; built-in unit type names; `Setup` objects.
- Outputs: `FightResult`, `CellResult`, `ScanResult`, a CSV rows file, one HTML page, and from a sweep the artifact page with its SVG diagrams.
- Constraints: no machine paths in code or tests (the repo root is found from the file's own location); entry points guarded; macOS starts workers by spawn, so no reliance on fork; nothing generated is committed except `tests/skilllab/golden_hashes.json`; the harness never edits `csrc/`, `Makefile` or `toys/`.
- Out of scope: engine edits (Cascade B); the Godot client and pipe frames; the toy (frozen); any change to game rules.
- To find out and report, not decide: how the engine numbers layers; whether the engine's own 1800-tick stalemate rule matters when stepping with `om_tactical_step`; measured fights per second on each machine.

## Scale & Boundary Profile

- **N typical / N peak:** 16 units a side typical; scans to 24 enemy units in the controls and to 48 in a sweep; 10 replicates (3 in a sweep) times 2 spawn orders per cell; up to 12000 ticks a fight.
- **Growth claim per hot path:** `fight` is linear-ish in units for the able-to-fire sample (units times enemies per sample is allowed to be quadratic-ok at these sizes); `scan` is linear in the number of cells; `write_rows` and `report` are linear in rows.

- **External call budget:** one library build per process; one world per fight.
