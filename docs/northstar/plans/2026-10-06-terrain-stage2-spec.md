## Scope

Two pieces behind one contract piece. **2a Walkers:** a movement kind per unit type; a walker stands only on the ground's band at its position, routes by least time over walkable cells and slopes, changes layer at a slope's midline by position, never takes a timed transfer, ignores layer orders, and spawns on the band under it. **2b Ground vision and era kind:** an era kind (space 0, ground 1) in the world; in a ground era a lower unit never sees a higher one, a higher unit sees down within its sensor radius unless ground stands in the line, a flyer sees down and is seen from farther than it sees, vantage nodes and the elevation bonus do nothing, the ping is refused. Not in stage 2: pipe and client (stage 3); missions calling the generator (stage 3); seer and scout units (E-11 S-201, own piece); swimming (declared, not routed); slopes spanning more than two layers (Q-STAGE2-01); water (stage 1 clamps it to height 0).

The space model is the default: with era kind 0 and every type flying, no fight changes. Hash honesty is in its own section below.

## Contract piece (lands first; one agent; `push/terrain2-base` from `origin/main`)

`signatures.toml` then `sig_table.py --emit`; these public symbols and no other, with working bodies where stated so the lanes can build in parallel:

- Enum `om_movement_kind` in the header in the form of the existing enums: `OM_MOVE_FLYING = 0, OM_MOVE_WALKING = 1, OM_MOVE_SWIMMING = 2`.
- `int om_roster_set_movement_kind(om_world *w, int type, int kind)` (0 ok; 1 unknown type; 2 unknown kind) and `int om_unit_profile_movement_kind(const om_world *w, int type)` (module `tactical_move.c`, stored exactly as reach is: a per-type array in the move state beside `reach_type/up/down` (`tactical_move.c` ~314), hashed where reach is hashed (~3251) and saved where reach is saved (~3349, ~3481), carried across `om_tactical_reset` by hand as `kept_up/kept_down` are (`unit.c` ~2392-2418)). **Working bodies in the contract piece**, since the unit and fog lanes read the kind.
- `int om_set_era_kind(om_world *w, int kind)` (0 ok, 1 bad kind), `int om_era_kind(const om_world *w)` (module `fog.c`; stored in fog state beside the era flags; hashed and saved with them; default 0). **Working bodies in the contract piece.**
- `uint32_t om_terrain_walk_mask(const om_world *w, int layer, uint8_t *out, uint32_t cap)` (module `terrain.c`; `layer` is an engine layer 0..4; one byte per cell, 1 where a walker may stand on that layer: the cell's band is `layer + 1` and the cell is walkable, or the cell belongs to a slope whose lower or upper band is `layer + 1` and the cell is walkable; returns the cell count; `out` NULL returns the count only).
- `int om_terrain_slope_at(const om_world *w, double x, double y, om_slope *out)` (the struct is `om_slope` in the header, `OMSlope` in `signatures.toml`): the lowest-index slope whose run contains the cell and whose bands match the cell's band; returns the slope index, or -1.
- `int om_terrain_sight_blocks(const om_world *w, double x0, double y0, double x1, double y1)`: positions only; both endpoints at terrain height plus `OM_TP_SIGHT_EYE_HEIGHT`; samples every 25 wu along the segment, skipping samples within half a cell of either endpoint (the own-cell exemption the blocked-bit walk has today, `fog.c` ~371); 1 when the terrain height at a sample exceeds the line's height there; 0 when no terrain is present. Integer cm throughout; no libm beyond `sqrt`.
- Internal (`om_internal.h`): `int om_walk_route(const om_world *w, uint32_t unit, double gx, double gy, double *pts, uint32_t cap, double *seconds)`: returns the point count written (x, y pairs; the first point is the unit's position, the last the end); when the goal is unreachable the route ends at the nearest reachable cell (R-200-04) and the count is still positive; 0 when the unit is already in the goal cell; -1 when the unit has no walkable cell on its layer; when `cap` is too small, returns the needed count and writes nothing; `seconds` is the route's total time (0 on -1). The goal's layer is the band under the goal; the planner works on the unit's layer and crosses only by slope links. `void om_move_walker_tick(om_world *w)`. The walk-mask arrays and the kind array on the structs that hold them. `csrc/walk_route.c` created with a stub returning -1.
- Tactical parameters appended last, in this order: `OM_TP_SLOPE_UP_DIV`, `OM_TP_SLOPE_DOWN_MULT`, `OM_TP_SIGHT_EYE_HEIGHT`, `OM_TP_GROUND_FLYER_SEEN_MULT`; `pp_contract.md` rows; `conftest.py` members; the parameter-count tests re-pinned with a ledger row.
- Era pack field: `assets/eras/settled_reach/manifest.json` and `test_era` gain `"kind": "space"`, `greek_placeholder` gains `"kind": "ground"`; `autoload/era_config.gd` reads it into a constant (client side only in stage 2); `docs/architecture.md` documents the field where the manifest is described.
- Checks as stage 1: build with `-Werror`; `sig_table --check`; lints; csim failing ids equal to main's apart from the count tests; transport; net; the two traces; plus the hash check of the section below.

## Hash and save honesty

- The lockstep section hashes (move, fog, units) change layout: the move section hashes the parameter count (`tactical_move.c` ~3250), so appending four parameters changes every move-section value; the fog section gains the era-kind word; the move section gains the kind array (hashed beside reach). These are not recorded anywhere: `tests/net` compares worlds with each other, never against stored values. No test stores a section value.
- Recorded hashes that must not move: the strategic hashes (A99, F1 to F3, G3, scale) and the skill-lab goldens (just re-recorded today). None reads a tactical section hash or the parameter count (the stage-1 and stranding landings appended a parameter and a terrain section with no golden moving: evidence that holds). The contract agent re-runs those tests and stops if any moves.
- Save: the fog slot gains the era-kind word and the move slot the kind array. The save format number stays 6 through stage 2; the ledger says so; saves written before stage 2 are not loadable; a bump to 7 lands with stage 3 (the pipe frame), once per substrate.
