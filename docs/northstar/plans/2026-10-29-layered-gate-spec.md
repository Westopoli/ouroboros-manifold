## 2. The method: four layers

Each layer runs only when the one above it passes, and each is about one order of magnitude longer than the one above. A landing is pushed after layer 2. Layers 3 and 4 run on main, off `gate.lock`, and never block a push.

**Layer 0, pre-gate on the builder's worktree (exists, about one minute).** `scripts/specfactory/pre_gate.sh`: noise, `merge_gate.sh --revert` (base, make, every lint, footprint, owner rows), the piece's own tests, rule pins, provenance. Unchanged by this spec.

**Layer 1, fingerprint and flag (new, under the lock, about one minute).** The "something is wrong, not what" layer. Every `pieces.toml` row gets a key `impact`, one of `harness`, `client`, `sim`, `contract`; the Architect sets it in the spec paragraph, the records clerk copies it; a row without the key is `sim`, the strict case. After the gate's `make` stage, the new stage `flag` runs `checksum_trace.py` (seed 1, 60 regions, 500 ticks, features 6: the numbers of today's stage 10) and `tactical_trace.py` (seed 1, 1500 ticks: today's stage 10b) once each on the candidate's freshly built library and compares both traces with the base sha's traces from a new cache `<merge_root>/trace_cache/<sha>.{strategic,tactical}.txt` (the candidate's traces are written there under its own sha, so the next landing's base is cached when main is that sha; a base sha with no cache entry is built once in a throwaway worktree, as `regression_check` does for a baseline, about one minute, never twice). The verdict by flag: `harness` or `client` with a trace that differs is REJECT ("sim moved under a non-sim flag": a wrong flag or an unintended sim change, either way dig); `sim` with a trace that differs is OK and the stage prints the differing tick as evidence; `contract` may differ and REJECTs when no pin file is in the diff (`csrc/ouroboros_sim.h`, `docs/northstar/spec_factory/signatures.toml`, `csrc/om_internal.h`, `csrc/pipe/pipe_internal.h`: "contract flag without a contract change"). The flag also tightens the footprint: `harness` requires an empty diff under `csrc/`, `autoload/`, `scenes/` and `project.godot`; `client` an empty diff under `csrc/`. The piece's acceptance tests and every file under `tests/` the diff touches run in this layer as today's `acceptance` and `acceptance_godot` stages.

**Layer 2, selected suites (per landing, DRAFT-fast-gate-target 600 s).** HARNESS-gate-tiers' fast tier, with two fixes and the flag choosing the suites when `--tier` is not given. `harness`: the specfactory suite only (`tests/specfactory`; not under xdist, see section 8 F12). `client`: transport when the diff touches `csrc/pipe/` or `autoload/`, playthrough on today's trigger (`playthrough_trigger`, `merge_gate_support.py:1019`), and the lane plays the diff touches. `sim` and `contract`: `select-csim` as the tiers paragraph specifies (changed `csrc/*.c` mapped to symbols through `_symbol_module_map`, `merge_gate_support.py:309-320`, then the `tests/csim/test_*.py` files naming those symbols; a changed header, `Makefile` or `tests/csim/conftest.py` selects the whole suite), under xdist (HARNESS-csim-xdist), plus transport, plus regression_lab only when the diff touches `csrc/` or `scripts/skilllab/` (today's rule, `regression_lab_check` :1005). Fix one, no double run: a suite's result is already stored per `(suite, input_hash)` in `<merge_root>/candidate_results/<sha>.json` by `_store_candidate_result` (:659) and copied to `baseline_cache/` by `seed-cache` after the push; `_find_cached_by_inputs` (:642) scans `baseline_cache/` only, so a records push between the gate and the seed loses the entry (the seed's own skip line, `seed_cache` :665): it now scans `candidate_results/` too, and the baseline is computed in the gate only when neither folder has the base's input hash. Fix two, honest inputs: `suite_inputs.toml` declares the files a suite opens under `docs/northstar`, `scripts/specfactory`, `scripts/skilllab` and `simulation/` by file, never by directory (piece HARNESS-suite-inputs-trim). Pass: push to main; the gate row records the tier and the stage seconds as today.

**Layer 3, the sweep on main (full suite, off the lock, never blocks a push).** The tiers paragraph's slow tier: `merge_gate.sh --tier slow` on a worktree at `origin/main` against the main sha of the last PASS row of `docs/northstar/plans/push/sweeps.md`, run by a sweep clerk when any of these comes first: DRAFT-slow-tier-batch (3) landings, DRAFT-slow-tier-hours (2 h), or the nightly timer `om-sweep.timer` at DRAFT-sweep-nightly (23:30 local). Under xdist the full csim suite is estimated at under 10 minutes (HARNESS-csim-xdist's estimate at DRAFT-xdist-workers 5; DRAFT-sweep-workers 3 while gate.lock is held) and the whole sweep at about 30 minutes; nobody waits for it. The sweep row (date-time UTC, main sha, PASS or REJECT, red ids) goes to `sweeps.md` under `records.lock`; `status_check.py` prints `STATUS sweep WARN` when the sweep is overdue and `DRIFT` at DRAFT-slow-tier-drift-mult (2) times the limit, as the tiers paragraph specifies.

**Layer 4, bisect (only on a red sweep, minutes).** A red sweep names the failing test ids. The bisect clerk runs, per id, `git bisect start origin/main <last green sweep sha> --first-parent` then `git bisect run <venv python> -m pytest <id> -q -x -p no:cacheprovider` (git 2.53 on the box; `--first-parent` needs 2.29). One failing test runs in seconds, so log2(landings since the last green sweep) steps finish in under five minutes even when the sweep is a day late. The culprit landing is reverted (`git revert -m 1` for a merge commit, plain `git revert` otherwise), checked with `merge_gate.sh --revert`, pushed under `gate.lock`; a FINDING row names the landing and the test; the piece returns to its lane with its flag re-examined (a wrong flag is the likeliest cause and is itself a ledger row). The same procedure pays the standing debt: the first sweep lists the 142 red csim tests; each gets one of three rulings from the Architect (a test-defect fix with a TD row; an xfail with a ledger row, carried by HARNESS-known-xfail; or a FINDING row naming the landing that broke it, found by `git bisect run` against the last green sha of September). Main is green when a `sweeps.md` row says PASS with `red: 0` (section 8 B2), and from then on green means green.

What this removes per landing: 50 to 110 minutes of suites that cannot fail for the flagged change; the double run; pin churn as a reject (a `contract` piece re-records its pins in the build, under layer 0); the over-declared inputs. What it keeps: fenced tests, the determinism trace (now first, not last), the playthrough for client changes, one owner per file, the known-red lists, the gate row, the status check. Nothing a landed piece could break goes unchecked for longer than one sweep window, and a sweep red is found by bisect, not by a human reading logs.

- DEC-layered-gate-window-2026-10-29: main may carry an unnoticed regression for at most DRAFT-slow-tier-batch (3) landings or DRAFT-slow-tier-hours (2 h), or overnight until the nightly sweep, instead of zero at the price of 60 to 70 minutes per landing.
