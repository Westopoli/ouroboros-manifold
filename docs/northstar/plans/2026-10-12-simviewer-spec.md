Westley's ask 2026-10-12; the approved plan is `2026-10-12-simviewer-plan.md`. **Where this spec and that plan disagree, this spec wins.** Tooling only: never enters the game loop.

## Pre-flight corrections (each read from code on origin/main 3125ee77)

1. **Framing is binary, not JSON lines.** Every frame, both ways, is a 4-byte big-endian length then the JSON body (`tests/transport/test_pipe_debrief_region_delta.py` `_frame` / `_run`). The first frame the server writes is `hello`. `PipeSession` reads exactly that.
2. **`set_seed` answers no frame on success** (architecture.md:256); only `error` on failure. `step n` answers n `delta` frames then one `ack` (`{"type":"ack","name":"step","tick":N}`, om_pipe.c:1120, verified on the dbg pipe); `send` returns all of them, ack last; `snapshot` answers one `snapshot`; `mission_start` one `mission`; `objective_complete` one `ack`; `mission_end` and `mission_refuse` a `debrief` then a `snapshot`; `jump` a `chronicle` then a `snapshot`; `save` / `load` per architecture.md session commands. `error` ends any read. The terminal table is a module constant `TERMINAL` in `pipe_session.py`, filled from architecture.md by the builder and pinned by the test.
3. **`objective_complete` exists only in the debug pipe** (`#ifdef OM_DEBUG_INJECT`, `csrc/pipe/om_pipe.c:1731`). The viewer launches `pipe/ouroboros_pipe_dbg` (`make pipe/ouroboros_pipe_dbg`), the same binary the transport tests use.
4. **Client constants:** `DEFAULT_FEATURES = [0,1,2,3,4,5,6,7]` (`autoload/c_bridge.gd:27`); the client's jump is `{"name":"jump","ticks":50}` (`autoload/c_bridge.gd:749`). Both pinned as constants with that citation.
5. **"Pick an outcome" needs a core hook, not a pipe edit.** `om_mission_end` (`csrc/mission.c:1514`) computes retention inside one call and applies the band's consequences in the same call, so the pipe cannot substitute a value afterwards. Westley's idea (a hard-coded value in place of the computed one) is exactly the fix, and the hook is that substitution: a setter `void om_mission_set_retention_override(om_world *w, double r)` stores a transient value in the mission state (an `int` flag plus a `double`, zero by default, not saved, not hashed, cleared by `om_mission_end` after use); `om_mission_end` uses it in place of `om_mission_end_retention`. `mission_end` gains optional `"retention"` (0..1): present and in range calls the setter before `om_mission_end`; out of range or not a number answers `error` reason `bad retention` and changes nothing; in the release pipe a present field answers `error` reason `debug build required`. Without the field behaviour and bytes are unchanged.
6. **Owner conflict:** SV-0 touches `csrc/mission.c`, `csrc/ouroboros_sim.h`, `csrc/pipe/om_pipe.c`, `docs/architecture.md`, `docs/northstar/spec_factory/signatures.toml`; `VG-CONTRACT-E7` and `VG-W2` (queued) own mission.c, the header, architecture.md and signatures.toml. SV-0 queues behind both (`depends_on`), takes no file while they are in flight, and is audited by a second Fable chat. **SV-1 to SV-3 are new files only and run now.**
7. **Until SV-0 lands** the viewer still sends `retention`; the old pipe ignores the unknown field, so the "total failure" pick shows a red mismatch (a known gap, one line in the README), not a crash. The viewer pins the R-077-02 threshold table with its citation and the pick-versus-band mismatch is the tool's finding signal.

## Shared interfaces (frozen; test writers and builders both use exactly these)

`scripts/simviewer/pipe_session.py`
- `PIPE_DBG: Path` (repo root `/pipe/ouroboros_pipe_dbg`), `DEFAULT_FEATURES: list[int]`, `JUMP_TICKS: int = 50`, `TERMINAL: dict[str, ...]` (verb to the frame types it answers, in order; `step` handled by count).
- `class PipeSession`: `__init__(self, argv: list[str] | None = None)` spawns `argv` or `[str(PIPE_DBG)]` with `Popen(stdin=PIPE, stdout=PIPE)`, reads and stores `self.hello: dict`; `send(self, name: str, **fields) -> list[dict]` writes one `{"type":"cmd","name":name,**fields}` frame and returns the frames up to the verb's terminal frame (step: `n` deltas then the ack, default `n=1`); raises `PipeError(frame)` when an `error` frame arrives; `close(self)` sends `quit`, waits 5 s, kills on timeout; context manager.
- `class PipeError(Exception)`; `.frame: dict`.

`scripts/simviewer/history.py`
- `LAYOUT_ITERATIONS = 200`, `LAYOUT_SEED = 1`, `RING = 60`.
- `class History`: `__init__(self)`; `apply(self, frame: dict) -> None` folds a `snapshot`, `delta`, `mission`, `debrief` or `chronicle` frame (others ignored); `tick: int`; `regions: dict[int, dict]` (`owner`, `tier`, `military`, `economy`, `tension`, `population`, `stability`, `capacity`); `edges: list[tuple[int,int]]` from the snapshot; `factions: dict[int, dict]`; `ring(region: int, field: str) -> list[float]` (last `RING` values, oldest first, one per applied tick that listed the region); `events(region: int) -> list[dict]` (`tick`, `template`, `chain`, `delta`); `missions: list[dict]` (`tick`, `region`, `archetype`, `band`, `region_delta`); `layout(self) -> dict[int, tuple[float, float]]` (seeded force layout over `edges`, fixed iterations, rounded to 3 decimals, identical bytes over two runs on the same edges); `diff(before: dict, after: dict) -> list[int]` static: regions whose owner or any of the six values differ.

`scripts/simviewer/viewer.py` (SV-3): `class ViewerState` (pure state the draw reads: `mode` "tick"|"mission", `rate` from `RATES = (1,2,5,10,20,50)`, `paused`, `pick` 0..4 or `None`, `selected_region`, `pulse: dict[int,float]`, `last_debrief`) and `def draw(state, history, surface)`; the headless test imports these; `python -m scripts.simviewer` is `__main__.py`.

## SV-3 interfaces (frozen; added 2026-10-12 after SV-1 and SV-2 landed on their branches)

`scripts/simviewer/viewer.py` (pygame, `SDL_VIDEODRIVER=dummy` in tests; import pygame inside functions that need a display so `ViewerState` imports without a display)
- `RATES = (1, 2, 5, 10, 20, 50)` (ticks per second); `BANDS = ("total failure", "partial failure", "partial success", "strong success", "total success")`.
- `BAND_THRESHOLDS: dict[int, tuple[float, float, float, float]]`: `om_mission_archetype` id to the four R-077-02 thresholds (t1..t4), read from `csrc/mission.c` `om_mission_classify_band` and the `OM_MISSION_BAND_THRESHOLDS_*` constants it uses (value and citation in the module docstring; every archetype id the sim can draw has a row, unlisted ids use the STANDARD row exactly as the C `default` does).
- `pick_to_inputs(archetype: int, band: int) -> tuple[float, float]`: returns `(completion, retention)` for a band 0..4. Let the band's interval be `[lo, hi)` with `lo = 0` for band 0 and `hi = 1` for band 4 (else adjacent thresholds); `m = (lo + hi) / 2` is the target final score. If `m >= 0.25`: retention 1.0, completion `(m - 0.25) / 0.75`; else retention 0.0, completion `m / 0.75`. (final = 0.75 x completion + 0.25 x retention, R-077-01.) The returned pair always classifies back to `band` through `BAND_THRESHOLDS`.
- `class ViewerState`: `__init__(self, history, session=None)`; attributes `mode` ("tick" | "mission"), `rate` (a member of RATES, default 5), `paused` (default True), `pick` (None, 0..4, or 5 = refuse), `phase` ("idle" | "started" | "debriefed"), `selected_region` (None or int), `pulse: dict[int, float]` (region to seconds left, 2.0 when set), `last_debrief` (dict or None), `mismatch` (bool: last debrief band != pick), `status` (str). Methods: `toggle_mode()`, `rate_up()`, `rate_down()` (clamped to the ladder ends), `toggle_pause()`, `set_pick(n)`, `select(region)`, `update(dt: float)` (tick mode, unpaused: accumulates dt and calls `advance()` once per `1/rate` seconds; decays `pulse`), `advance()`, `handle_key(key: int)` (pygame key constants: SPACE pause, LEFTBRACKET/RIGHTBRACKET rate, RIGHT one tick, m mode, 0 to 5 as in the plan: keys 1-5 -> pick 0-4, 0 -> pick 5, RETURN -> advance in mission mode, f faction sidebar toggle).
- `advance()`: tick mode: `session.send("step", n=1)`, every returned frame to `history.apply`. Mission mode, phase "idle": `session.send("mission_start", faction=<player faction from the history's snapshot, 0 if unknown>, era_kind=0)`, apply frames, `selected_region` = the mission's region, pulse it, phase "started". Phase "started": no-op with `status` "pick an outcome" while `pick` is None; `pick == 5`: `mission_refuse`; else look up the mission archetype, `pick_to_inputs`, `objective_complete` for every objective index 0..(n_objectives-1) with the completion (n_objectives from the mission frame; at least objective 0), then `mission_end` with `retention=<retention>`; apply frames, set `last_debrief`, `mismatch`, pulse every region `History.diff` reports between the snapshot before and after, phase "debriefed". Phase "debriefed": `session.send("jump", ticks=JUMP_TICKS)`, apply, phase "idle", pick back to None.
- `inventory(state, history) -> dict`: pure, display-free element inventory for tests and QA, keys `mode`, `rate`, `paused`, `phase`, `pick`, `mismatch`, `regions_drawn` (count), `factions_listed` (count), `selected_region`, `mission_rows` (len of `history.missions`), `pulsing` (sorted region ids).
- `draw(state, history, surface)`: ports the old viewer's drawing (hulls, edges, nodes in the owner colour from a fixed palette keyed by faction id, radar arms, sidebars, event log, controls strip); never raises on an empty History.
- `main(argv: list[str] | None = None) -> int` in `__main__.py` calls `viewer.run(args)`; args `--seed` (default 1), `--n-regions` (default 80), `--rate`, `--mode`, `--features` (default DEFAULT_FEATURES), `--shot DIR` (headless: runs a scripted tick-mode run of 30 ticks then one full mission-mode cycle at pick 3 on the dbg pipe, saves `tick_mode.png` and `mission_mode.png` to DIR, exits 0).
- Until SV-0 lands the pipe ignores `retention`; pick 0 then mismatches (red). The real-pipe test for pick 0 is `xfail(strict=False, reason="SV-0 retention override not landed")`.
