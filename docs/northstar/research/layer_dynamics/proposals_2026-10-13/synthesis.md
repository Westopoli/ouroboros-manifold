# Synthesis: three proposals for covering the lab's two blind spots (2026-10-13)

Written by the Architect chat for Westley. Three Fable 5.1 research agents received one identical read-only brief (the lab's goal and Westley's words, the 2026-10-13 rulings, the two blind spots in the "able to fire" count, the recorded trap, the seven gaps from the same day's audit, and a reading list), with the same repository access, and reported once each: `agent_one.md`, `agent_two.md`, `agent_three.md`, verbatim. Each built the C library in scratch and ran probe fights; none edited the repository.

## Where all three converge

1. **The count.** Rebuild "able to fire" from the engine's own four gates, composed in Python from public queries: the target is seen by the side (`om_player_can_see`, which includes ping reveals; not the per-unit `seen_by_sight`), the layer offset is inside the attacker type's reach, the distance is within attack range times the offset's range multiplier (`OM_TP_RANGE_UP_n` or `DOWN_n`), and the line of fire is clear (`om_combat_can_shoot`). A unit in transition needs no special case: the engine's layer getter already returns the effective layer of R-004-02. All three measured this count against the engine's own target set and found agreement within about one percent, while today's count reads zero through a 16-to-0 cross-layer wipe.
2. **One engine query later.** All three want the same test exposed by the engine as one contract call (`om_combat_can_engage` with a reason code), landing with the firing-arc piece, so the Python composition is replaced by the engine's truth once the arc exists. Until then the lab asserts parity between the composed count and the engine-target count on every fight.
3. **The type weight.** Retire the damage-rate weight. Weight each able unit by the category multiplier of its category against its target's category (R-081-01, read from `OM_TP_CATMULT_*` so a matchup sweep moves it), nothing else: no damage, interval, health or cross-layer damage multiplier. Both predictions share the one eligibility. The four readings of the approved design follow: both right; count wrong and type right (the triangle decided it); both wrong (a number overrode position); count right and type wrong (the weighting is wrong).
4. **The opening window.** The whole-fight firing total leans toward the winner by construction. All three want an opening window after first contact as the primary prediction and the whole-fight total kept as a chart. The toy used 40 ticks.
5. **The emitting pair is inert at the bible's base.** Cross-layer sight is capped at factor 1.0 after the multiplier (`fog.c`), so at the base 0.5 both 2.0 and 3.0 saturate and the ruled starting pair cannot be told apart. Emitting must be swept jointly with vision at a low base (0.125 to 0.25), where seen-from and sight separate.
6. **Vision band.** 0.125, 0.25, 0.5, 1.0 at one layer (the engine refuses values above 1.0, so the band's top is 1.0, written in the batch spec); two layers at the bible's 0.4 ratio. The crossing for a Raider-up play was measured by one agent between 0.125 and 0.25 (the Raider sees 800 times the factor, fires at 200).
7. **Scenes.** Same roster mix on both sides; the skilled side differs only in where its reach-capable types stand. A layered open-ground scene (reach-1 types one layer up against the identical mix flat) as the primary knob scene; the corrected S3 play (Interceptors above, Vanguards on the enemy layer; the Vanguard-with-reach variant is retired, R-164-01); an over-the-choke play on a layout whose wall top is below the attacker's layer; a silent-versus-emitting play; a ping-then-commit play; the ground lab's first scene as hold-the-slope-top with eye height, slope divisor and the flyer seen-multiplier as its knobs.
8. **Controls.** Vision factor 0 must give 16 versus 16 with no shot; the damage-up knob must change the result while leaving the count unchanged (the planted "number that is off"); reach (0, 0) on both sides must be byte-identical across every vision point; the Bombard-and-spotter case (0 able without a spotter, able with one) joins the hand-built cases.
9. **Where the text goes.** Harness spec clause 10 rewritten and clause 24 extended; README section 4 (measure), 7 (the stale gap table) and 8 (plan); a new batch spec beside the layout search spec; register rows Q-008-03 and Q-008-07; the superseded tests listed with the ruling that retires each.

## Where they diverge, or only one found it

- **Contact is not guaranteed by the order alone.** Agent two found, with two probes and the rule text, that an attack-move group ends once every member has engaged and nobody resumes the march (E-13 R-096-02 as built), so two remnants can stand 316 wu apart with no target for ever: a tie with no lab bug, which the elimination ruling does not allow. Agent one found a second stall: at cross-layer sight below weapon range, units halt at their attack-range slot and never close the last stretch. Agent three did not probe contact. Both findings rest on probes and are the strongest new evidence in the three reports.
- **Multipliers above 1.0 for firing up.** Agent one includes 2.0 as a sign-flip control; agent two sweeps penalties only (1.0 down to 0.25); agent three uses 0.5 to 1.5 for range and 0.25 to 1.0 for damage. Westley's words name a penalty.
- **C2 computation.** Agent three found that the existing C2 pools fights across every enemy headcount, so its rank agreement is driven by headcount itself; it proposes per-headcount cells. The others keep the pooled form beside the window. Code-based, not probed.
- **Ground fire across bands.** Agent three found the engine applies reach by type in every era while E-01 S-164 says space only, so a walker one band below can never fire up a slope under the default reach; nothing rules it. Open question for Westley.
- **Asymmetric vision set by a play.** Agent three found `plays_space.py` sets the down factor to 1.0 while up stays 0.5 inside the S3 play, against R-005-05 and the same-values ruling.
- **Area damage today.** Agent two found the disc area attack is already sweepable on any type through the lab's custom-unit registration, so a disc radius sweep needs no engine change; the cone does.
- **Already known.** Agent one found the 2026-10-04 audit recorded "the firing count is binary, same-layer only and unweighted" nine days before the 2026-10-13 audit, with no ledger row or spec change after it.
- **Acquisition radius.** Agent three found the engine's cross-layer acquisition scans only inside weapon range times the widest multiplier, never the sensor radius, so a seen enemy two layers up is engaged only once inside weapon range.

## Evidence ranking

Strongest (probed, two or three agents agree): the composed count reads the knobs and matches the engine; the vision cap makes the emitting pair inert at base 0.5; the R-096-02 tie and the low-vision stall; the damage knob moving the result and not the count. Strong (quoted lines, three agree): the type weight, the stale harness clause, the stale README gap table, the forbidden Vanguard reach. Medium (one agent, code-read): per-cell C2, the acquisition radius, the ground reach question. Weakest (all three say so): the ground scenes, which no lab fight has ever run, and every band value, which is a draft.

## The Architect's pick

Adopt the convergent design as written in point 1 to 9 above, with the agent-two contact finding folded into the batch spec as a pre-flight rule, and these choices on the divergences: penalties only in the coarse grid with a single 2.0 point as a labelled sign-flip control; C2 reported per headcount cell and pooled, both; the opening window at 40 ticks as a named draft; the ground batch after the space batch and only after Westley rules on fire across bands. Everything numeric stays a named draft until the first chart.
