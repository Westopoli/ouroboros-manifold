# HUD mockup — camera, selection, control groups, lean HUD (P8)

## Design as built

`scenes/mockups/hud/hud_mockup.tscn` is a fixed top-down camera mockup over a flat 6,000×6,000 wu canvas with 24 toy units (16 friendly, 8 enemy) wandering a seeded 4-waypoint loop on two layers (y=0 and y=400, the second drawn as a large translucent plane so the second layer reads as "up"). Selection logic (`selection.gd`) is a pure `RefCounted` class over unit records with no node dependencies: click, shift-click, box (spans both layers), narrow-by-layer, exclusive-membership bind, recall with 0.4s double-tap centring, and a `commands()` list that is checked to contain no select-all/select-all-army/select-all-of-type name (R-105-04). Toy units (`toy_units.gd`) are also pure and deterministic: same seed, same tick count, byte-identical state hash, verified by running 300 ticks twice and comparing.

The camera (`camera_rig.gd`) copies the legacy constants named in the brief — 1500 wu/s pan, 300/notch wheel zoom, height 150–12,000 wu — clamped so the *visible ground rectangle* (computed from height, vertical fov and aspect, `get_ground_half_extent()`) stays inside the 6,000×6,000 canvas, not just the camera's centre point; when the view is wider than the canvas (height 12,000 with a 55° fov and 16:9 aspect always shows more than 6,000 wu across) the camera centres itself instead of lurching toward one edge. Pitch fixed at 90°, never bound to the layer strip. `input_router.gd` is a plain `Node` doing `_unhandled_input`: left click picks the nearest friendly within 30px, shift toggles, a drag under 6px collapses to a click, digits 1-9 recall/Ctrl-digit binds, Q/E narrow to layer 1/2, Tab flips the focus slot, right click issues a straight-line toy move. It delegates to the root's `qa_*` methods wherever one exists, so the driver's scripted `call` verbs and real interactive input share one code path.

The HUD (`hud.gd`, a `CanvasLayer`) is deliberately lean: one objective line top-left (text-embedded block-bar plus a real 320×6 `ColorRect` fill, driven by a fixture's progress curve interpolated by tick — `fixtures/mission_seed11.json`), the mission clock top-right (`tick / 20` seconds, never wall-clock), the selection panel bottom-centre (count, one row per a cosmetic "type" grouping — see the open question below — with count/summed-HP/per-unit layer-colour dots), nine group tabs beneath it (count when bound, highlighted when last recalled), a two-slot layer strip on the right edge with a "Q/E narrow" hint, and a full-rect `BoxOverlay` Control (`mouse_filter = IGNORE`) that draws the drag rectangle. Every `Control`'s `focus_mode` is forced to `FOCUS_NONE`.

All 6 fault sites (`box-one-layer`, `group-shared`, `select-all-exists`, `camera-unbounded`, `clock-wallclock`, `narrow-moves-focus`) are confirmed live both headlessly (`scripts/mockup_verify.sh hud --plant <id>`, each isolates to exactly its named check) and, where the fault has a visual signature, under Xvfb.

Three real bugs were found and fixed across the original pass and this fix pass, not by construction:

1. **`verify.gd` itself** had the same defect twice (original pass): Godot's `%` string-format operator spreads an `Array` right-hand operand as separate positional arguments rather than substituting it as one `%s` value, so `"...%s..." % an_array_of_3` throws "not all arguments converted", which silently aborts the rest of that check function (no crash, no `FAIL:` line, no `_failures` increment) and can produce a false `VERIFY OK`. Caught this because `_check_box2`'s assert message crashed exactly that way; audited every remaining `%`-format call in the file and fixed the one other unguarded case.
2. **`hud.gd`'s `BoxOverlay`** never cleared the drag rectangle after the drag ended (original pass): it only called `queue_redraw()` while `box_active` was true, so the last mid-drag `_draw()` call's rectangle stayed rendered forever once the drag finished (nothing ever told the `CanvasItem` to redraw the now-empty state). Found by reading a real Xvfb screenshot (`boxed.png`) taken *after* a completed drag and seeing the rectangle still there. Fixed with an edge-triggered final redraw on the `true→false` transition frame.
3. **`hud_mockup.gd`'s `qa_camera()`** called `centre_on()` before `set_height()` (fix pass): once the camera clamp became height-dependent, a height change could get silently swallowed — `centre_on()` clamped against the *old* height, then `set_height()`'s reclamp was a no-op whenever the new height's range happened to already contain the stale value. Found by temporarily making `_assert` print every message (not just failures), running the headless verify, and hand-checking the `BOUND-8` numbers at height 150 against the clamp math — it printed the height-3000 answer instead. Fixed by setting height before centring; reverted the debug print before committing.

Two upstream harness bugs were found and fixed on `main` by the design chat during this pass (not authored by this implementor, merged in via `git merge`): an Xvfb screensaver blanking the display after 600s of no real X11 input (`a98c47f`), and the actual root cause of every long-run stall — `qa_boot.gd` left the project's 19 autoloads running under `--script` boot, so `SimBridge`'s child Python sim died immediately in a worktree, `SceneRouter` routed to the error screen, its 0.3s fade-to-black is what the progressively-darkening screenshots were, and the scene swap that followed freed the mockup root out from under the driver, which is why the very next `screenshot` verb hung forever waiting on a `frame_post_draw` that would never come (`b65afa8`, `qa_boot.gd` now frees every autoload before instantiating the mockup).

## Questions for Westley

Every one of these was built as the simplest thing that shows the question, per the brief; none was decided silently.

1. **Layer strip look.** Built: plain "L1"/"L2" text labels, dim when unfocused, cyan when focused, "Q/E narrow" hint beneath. Candidates: (a) current, (b) a filled pill/button background per slot for stronger at-a-glance focus, (c) a small colored icon/hex per layer instead of text.
2. **Minimap in Round 1 or not.** The brief's S-P12 scope explicitly excludes it (E-16's full S-104 layout has one; this prototype doesn't). Candidates: (a) omit for the whole Round-1 build as scoped, (b) add a placeholder panel bottom-left now at prototype fidelity so testers see the IGoP-register shape sooner, (c) leave it fully deferred to when S-104 itself is built.
3. **Double-tap centring window.** Built and verified exactly at 400ms (`CENTRE-5`: 300ms apart triggers, 700ms apart does not). Candidates: (a) current 400ms, (b) 300ms (tighter, common RTS default), (c) 500ms (more forgiving).
4. **Selection ring look.** Built: a flat cyan disc beneath the unit, same colour regardless of faction (only friendlies are ever selectable, so faction-coding it would be redundant). Candidates: (a) current filled disc, (b) an outline-only ring for less visual clutter over dense clumps, (c) a subtle pulse/animation to read better at a glance.
5. **Should narrowing be a toggle?** Built: `narrow(layer)` is one-directional — pressing Q or E again re-narrows (a no-op if already on that layer) but there's no way back to the full multi-layer selection except reselecting. Candidates: (a) current, (b) pressing the already-active layer's key again restores the pre-narrow multi-layer selection, (c) narrow becomes "sticky" and reapplies automatically to future selections until a fresh click/box clears it.
6. **What counts as a "unit type" for the selection panel's rows.** The contract's `units` dict (and the toy sim itself) has no real type field — only faction/layer/pos/hp. I derived a cosmetic `TYPE_NAMES[uid % 2]` ("scout"/"line") purely so the panel has something to group by, matching the brief's "row per unit type present" wording without adding an undocumented field to the tested contract. Candidates: (a) current cosmetic split, (b) group by faction instead (trivial today since only friendlies are ever selected, so this would collapse to one row), (c) drop the per-type grouping for this mockup and just show total count + summed HP.
7. **Two Xvfb oracle candidates from the brief didn't discriminate their fault as specified** (see `qa/checklist.md`'s "Why TAB-X and EDGE-X were revised" for the full evidence): TAB-X's smoke-script sequence only ever binds once, so `group-shared` has nothing to leak from at that point (GROUP-4, headless, is the real live oracle); EDGE-X's within-run `east_a` vs `east_b` diff is dominated by ordinary unit wander and the clock ticking rather than camera drift (0.003 measured, not under the candidate's 0.001). Recommend comparing `east_a` across runs (clean vs. planted) instead, where the difference is decisive: 0.999 (nearly the whole frame) now that the camera clamp keeps the clean run's view fully on-canvas, versus near-zero before the clamp fix.
8. **BOUND-8 at height 12,000 cannot literally have every ground corner inside the canvas.** At fov 55° and 16:9 aspect, the visible ground rectangle at height 12,000 is roughly 22,200×12,500 wu — wider than the 6,000×6,000 canvas in both axes — so no camera position shows zero void at that height; the check instead asserts the camera centres itself (the least-bad, symmetric option) rather than drifting toward one edge. Candidates: (a) current — accept that max zoom-out shows void symmetrically around a centred camera, this is normal for a finite map at max zoom in most RTS games, (b) lower `HEIGHT_MAX` (roughly 3,240 wu is the largest height that still fits the 16:9 view inside 6,000 wu) so max zoom-out always fully covers the canvas, (c) grow `CANVAS_SIZE` so the map stays bigger than the view at every height in the current 150–12,000 range.

## Running it

`~/.local/bin/godot --scene scenes/mockups/hud/hud_mockup.tscn` from the repo root. WASD pans, mouse wheel zooms, edge-scroll pans near the window border. Left click selects the nearest friendly within 30px; Shift+click toggles; left-drag box-selects across both layers. Digits 1-9 recall a group; Ctrl+digit (or Cmd on macOS) binds the current selection to that digit, exclusive of any other group; pressing the same digit again within 0.4s centres the camera on the group. Q narrows the selection to layer 1, E to layer 2; Tab flips which layer slot is focused. Right click issues a straight-line move for the selection. The `QADriver` child is inert on this launch — it only activates when `--qa-script` is passed on the command line, which the interactive `--scene` launch never does, so nothing writes to `user://qa` and no autoloads are touched.
