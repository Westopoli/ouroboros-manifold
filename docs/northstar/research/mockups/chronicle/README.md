# Chronicle and time-jump mockup (P7)

Brief: `docs/northstar/plans/briefs/2026-09-22-p7-chronicle-mockup.md`. Scene: `scenes/mockups/chronicle/chronicle_mockup.tscn`. Interactive command: `~/.local/bin/godot --scene scenes/mockups/chronicle/chronicle_mockup.tscn` from the repo root.

Hotkeys: `S` skip, `Enter` proceed (enabled once the phase reaches `done`), `R` reset the current seed. Right-drag over the galaxy pans the auto-orbit. A wrapper run without `--qa-script` leaves `QADriver` inert (no `--qa-script` in the launch args means `_ready()` returns immediately without wiring the script; no `_run.json` is ever written).

## Design as built

The scene is a plain `Control` root (`chronicle_mockup.gd`) with no autoload dependency: `MapViewport` (a `SubViewportContainer` holding `MiniGalaxy`, a `Camera3D`, one `DirectionalLight3D`, and a `WorldEnvironment`), `Scroll` (the entry panel), `HUD` (a `CanvasLayer`), and `QADriver`.

`jump.gd` is a `RefCounted` that loads a fixture JSON (`fixtures/jump_seed11.json`, `fixtures/jump_seed12.json`), validates R-065 order (consequence first, a lineage entry present, no category over two, the rest in descending score), R-068-02 word limits, R-068-07 near-duplicate dropping (40% shared content words, relative to the shorter), and R-069-05 keyframe coverage (every entry's tick range contains a keyframe; every ownership change has one). All six fault sites live behind `QaPlants.is_active(...)` at the exact point the brief names: the drop-skip and duplicate-append in `_dedup`, the reversal in `load_dict`, `expanded_text_for` returning the base form, the wall-clock branch of `_printed_words_for` (on the scene root), the paused-still-advances branch of the tick gate, and the no-interpolation branch of the morph lerp in `mini_galaxy.gd`.

The clock is a plain integer tick counter, 20 ticks per second of real time, advanced by `_process` (fractional accumulator) in interactive play and synchronously by `qa_tick(n)` in tests — the same code path either way, so there is no dual implementation to drift apart. Printed-word count is `floor(5*(tick-start)/8)`, the exact integer form of "one word every 0.08s = 1.6 ticks"; per-word fade uses the same arithmetic to find each word's reveal tick and ramps its alpha over 4 ticks (0.20s). Nothing in the printing path reads the wall clock except the blinking cursor (deliberately: the harness's own `PAUSE-X` oracle already excludes the cursor's crop from its diff, so wall-clock cosmetic blinking was the one place left where it does not fight determinism).

Ownership is data, not animation: `owners` (in `qa_state()`) flips to the new owner at the exact keyframe tick, the same instant the game-logic border actually changes; only the rendered colour lags behind on a 40-tick (2.0s) lerp with a fading pulse ring, matching the E-16 60-second text's "border visibly morphs over two seconds" without ever letting the *visual* animation be load-bearing for anything a test asserts on.

The galaxy is `mini_galaxy.gd` alone: ~22 systems (8 tied to chronicle-entry regions, 14 filler) as `SphereMesh` instances, edges as one `ImmediateMesh` line set, a faint `MultiMeshInstance3D` starfield seeded from a fixed constant (not the jump seed — it is decoration, not simulated state), and a slow auto-orbit of the whole system root that a right-drag overrides.

The scroll is `scroll_panel.gd` + `entry_view.gd`. Rows are created lazily as the clock reaches each entry's `tick_range_start`; words render via BBCode with `[color]` (faction hue, or a light accent for region/character mentions) wrapped in `[url=kind:id]` for the mention spans the fixture already carries. Clicking a row that is not yet fully printed does nothing (checked by whether `printed_words >= total_words` at click time, not by a separate phase guard); clicking a printed row opens a full-rect expansion overlay and pauses the tick (and the morph lerp and the printing, since all three read the same tick).

Fragments for both fixtures were hand-written in the register of `simulation/library/chronicle/fragments.json`'s tone (read for reference), with invented names only: factions "The Ostrel Concord" / "The Kaine Dominion"; regions Halven Reach, Kestrel Hold, Moorwick, Pellast, Dray's Hollow, Undermere, Ashcombe, Thistlewake (seed 11) and Varlow, Ambervale, Greymoor, Saltmere, Farrow, Windle (seed 12); people such as Commander Rael Voss, Warden Coel Ashby, Magistrate Enna Thale. Seed 11 is 8 entries (consequence-success, one lineage, two regional-faction-shift covering the two regions that change hands, one famine chain, one expansion chain, two regional filler). Seed 12 is 6 entries (consequence-failure, one `lineage_quiet`, one chain stalemate, one region change, one decline, one stable) to also exercise the near-minimum end of the 5–10 range.

## Fixture shapes invented beyond the message contract

`docs/architecture.md`'s `chronicle_entry` and `time_jump_start` shapes do not carry `category`, `region`, or `score` — those exist only in the simulation's internal cluster objects, never crossing the pipe. The mockup's fixtures add all three directly to the entry object (and `keyframes` as a top-level array distinct from `ownership_timeline`, since not every keyframe is an ownership change) because the client-side mockup has no distiller to derive them from; this is flagged explicitly rather than guessed into architecture.md, since a fenced-path mockup brief cannot amend that doc. See "Questions for Westley" below.

## Questions for Westley

Every one of these is a place I built the simplest thing that shows the question rather than guessing; no decision was made.

- **Q-065-02 (setup entries, open in the epic already)**: the mockup ends both scrolls with no setup entry, matching the epic's own open flag. Not re-decided here.
- **The per-category cap of 2 (Q-065-01, open in the epic already)**: implemented as the epic's code behavior describes; not re-decided here.
- **The expansion animation**: I built it as an instant show/hide (no fade), full-rect over the scroll only (not the map). Candidates: (a) instant, scroll-only [built], (b) a short fade-in matching the 0.20s word-fade rhythm, (c) an overlay across the whole screen (map included), which is one reading of R-069-04's "overlays the scroll and the map" — I read that clause as "the map's animation pauses," not "the map is visually covered," since covering it would hide the very border-morph the expansion is meant to let you read *about*.
- **Should Skip also skip the morphs**: yes, built that way — `qa_set("skip", true)` jumps the tick straight to the fixture's final tick and calls `update_tick` once, so every system's colour goes straight to its final owner with no visible lerp. Candidate alternative: play the morphs at high speed instead of snapping, for a few hundred ms of "history rushing past" before landing on the ending.
- **The blinking cursor**: wall-clock driven (not tick-driven), the one place in the whole scene that reads real time. Candidates: (a) wall-clock blink [built, and the harness's own `PAUSE-X` oracle already special-cases this by excluding the cursor's crop from its diff, suggesting the harness's author anticipated this exact choice], (b) tick-driven blink for total purity, at the cost of the cursor visibly freezing whenever the clock is paused (which may actually read *better* — a frozen cursor is a clearer "everything stopped" signal than a cursor that keeps blinking through a pause).
- **`map_width_fraction` at "done"**: R-069-01 says the panel "slides out... and the map returns to full width" at the end of narration, but S-069's own text also says "at the last entry the panel stays; Proceed becomes enabled" — those read like they're describing two different moments. I made `map_width_fraction` (and the actual anchor) return to 1.0 (and the scroll become invisible) whenever `phase` reaches `"done"`, whether that's by finishing narration naturally or by Skip, since that's the only reading that makes `LAYOUT-10`'s literal contract ("0.62 at start, 1.0 at the end") true in one uniform rule. Candidates: (a) always revert to full width at `done` [built], (b) only revert on Skip, keep the panel showing at 0.62 after a *natural* finish until Proceed is actually pressed, (c) revert only after Proceed is pressed, a fifth observable moment the current phase enum doesn't have room for.
- **Fixture fields invented beyond the message contract**: `category`, `region`, `score` on each entry, and a top-level `keyframes` array (distinct from `ownership_timeline`, since most keyframes are narrative beats with no ownership change). None of these cross the real pipe today (`docs/architecture.md`'s `chronicle_entry`/`time_jump_start` don't carry them); the mockup needs them because it has no distiller to derive rank, region, or "was this tick meaningful" from. If a future story wires a real client-side distiller instead of hand-authored fixtures, these become either derived-client-side or added to the real message shape — that decision belongs to whoever writes that story, not this mockup.
- **`MORPH-X` and `SEED-X` pixel-oracle thresholds**: see the checklist's "Why two oracles were revised" section — both measured well below the brief's candidate numbers, for reasons that are about pixel-diff sensitivity (auto-orbit churn, a hidden scroll at the "done" screenshots), not about the underlying behaviour being wrong (both are independently proven correct via `MORPH-9`'s headless colour check and the galaxy's own layout data). Candidates are listed there.

## Report

**1. Pace and legibility.** 0.08s/word (~12 words/s) reads as writing-itself at `qa_tick`-driven speed in the screenshots, and the same cadence in real interactive play (not fast-forwarded) is brisk but comfortably readable — closer to "urgent report" than "leisurely history." I would not change it without seeing it in motion rather than in stills, but if it reads too fast in person, 0.10-0.12s/word (8-10 words/s) is the next candidate; both are trivial to change (`WORD_TICKS_NUM`/`WORD_TICKS_DEN` in `chronicle_mockup.gd`, one constant each).

**2. Does the map side need more than points and morphs?** For a mockup, points + edges + morph + starfield read clearly as "a galaxy where borders are changing" (see `pass1/before_morph.png` vs `after_morph.png`) and the reference's territory-shell glow is the one thing visibly missing — the reference's systems sit inside soft translucent faction-coloured blobs that overlap where two factions' territory touches; my systems are bare spheres. That glow is what makes the reference read as *territory* rather than *dots*; I'd rate it the single highest-value addition before this leaves mockup stage. Lanes-as-lit-threads are already present (the `ImmediateMesh` edges), just thinner and less luminous than the reference's gold glow.

**3. Fixture shapes.** The real message shapes (`chronicle_entry`, `time_jump_start`, `mentions[]`) were enough to build the printing/mention/expansion mechanics faithfully. Three fields had to be invented (`category`, `region`, `score` per entry) plus a `keyframes` array separate from `ownership_timeline` — see "Fixture fields invented" above. `mentions[]`'s `span_start`/`span_end` matched the architecture doc's shape exactly and needed no changes.

**4. Frame time under llvmpipe at 720p.** 33.7-106.8ms/frame (`_qa.fps_ms`) measured across one clean run, on a machine running 20-45 concurrent Godot mockup-QA processes for most of this session (other parallel briefs, not this mockup's own cost) — well inside the brief's "up to a second per frame" budget even under that contention. `--fixed-fps 30` keeps the simulation clock exact regardless of render time; two clean runs hash-matched and pixel-diffed to 0.000000 on every screenshot checked, so the contention affected wall-clock smoothness only, never state.

**5. Under-defined points.** All five (setup entries, per-category cap — both already open in the epic and not re-decided here — the expansion animation, whether Skip also skips morphs, the blinking cursor) plus the `map_width_fraction`-at-done reading and the two pixel-oracle thresholds are listed under "Questions for Westley" above, each with two or three candidates and no decision made.

### A real bug found and fixed along the way

`entry_view.gd` started as a plain `Control` wrapping a `VBoxContainer`+`RichTextLabel` with no anchors of its own; Godot's container layout never propagates a size into a plain `Control`'s children, so the label rendered at its natural near-zero width and the text collapsed to a one-character-wide sliver. Separately, `scroll_panel.gd`'s slide-in tween animated `position.x` from 60 to a hardcoded `0.0`, fighting the panel's own `anchor_left = 0.62` and pinning the whole scroll under the HUD at the left edge instead of the right 38%. Both are fixed (`EntryView` is now itself a `VBoxContainer`; the tween captures the anchor-derived rest position once, the same pattern the legacy `chronicle_scroll_panel.gd` uses). Screenshots in `pass1/` are from after both fixes.
