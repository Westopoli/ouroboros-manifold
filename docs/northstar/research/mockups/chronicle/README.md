# Chronicle and time-jump mockup (P7)

Brief: `docs/northstar/plans/briefs/2026-09-22-p7-chronicle-mockup.md`. Scene: `scenes/mockups/chronicle/chronicle_mockup.tscn`. Interactive command: `~/.local/bin/godot --scene scenes/mockups/chronicle/chronicle_mockup.tscn` from the repo root.

Hotkeys: `S` skip, `Enter` proceed (enabled once the phase reaches `done`), `R` reset the current seed. Right-drag over the galaxy pans the auto-orbit. A wrapper run without `--qa-script` leaves `QADriver` inert (no `--qa-script` in the launch args means `_ready()` returns immediately without wiring the script; no `_run.json` is ever written).

## Design as built

The scene is a plain `Control` root (`chronicle_mockup.gd`) with no autoload dependency: a `Background` `ColorRect` (near-black, `#0A0D12`, covers the whole window so nothing outside the SubViewport ever shows the engine's default grey clear colour), `MapViewport` (a `SubViewportContainer` holding `MiniGalaxy`, a `Camera3D`, one `DirectionalLight3D`, and a `WorldEnvironment` whose `Environment.background_mode` is `BG_COLOR`, not the `BG_SKY` it started as — `BG_SKY` with no `Sky` resource assigned silently falls back to the project's default clear colour, `(77,77,77)`, under the Compatibility renderer, which is why every early screenshot read as flat grey inside and outside the SubViewport alike), `Scroll` (the entry panel, itself given its own slightly-lighter dark panel background, `SURFACE` `#10141A`, so it reads as a distinct panel rather than more of the map's near-black), `HUD` (a `CanvasLayer`, its button/label stack now sitting inside an opaque `PanelContainer` backdrop so the polar grid or a star never renders behind the HUD text), and `QADriver`.

`jump.gd` is a `RefCounted` that loads a fixture JSON (`fixtures/jump_seed11.json`, `fixtures/jump_seed12.json`), validates R-065 order (consequence first, a lineage entry present, no category over two, the rest in descending score), R-068-02 word limits, R-068-07 near-duplicate dropping (40% shared content words, relative to the shorter), and R-069-05 keyframe coverage (every entry's tick range contains a keyframe; every ownership change has one). All six fault sites live behind `QaPlants.is_active(...)` at the exact point the brief names: the drop-skip and duplicate-append in `_dedup`, the reversal in `load_dict`, `expanded_text_for` returning the base form, the wall-clock branch of `_printed_words_for` (on the scene root), the paused-still-advances branch of the tick gate, and the no-interpolation branch of the morph lerp in `mini_galaxy.gd`.

The clock is a plain integer tick counter, 20 ticks per second of real time, advanced by `_process` (fractional accumulator) in interactive play and synchronously by `qa_tick(n)` in tests — the same code path either way, so there is no dual implementation to drift apart. Printed-word count is `floor(5*(tick-start)/8)`, the exact integer form of "one word every 0.08s = 1.6 ticks"; per-word fade uses the same arithmetic to find each word's reveal tick and ramps its alpha over 4 ticks (0.20s). Nothing in the printing path reads the wall clock except the blinking cursor (deliberately: the harness's own `PAUSE-X` oracle already excludes the cursor's crop from its diff, so wall-clock cosmetic blinking was the one place left where it does not fight determinism).

Ownership is data, not animation: `owners` (in `qa_state()`) flips to the new owner at the exact keyframe tick, the same instant the game-logic border actually changes; only the rendered colour lags behind on a 40-tick (2.0s) lerp, matching the E-16 60-second text's "border visibly morphs over two seconds" without ever letting the *visual* animation be load-bearing for anything a test asserts on. The pulse ring and a new sphere scale-up are a separate, longer-lived salience signal on top of that colour lerp: both decay over 80 ticks (4.0s), twice the colour lerp's window, so the morphed system is still visibly larger with a lit ring at the 2.0s mark where the colour itself has already finished settling — the first build let the ring fade out in lockstep with the colour, so by the time a screenshot could show the finished transition there was nothing left to draw the eye to which of ~20 systems had actually changed.

The galaxy is `mini_galaxy.gd` alone: 18-22 systems depending on seed (6-8 tied to chronicle-entry regions, the rest filler) as `SphereMesh` instances, edges as one `ImmediateMesh` line set, a `MultiMeshInstance3D` starfield of 900 quads (was 260; widened radius range and per-instance size variance for depth) seeded from a fixed constant (not the jump seed — it is decoration, not simulated state), a faint polar grid (four concentric rings plus twelve radial spokes, another static `ImmediateMesh` line set, rebuilt alongside the edges so it rotates with the galaxy's own orbit rather than staying a fixed backdrop), and a slow auto-orbit of the whole system root that a right-drag overrides. Territory shells (the reference's translucent glowing faction blobs) stay deferred — out of this pass's static-quads-only scope; still the single highest-value visual addition left, per the original report's Q2 answer. Seed 12's galaxy is deliberately reshaped from seed 11's: a 12-point flattened ellipse with a sinusoidal radius wobble instead of a near-circle at the same radius, one spoke per inner region instead of two of six, and a third faction colour (`f_dray`, green) rotated onto part of the outer ring — the first build gave both seeds the same system count, the same two faction hues, and near-identical ring geometry, so the two galaxies read as the same shape with different noise rather than two different galaxies.

The scroll is `scroll_panel.gd` + `entry_view.gd`. Rows are created lazily as the clock reaches each entry's `tick_range_start`; words render via BBCode with `[color]` (faction hue, or a light accent for region/character mentions) wrapped in `[url=kind:id]` for the mention spans the fixture already carries. Clicking a row that is not yet fully printed does nothing (checked by whether `printed_words >= total_words` at click time, not by a separate phase guard); clicking a printed row opens a full-rect expansion overlay and pauses the tick (and the morph lerp and the printing, since all three read the same tick). The expansion overlay's background `ColorRect` is fully opaque (alpha 1.0, was 0.94, which let the printed row underneath show faintly through the "click to close" hint); a second, independent cause of the same symptom was a one-frame layout-settle race in `RichTextLabel.fit_content` right after the overlay becomes visible, fixed by giving `qa/smoke.json`'s post-click wait enough frames (6, was 2) to clear before the screenshot.

Fragments for both fixtures were hand-written in the register of `simulation/library/chronicle/fragments.json`'s tone (read for reference), with invented names only: factions "The Ostrel Concord" / "The Kaine Dominion"; regions Halven Reach, Kestrel Hold, Moorwick, Pellast, Dray's Hollow, Undermere, Ashcombe, Thistlewake (seed 11) and Varlow, Ambervale, Greymoor, Saltmere, Farrow, Windle (seed 12); people such as Commander Rael Voss, Warden Coel Ashby, Magistrate Enna Thale. Seed 11 is 8 entries (consequence-success, one lineage, two regional-faction-shift covering the two regions that change hands, one famine chain, one expansion chain, two regional filler). Seed 12 is 6 entries (consequence-failure, one `lineage_quiet`, one chain stalemate, one region change, one decline, one stable) to also exercise the near-minimum end of the 5–10 range.

## Fixture shapes invented beyond the message contract

`docs/architecture.md`'s `chronicle_entry` and `time_jump_start` shapes do not carry `category`, `region`, or `score` — those exist only in the simulation's internal cluster objects, never crossing the pipe. The mockup's fixtures add all three directly to the entry object (and `keyframes` as a top-level array distinct from `ownership_timeline`, since not every keyframe is an ownership change) because the client-side mockup has no distiller to derive them from; this is flagged explicitly rather than guessed into architecture.md, since a fenced-path mockup brief cannot amend that doc. See "Questions for Westley" below.

## Questions for Westley

Every one of these is a place I built the simplest thing that shows the question rather than guessing; no decision was made.

- **Q-065-02 (setup entries, open in the epic already)**: the mockup ends both scrolls with no setup entry, matching the epic's own open flag. Not re-decided here.
- **The per-category cap of 2 (Q-065-01, open in the epic already)**: implemented as the epic's code behavior describes; not re-decided here.
- **The expansion animation**: I built it as an instant show/hide (no fade), full-rect over the scroll only (not the map). Candidates: (a) instant, scroll-only [built], (b) a short fade-in matching the 0.20s word-fade rhythm, (c) an overlay across the whole screen (map included), which is one reading of R-069-04's "overlays the scroll and the map" — I read that clause as "the map's animation pauses," not "the map is visually covered," since covering it would hide the very border-morph the expansion is meant to let you read *about*.
- **Should Skip also skip the morphs**: yes, built that way — `qa_set("skip", true)` jumps the tick straight to the fixture's final tick and calls `update_tick` once, so every system's colour goes straight to its final owner with no visible lerp. Candidate alternative: play the morphs at high speed instead of snapping, for a few hundred ms of "history rushing past" before landing on the ending.
- **The blinking cursor**: wall-clock driven (not tick-driven), the one place in the whole scene that reads real time. Candidates: (a) wall-clock blink [built, and the harness's own `PAUSE-X` oracle already special-cases this by excluding the cursor's crop from its diff, suggesting the harness's author anticipated this exact choice], (b) tick-driven blink for total purity, at the cost of the cursor visibly freezing whenever the clock is paused (which may actually read *better* — a frozen cursor is a clearer "everything stopped" signal than a cursor that keeps blinking through a pause).
- **`map_width_fraction` at "done"**: R-069-01 says the panel "slides out... and the map returns to full width" at the end of narration, but S-069's own text also says "at the last entry the panel stays; Proceed becomes enabled" — those read like they're describing two different moments. I made `map_width_fraction` (and the actual anchor) return to 1.0 (and the scroll become invisible) whenever `phase` reaches `"done"`, whether that's by finishing narration naturally or by Skip, since that's the only reading that makes `LAYOUT-10`'s literal contract ("0.62 at start, 1.0 at the end") true in one uniform rule. Candidates: (a) always revert to full width at `done` [built], (b) only revert on Skip, keep the panel showing at 0.62 after a *natural* finish until Proceed is actually pressed, (c) revert only after Proceed is pressed, a fifth observable moment the current phase enum doesn't have room for.
- **Fixture fields invented beyond the message contract**: `category`, `region`, `score` on each entry, and a top-level `keyframes` array (distinct from `ownership_timeline`, since most keyframes are narrative beats with no ownership change). None of these cross the real pipe today (`docs/architecture.md`'s `chronicle_entry`/`time_jump_start` don't carry them); the mockup needs them because it has no distiller to derive rank, region, or "was this tick meaningful" from. If a future story wires a real client-side distiller instead of hand-authored fixtures, these become either derived-client-side or added to the real message shape — that decision belongs to whoever writes that story, not this mockup.
- **`MORPH-X` and `SEED-X` pixel-oracle thresholds**: see the checklist's oracle table and its "Why SEED-X still can't clear 0.10" note — both measured well below the brief's candidate numbers, for reasons that are about pixel-diff sensitivity (auto-orbit churn dominating the `morph_1s`-to-`after_morph` window; a hidden scroll and a seed-independent starfield dominating the `end_seed11`-to-`end_seed12` frame), not about the underlying behaviour being wrong (both are independently proven correct via `MORPH-9`'s headless colour check and the galaxy's own layout data, and the fix pass made both the morph and the two seeds' galaxies visibly more distinct by eye without moving either raw number much). Candidates from the original pass are unchanged and not re-decided here.

## Report

**1. Pace and legibility.** 0.08s/word (~12 words/s) reads as writing-itself at `qa_tick`-driven speed in the screenshots, and the same cadence in real interactive play (not fast-forwarded) is brisk but comfortably readable — closer to "urgent report" than "leisurely history." I would not change it without seeing it in motion rather than in stills, but if it reads too fast in person, 0.10-0.12s/word (8-10 words/s) is the next candidate; both are trivial to change (`WORD_TICKS_NUM`/`WORD_TICKS_DEN` in `chronicle_mockup.gd`, one constant each).

**2. Does the map side need more than points and morphs?** For a mockup, points + edges + morph + starfield read clearly as "a galaxy where borders are changing" (see `pass1/before_morph.png` vs `after_morph.png`) and the reference's territory-shell glow is the one thing visibly missing — the reference's systems sit inside soft translucent faction-coloured blobs that overlap where two factions' territory touches; my systems are bare spheres. That glow is what makes the reference read as *territory* rather than *dots*; I'd rate it the single highest-value addition before this leaves mockup stage. Lanes-as-lit-threads are already present (the `ImmediateMesh` edges), just thinner and less luminous than the reference's gold glow.

**3. Fixture shapes.** The real message shapes (`chronicle_entry`, `time_jump_start`, `mentions[]`) were enough to build the printing/mention/expansion mechanics faithfully. Three fields had to be invented (`category`, `region`, `score` per entry) plus a `keyframes` array separate from `ownership_timeline` — see "Fixture fields invented" above. `mentions[]`'s `span_start`/`span_end` matched the architecture doc's shape exactly and needed no changes.

**4. Frame time under llvmpipe at 720p.** 33.7-106.8ms/frame (`_qa.fps_ms`) measured across one clean run at pass-1, on a machine running 20-45 concurrent Godot mockup-QA processes for most of that session (other parallel briefs, not this mockup's own cost) — well inside the brief's "up to a second per frame" budget even under that contention. `--fixed-fps 30` keeps the simulation clock exact regardless of render time; two clean runs hash-matched and pixel-diffed to 0.000000 on every screenshot checked, so the contention affected wall-clock smoothness only, never state. Re-measured after the fix pass: 46.8-121.8ms/frame, up from the denser starfield and polar grid (items 3-4), still comfortably inside budget; see `qa/checklist.md`'s Timing section for the current numbers.

**5. Under-defined points.** All five (setup entries, per-category cap — both already open in the epic and not re-decided here — the expansion animation, whether Skip also skips morphs, the blinking cursor) plus the `map_width_fraction`-at-done reading and the two pixel-oracle thresholds are listed under "Questions for Westley" above, each with two or three candidates and no decision made.

### A real bug found and fixed along the way

`entry_view.gd` started as a plain `Control` wrapping a `VBoxContainer`+`RichTextLabel` with no anchors of its own; Godot's container layout never propagates a size into a plain `Control`'s children, so the label rendered at its natural near-zero width and the text collapsed to a one-character-wide sliver. Separately, `scroll_panel.gd`'s slide-in tween animated `position.x` from 60 to a hardcoded `0.0`, fighting the panel's own `anchor_left = 0.62` and pinning the whole scroll under the HUD at the left edge instead of the right 38%. Both are fixed (`EntryView` is now itself a `VBoxContainer`; the tween captures the anchor-derived rest position once, the same pattern the legacy `chronicle_scroll_panel.gd` uses). Screenshots in `pass1/` are from after both fixes.

## Fresh-eyes review (2026-09-22, Sonnet reviewer, screenshots only)

Verdict: fix first. Blocker: every shot renders a flat grey background (77, 77, 77) inside and outside the map viewport although the scene's Environment sets a near-black; the configured colour never reaches the screen under the Compatibility renderer (SubViewport clear mode, a camera environment override, or the project's default clear colour), so the map reads as a wireframe on grey rather than a galaxy. Should-fix: the expansion overlay is 94 percent opaque and the entries beneath bleed through the "click to close" hint; the ownership morph is correct in the pixels (cyan to purple at the keyframe node, timed to the entry) but the node is a 15 px dot among twenty and the pulse ring has faded by the after frame, so nothing draws the eye; the map has no shells, glow, grid or dense starfield; the two seeds' galaxies look interchangeable. The scroll side (pace, expansion content, prose tone, mention colouring) checks out. The checklist's Q1 and Q6 answers must be amended.

## Fix pass (2026-09-22, same day, ordered fix list)

Every item reproduced with a screenshot or a pixel sample before changing code, and proven after; one commit per item on `mockup/chronicle-fixes`.

1. **Background.** Root cause: `Environment.background_mode` was `2` (`BG_SKY`), not `1` (`BG_COLOR`); with no `Sky` resource assigned, `BG_SKY` silently falls back to the project's default clear colour (`0.3,0.3,0.3` -> `(77,77,77)`) under the Compatibility renderer, both inside the SubViewport and, via the same fallback path on the root window, outside it. Confirmed by sampling five points across map and scroll before the fix: all five read exactly `(77,77,77,255)`. Fixed: `background_mode = 1`; a `Background` `ColorRect` (`#0A0D12`, near-black) added as the root Control's first child for the area outside the SubViewport; the scroll panel given its own `SURFACE` (`#10141A`) background so it reads as a distinct dark panel, not more of the map. After: the same five points read `(13,15,25)`-`(16,20,26)`. New headless check `CHECK-12` asserts the map's `WorldEnvironment.environment` reports `BG_COLOR` and a near-black `background_color`; new Xvfb oracle `BG-X` asserts an empty map corner is darker than `(20,20,30)` (measured `(13,15,25)`).
2. **Expansion overlay.** `ColorRect` alpha `0.94` -> `1.0` (`scroll_panel.gd`, was line 39). A second, independent cause of the same visible symptom was found by evidence (temporarily swapping the overlay's colour to solid opaque red and confirming the ghost text was still visible through it, then bisecting on `wait_frames` after the click): a one-to-two-frame `RichTextLabel.fit_content` layout-settle race, present even at full alpha, that only clears by `wait_frames=5`. `qa/smoke.json`'s post-click wait bumped `2` -> `6`.
3. **Morph salience.** Ring alpha and a new sphere scale-up now decay over 80 ticks (4.0s) instead of 40 (2.0s), so at the point where the colour lerp finishes (matching `MORPH-9`'s exact contract, untouched) the ring and the enlarged sphere are still clearly visible, not already at zero. No screenshot-timing change was needed (the brief's fallback of shooting `after_morph` at 1.5s instead of 2.0s was not used).
4. **Map richness.** Starfield `260` -> `900` quads, radius range widened, per-instance size variance added, still a plain `MultiMeshInstance3D` of static unshaded quads. New faint polar grid (four rings, twelve spokes, one more static `ImmediateMesh`, alpha 0.14) rebuilt alongside the edges so it orbits with the galaxy. Territory shells stay deferred, out of this pass's static-primitives-only scope — see "Design as built" above.
5. **Seed variety.** Seed 12's `galaxy.systems`/`edges` reshaped (18 systems instead of 22, a flattened-ellipse-with-wobble outer ring instead of a near-circle at the same radius as seed 11, a third faction colour on part of the ring); all entry-referenced region ids and keyframe system ids preserved untouched. `SEED-X` (`diff end_seed11.png end_seed12.png`) measured **0.009971** (default fuzz), still well under the brief's 0.10 candidate even at fuzz 0% (0.017020) or on a map-only crop (0.012316) — reported, not forced; threshold not touched. Root cause (unaffected by the reshape): the `end` screenshots hide the scroll (`map_width_fraction == 1.0`) and the starfield is seed-independent, so the dominant majority of the frame is identical between seeds regardless of how different the ~20 system dots read by eye. See the checklist's "Why SEED-X still can't clear 0.10" for the full accounting.
6. **A regression found while re-checking Q6.** Item 4's denser polar grid put a spoke line directly behind the HUD's transparent-background `PaceLabel` at `phase == "done"` (full map width), rendering "Phase: done" as a visible stray-mark glitch, "Phase: 'done" — confirmed present in both end-seed screenshots and absent at 0.62 width (different screen position, no line crossing there). Fixed: the HUD's button/label stack now sits inside an opaque `PanelContainer` backdrop.
