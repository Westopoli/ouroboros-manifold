## 5. Tick and behavior

One tick is 1/20 s, `dt = 0.05`. Iteration is always in index order (unit id = index in `spawns`); no hash order, no pointer order, no wall clock.

### 5.1 Effective layer
`u.layer` is the layer the unit counts as being on. It is recomputed at the start of every tick (step 2) from the unit's movement state:
- Not changing layer: its layer.
- Timed transfer from L0 to L1, elapsed `e`, duration `D = transition_s`: L0 while `e < D/2`; from `D/2` on, L1 if `timed_new_layer_at_half` else L0 until `e >= D`, then L1.
- On a slope with bottom layer `B`, top `T`, `n = T - B`, position `t` in [0,1]: `B + count of k in 1..n with t >= (k - 0.5) / n`. At the midline of a one-layer slope the unit counts as upper (R-004-06 "at or above"). Direction (up or down) does not matter.

A unit is `changing` while in a timed transfer or on a slope.

### 5.2 Vision
`can_see(o, t)` (observer alive; both layers effective):
1. `off = LL_OFFS(o.layer, t.layer)`. `f = in_vantage(o) ? vantage_vis_factor[off] : vis_factor[off]`. `in_vantage`: observer xy inside any vantage disc (any layer). If `f <= 0`, false.
2. `interf` = sum over zones with `zone.layer == o.layer` and `d < r` of `intensity * (1 - d / r)`, clamped to [0,1] (d xy distance from observer to zone centre).
3. `elev = max(0, 1 + sensor_elev_bonus_per_layer * (o.layer - t.layer))`.
4. `eff_r = o.sensor * (1 - interf) * elev * f`.
5. `d3 = sqrt(dx^2 + dy^2 + (dl * layer_spacing)^2)`, `dl = o.layer - t.layer` (with spacing 0 this is xy distance). Visible if `d3 <= eff_r`.
6. If `cover_mode`, not blocked (5.3).

Side visibility, computed once per tick (step 3) into `side_sees[side][unit]`: unit `e` is seen by side `S` if any alive unit of `S` `can_see(e)`, or `e.pre_revealed` and `e.side != S`, or a pulse of side `S` covers it (5.7). Target acquisition and the fire check both read `side_sees`; there is no second visibility function.

`ll_probe_can_see(sc, seed, o, t)` runs spawn placement and evaluates step 5.2 for the pair at tick 0 (`can_see` only, no side union).

### 5.3 Cover (R-007-01 to 05)
With `cover_mode = 1`, a disc blocks the sight line from `o` to `t` when: neither endpoint's xy is inside the disc (`dist <= r`); the closest point of the xy segment to the disc centre, at parameter `s` in [0,1], is closer than `r`; and `lerp(o.layer, t.layer, s) <= height_layer`. R-007-01 (both on 1, height 2) blocks; R-007-02 (both on 3) does not. Cover never changes damage, movement or fire: a hidden attacker still fires at an observer it can see (R-007-03); the cover test is applied only inside `can_see`. The layer interpolation is the lab's choice for cross-layer lines; it is recorded as T1-candidate and may be varied by `cover_mode` values added later.

### 5.4 Acquisition and eligibility
For every alive unit `u` in index order, candidates are alive enemies `e` with:
- visibility: `side_sees[u.side][e]`. Blind fire is not a rule (E-01 R-008-04, Q-008-04): a unit never fires at a target it cannot see. `fire_requires_vision = 0` stays in the interface for tests of the harness and is never swept.
- `off = LL_OFFS(u.layer, e.layer)` and `range_mult[off] > 0` and `dmg_mult[off] > 0` (area units: `aoe_layer_mult[off] > 0`).
- halfway eligibility, if `e` is changing: `halfway_mode = RULE`: only attackers whose `u.layer == e.layer` (the effective layer) may target it, with `off = 4`; `BOTH`: attackers on either endpoint layer of the change (timed: from and to; slope: bottom and top) as if same layer (`off = 4`); `UNTARGETABLE`: none.
- range: `d3 <= u.range * range_mult[off]`.
- if `facing_gates_fire`: the bearing to `e` lies within `arc_deg / 2` of the facing (dot product against `cos(arc/2)`, 5.12).

A changing unit may itself acquire and fire on any candidate its own effective layer allows (R-004-02: it stops only when the transition takes its sight away, which falls out of `side_sees`: if that side no longer sees the target it is not a candidate).

A unit whose type has `dmg == 0` and no ability (a seer: wide sight, no attack) never acquires: its `target`, `aim` and `chase` stay -1, it is never counted as able to fire (5.11a), and it moves only by `MOVE` orders or a spawn transfer. Selection: policy `NEAREST` (smallest `d3`), `LOWEST_HP` (smallest absolute HP), `HIGHEST_COST` (largest type cost); ties break nearest, then lowest index.

A unit under a `MOVE` order that has not arrived does not acquire or fire. Units in an ability windup do not fire.

### 5.5 Fire and damage
Each unit has a cooldown; `cooldown -= dt` each tick (step 1). It fires when it has a target, `cooldown <= 0`, and nothing above forbids it. Firing sets `cooldown += interval_s`. A cooldown below zero on a tick with nothing to fire at is reset to 0, so an idle unit banks no shots. Initial cooldown is drawn at spawn: `U(0, interval_s)`.

All firing decisions in a tick are made before any damage applies (simultaneous fire; a unit killed this tick still fires). Events are queued and applied together in step 6:
- Direct (`aoe_r == 0`): `dmg * category_mult[a.cat][t.cat] * dmg_mult[off]` to the target.
- Area (`aoe_r > 0`): centre = target xy at fire time. Every alive enemy within `aoe_r` (xy) of the centre that passes halfway eligibility takes `dmg * category_mult * aoe_layer_mult[LL_OFFS(attacker.layer, e.layer)]`. Per target per tick, the sum of area damage is clamped to `aoe_cap_mult` times the largest single area hit it took that tick. No friendly fire.
- Burst ability (5.6) damage is applied in the same step and is not capped.

Damage dealt is counted after clamping to the target's remaining HP. A unit with `hp <= 0` after step 6 is dead; its type cost is added to `cost_lost[side]`.

### 5.6 Burst ability (the storm shape)
A unit with `ability_kind = BURST`, not winding, with ability cooldown `<= 0`: looks at visible, eligible enemies within `range`; for each, counts eligible enemies within `ab_radius` (xy) of it; takes the one with the largest count (ties nearest, then lowest index). If the count is `>= ab_min_targets`, it locks that enemy's xy as the centre and starts a windup of `ab_windup_s`; during the windup the unit does not move or fire. At expiry every alive enemy within `ab_radius` of the locked centre (enemies may have left; that is the counterplay) takes `dmg * ab_dmg_mult * aoe_layer_mult[off]` (no category multiplier); the ability cooldown starts at expiry. A caster that dies in its windup casts nothing. A cast counts as one shot.

### 5.7 Pulse (R-006)
A `pulse_capable` unit with `spawn.pulse_tick >= 0` pulses on that tick if its cooldown is ready. For `pulse_reveal_s` seconds after, its side sees every alive enemy on any layer within `pulse_radius * (1 - interf_at_pulser)` (xy) of the pulser's current position, if the pulser is alive. Cooldown `pulse_cooldown_s` from the pulse tick. No heuristic trigger.

### 5.8 Timed transfer (flyers only)
Started by `spawn.transfer_layer` at `transfer_tick`, or by a forced change (5.10). Walkers never make timed transfers. A transfer to the unit's own layer completes at once with no transition. Otherwise: duration `transition_s` whatever the distance (Q-002-01); the target layer must be open at the unit's xy when it starts (else it stays pending and starts on the first tick it is, R-002-02). During the transfer the unit moves at `speed * transition_speed_mult` and may enter only cells open on both layers (else it stands). A new transfer ordered mid-transfer becomes pending and starts when the current completes (R-004-04). The unit's `transitions` counter increments each time its effective layer value changes.

### 5.9 Slopes and walking (R-001-06, R-001-07, R-004-06 to 08)
Flyers ignore slopes: they are terrain, not paths, for them. Walkers occupy only cells where `land` has their layer's bit, and change layer only by walking a slope.

A walker mounts a slope when its flow-field step says to take it and it is within `max(body_radius, 0.5 * cell)` of the matching edge centre; it is placed on the edge line, `t = 0` (bottom) or `1` (top), at its **lane** (below). On a slope it moves along the slope direction at its own speed (`speed`, never `transition_s`; R-004-07: 600 units at speed 150 takes exactly 80 ticks, at speed 40 exactly 300 ticks), at its lane's lateral offset, and **bodies on a slope are hard** (below); it is never pushed by separation. Each tick the unit chooses its goal as in 5.10 (order goal, or the chase target for an attack-move or idle chaser), compares the flow field's cost-to-go to that goal at the two edge nodes and moves toward the cheaper one (ties keep the current direction), so a changed goal or a chase target that moves back turns it around (R-004-08); a unit with no goal (hold, or arrived) stops where it is. It dismounts at `t >= 1` or `t <= 0` onto the edge's layer and cell. Its layer while on the slope is 5.1. **Lanes.** A slope is `width` wide, so it carries lanes: the usable half-width is `h = max(0, width / 2 - body_radius)` and the lane offsets are the multiples of 30 (a body width, `2 * body_radius` of the largest type, fixed at 30 in the lab) from the axis within `[-h, h]`, ordered by distance from the axis, then the left one first (offset 0, then +30, -30, +60, -60, ...; a slope narrower than a body has the one lane at the axis). A walker's lane is chosen when it mounts: its own lateral position relative to the axis (the signed distance of its xy from the axis line, clamped to `[-h, h]`) rounded to the nearest lane, and if another unit on the same slope is already within one body width of the entry point on that lane (`t` within 30 world units of the edge along the axis), the nearest free lane instead (ties to the lower lane index); if every lane is occupied at the entry the walker waits (it does not mount this tick, and the mouth zone of 5.10 keeps it from deadlocking). A mounted unit's position is the axis point at `t` plus its lane offset along the slope's left normal `(-dy, dx)`; it keeps its lane until it dismounts, and dismounts at the same lateral offset on the edge line, where normal movement and the mouth zone of 5.10 take over.
**Bodies on a slope.** A unit's step along its slope is refused for one tick when its destination would lie closer than `r_i + r_j` to any other unit on the SAME slope (units off the slope never block it and are never blocked by it, whatever their layer), unless the unit is already that close and the step does not bring it nearer. Units in different lanes are at least a body width apart and pass freely; units behind a slower or stopped unit in the same lane queue (a unit that stops on the slope to fire, a stand-and-fire from the slope, blocks the lane behind it, which is the trickle of README 6.2 E3). Two units meeting head-on in one lane block each other and deadlock (ends in a stalemate); in different lanes they pass. **Mounting is never blocked by bodies:** a walker that mounts is placed at its lane's entry point even when that overlaps other units waiting on its layer, and the units waiting near the entry are not pushed by it; the overlap clears as the mounted unit climbs away. Without this, two walkers each waiting within a body width of the entry point block each other and nobody ever climbs (found in E3, README 8 pass 3). Eligibility while on a slope is 5.4 with `changing` true.

### 5.10 Movement (deliberately crude; transfer class T3)
Per tick, per unit not winding and not on a slope: a goal point is chosen. `HOLD`: none (with `chase_when_idle`, the nearest visible enemy this unit could hit if in range, as for `ATTACK_MOVE`). `MOVE`: the order goal; arrival within `1.5 * body_radius`, after which the unit behaves as `HOLD`. `ATTACK_MOVE`: if a visible enemy it could hit exists and is out of range, its position (chase), but if some candidate is already in range the unit stands and fires; otherwise the order goal.

Path: if the straight segment to the goal is clear (sampled every half cell; each sampled cell open on the unit's layer, and `land` for a walker) the unit steers straight (the straight line is the shortest route and costs no layer change). Otherwise it follows a flow field. A flow field is a Dijkstra cost-to-go from the goal over nodes `(cell, layer)`, **in seconds for one unit type** (E-01 R-001-05, Q-001-04 and the recommended reading of Q-001-05: the shortest route by travel time wins across layers), cached by `(goal cell, goal layer, movement kind, unit type, auto_transition)`:
- same-layer edges to the 8 neighbours, cost `distance / speed`, allowed if the neighbour cell is open on that layer (and `land` for walkers; no diagonal corner cutting through a blocked cell);
- flyers, if `auto_transition`: a layer-change edge `(cell, L) -> (cell, M)` for every `M != L` open at that cell, cost `transition_s + forced_change_penalty * |M - L| / speed` (one timed transfer whatever the distance, Q-002-01; `forced_change_penalty` is an extra cost in world units, default 0; a very large value, 100000, makes a detour on the current layer always win, the earlier Q-001-04 reading). With `auto_transition = 0` there are no layer-change edges and a blocked destination leaves the unit standing at the edge;
- walkers: a slope edge between the two slope edge nodes, cost `length / speed`, both ways;
- **goal layer**: the layer the unit was on when its order was given (for an order in a scenario, its spawn layer). The goal nodes are `(goal cell, goal layer)` only, so a route that crosses another layer on the way returns to the ordered layer at the end (Q-001-05 reading a, part 2). If the goal cell is blocked on that layer but open on others (R-001-05's mountain case), the goal layer is the nearest open layer to it (ties go to the lower layer). If the goal cell is blocked on every layer (and for walkers has no land on any), the goal snaps to the nearest cell that is open on the unit's current layer by centre distance, and the unit stops there (R-001-05 second clause);
- ties between equal costs go to a same-layer step over a layer change or slope mount (within 1e-6 seconds), then to the lower node index.

A step whose next node changes layer starts a forced timed transfer to that layer at the current xy (5.8) and the unit keeps following the field. Steering is toward the next node's cell centre. Movement is axis-separated against blocked cells (try the full step, then x, then y). **Units are hard bodies** (the dimension map's body radius: "units cannot overlap"; production `OM_UNIT_COLLISION_RADIUS`): a step (full, then x, then y) is also rejected when its destination lies closer than `r_i + r_j` to any other alive unit `j` on the same effective layer (neither on a slope), unless the unit is already that close to `j` and the step does not bring it nearer (so an overlap that exists is never made worse and can be resolved). When the full, x and y tries are all rejected the unit tries the same step rotated by 45 degrees and then by 90 degrees to each side (four more tries, in the order +45, -45, +90, -90 for even unit indices and -45, +45, -90, +90 for odd ones, so two units facing each other do not both give way the same way; the rotation uses the literal constants 0.7071067811865476 for cos and sin of 45 degrees and (0, 1) for 90 degrees, no libm); each rotated try must pass the same terrain and hard-body tests. A unit whose every try is rejected stands still this tick. (Units on a slope follow their own rule, 5.9, and are not part of these pair tests with units off the slope.) A crowd that funnels into a one-body mouth therefore does not deadlock on a pair that is 30.4 apart and each steering at the other's cell; two columns head-on in a corridor one body wide still deadlock (nothing can pass), which ends in a stalemate. After movement, same-layer separation resolves any remaining overlap (spawn jitter, pushes, deadlock breaking): `LL_SEPARATION_PASSES = 8` passes per tick, each as before: for pairs `i < j` both not on a slope, effective layers equal, `overlap = r_i + r_j - d > 0`: each is pushed apart by `overlap / 2 * separation_weight` along the pair axis (along +x if `d == 0`); a push into a blocked cell is skipped. **Slope mouths.** Within 40 world units (`LL_MOUTH_RADIUS`) of the centre of a slope edge that lies on the unit's layer, bodies neither block steps nor are pushed by separation: a step whose destination is inside that radius is never refused for overlap, and a pair `i, j` is skipped by the separation pass when either unit is inside it. The mouth is where a crowd funnels onto a one-body entry whose centre can lie on a flow-field cell boundary, so two units a body width apart can otherwise each stand where the other needs to step and wait forever (found in E3: at speed 40, 3 to 7 of 10 walkers never climb a ramp even with no enemy; README 8 pass 3). The overlap clears as units mount and climb away. A column of units in a corridor one body wide therefore queues, and the number of units that can be within reach of a point is bounded by the space around it (the choke of README 6.2, E1). This is T3 (lab-only movement), and it changes the numbers of every earlier pass slightly at close contact; the logs say which build produced them.

### 5.11 Termination and outcomes
After step 6: a side with no alive units loses; both empty the same tick is `MUTUAL`. Otherwise `STALEMATE` after `stalemate_ticks` consecutive ticks with no damage applied; `CAP` at `max_ticks`. `ticks` is the number of ticks run.
- `hp_ratio[s]`: remaining HP of side `s` over its starting HP. `survivors`, `cost_lost`, `damage_dealt`, `shots` per side. `transitions`: total across units.
- `first_shot_side/tick`: the first tick any shot is fired; if both sides fire on that tick, side 0 is recorded (the trace shows the tie).
- `first_contact_tick`: first tick on which any `side_sees` entry is set for an alive enemy.
- `unanswered_ticks[s]`: ticks on which side `s` fired at least one shot and side `1 - s` fired none, counted only while both sides have alive units.
- `unit[i]`: final xy, hp, layer, alive, transitions.

### 5.11a Firing share (README 6.1; ABI version 2)
A unit **can fire** on a tick when it is alive, not winding, and acquisition (5.4) gave it a target: a target in range, seen when `fire_requires_vision` is on, eligible under the halfway rule, inside the arc when the gate is on, and the unit not under an unarrived `MOVE` order. It does not depend on the cooldown: a unit waiting for its next shot can fire. Counted at step 4 after acquisition and after the burst update, on every tick executed including the last. Per side the result carries:
- `alive_ticks[s]`: sum over ticks of the side's units alive at that point;
- `firing_ticks[s]`: sum over ticks of the side's units that can fire;
- `firing_weight[s]` (double): sum over ticks, over the side's units that can fire, of `category_mult[unit category][target category]` (the target is the unit's acquired `target`).
The trace flag bit4 is set on a tick for each unit that can fire. These counts are measurements only: nothing in the sim reads them. `alive_ticks` is counted before damage on the same tick (step 4), so it equals the trace's alive count plus the units that died on that tick.

### 5.12 Numerics
Doubles only. `sqrt` is allowed (IEEE correctly rounded); no other libm call in the sim path (`sin`, `cos`, `atan2`, `pow`, `exp` are banned). Facing is stored as a unit vector. `sincos` is the production Taylor series (7 terms, argument wrapped to [-pi, pi]): used to turn `facing_deg`, `arc_deg / 2` and the per-tick turn step into vectors and cosines. Turning: if `dot(facing, desired) >= cos(step)` snap to desired, else rotate by `step = turn_rate * dt` toward desired using the sign of the cross product. Arc test: `dot(facing, bearing) >= cos(arc / 2)`; `arc_deg >= 360` skips the test.

### 5.13 RNG
PCG32 exactly as the contract at `csrc/ouroboros_sim.h:310-322` (reference `pcg32_random_r`; `inc = (seed ^ 0xDA3E39CB94B95BDBULL) << 1 | 1`, `state = 0`, step, `state += seed`, step; `u` from two outputs with 53 bits; `U(lo, hi) = lo + (hi - lo) * u`). The only draws, in this order, per spawn in index order: jitter x `U(-j, j)`, jitter y `U(-j, j)`, initial cooldown `U(0, interval_s)`. Nothing else touches the stream. (The re-implementation follows the written contract; it does not copy production code.)

## 6. Terrain presets (`layerlab/terrain.py`)

A preset builds `open` and `land` arrays and the slope list from parameters. Parameter keys live in the `[terrain]` table beside `preset`; all lengths in cells unless stated; `cx` is the strip or block centre column (default: arena centre), `cy` the centre row (default: arena centre); `h` blocked height, default 2 (the E-01 S-001 example):

| Preset | Keys (defaults) |
|---|---|
| flat | none |
| block | `bw` 10, `bh` 10, `h`, `cx`, `cy` |
| wall | `wt` 4, `end_gap` 6, `h`, `cx` |
| barrier | `wt` 4, `h`, `cx` |
| lane | `wt` 4, `ch` 8, `h`, `cx` |
| ramp | `x1` (plateau starts at column `x1`, default 40), `sl` slope length in world units (default 600), `sw` slope width in world units (default 200), `g` ground layer (default 1), `h`, `cy` |

Explicit extras on top of any preset: `[[terrain.cover]]` (`x y r height_layer`), `[[terrain.vantage]]` (`x y r`), `[[terrain.zone]]` (`x y r intensity layer`), `[[terrain.slope]]` (`x0 y0 dx dy length width bottom_layer top_layer`; `dx,dy` normalised by the loader). Coordinates in world units.
 `open` bit `L-1` is set unless the preset blocks layer `L` there; `land` defaults to equal `open` (every open layer is a deck a walker can stand on) except as stated. Arena `W x H` in cells; `h` = blocked height (layers `1..h` blocked inside the footprint); strips are defined by x.
- `flat`: all open, all land.
- `block`: a rectangle `bw x bh` cells at the arena centre, layers `1..h` blocked, `land` cleared on those layers there.
- `wall`: a strip `wt` cells thick in x across the arena centre, spanning y from `end_gap` cells from the bottom to `end_gap` cells from the top (open ends), layers `1..h` blocked.
- `barrier`: a strip `wt` cells thick in x spanning the full y range, layers `1..h` blocked.
- `lane`: two blocks above and below a channel `ch` cells wide at the arena's mid-y, each spanning a strip `wt` thick in x, layers `1..h` blocked; channel open on all layers.
- `ramp`: a barrier from `x1` to the arena's far edge (the plateau), layers `1..h` blocked there. Ground layer `g` (default 1). `land` outside the plateau: only layer `g`. `land` inside the plateau: only layers `h+1..5`. One slope on the plateau's face at mid-y: bottom edge centre `(x1 * cell - cell / 2, mid-y)` (the centre of the last ground column, so the bottom node is a land cell on layer `g`), direction `+x`, length `sl`, width `sw`, top layer `h+1` (it spans `h + 1 - g` layers). The slope's top edge centre, `x0 + sl`, must fall inside the plateau (`>= x1 * cell`) on a land cell of layer `h+1`; the preset asserts it. Flyers ignore `land`.

Every preset validates: spawns land on open (and land for walkers) cells; slope edge cells are `land` on their layers; slope footprints do not overlap. Violations raise before the C call.

## 7. Formations (`layerlab/formations.py`)

Return `(x, y, facing_deg)` per unit for `n` units; parameters per group. Signature `place(kind, n, x, y, facing_deg, spacing, **params)` with the params named above. `line`: perpendicular to the group's facing, `spacing` apart, centred at `(x, y)`. `column`: along the facing. `box`: `cols` wide grid. `concave`: units on a circle of radius `R` around `center = (cx, cy)` (the enemy's centre), spanning `arc_deg` centred on the bearing from `center` to the group's `(x, y)`, each facing `center`. `screen`: the group's `count` units on a circle of radius `screen_r` around the group's `(x, y)` (the protected unit, a separate group, stands at that point), facing outward, spanning `arc_deg` centred on the group's `facing` (the direction of the enemy). `spacing` default is `2.5 * body_radius`. Placement is pure geometry: no draws.

## 14. Stage 3: skill measures (K0 to K2; README section 4 and 7)

A new package `layerlab/skill/`. No change to the C engine. Everything here is Python on top of `run()`. Every number it produces is transfer class T2. The target and the measure are defined in `docs/northstar/research/layer_dynamics/README.md` section 4; this section is the build contract. Side labels: A is side 0, B is side 1. The skilled side is the one the measure is about; the other is the naive side.

### 14.1 K0: force, margin, light runner, R* (the ratio is by HEADCOUNT and a win needs a margin: see 14.5, which overrides what follows where they differ)

`skill/cost.py`
- `unit_cost(scn, type_name) -> float`: the type's `cost` if set, else `hp * dmg / interval_s / 31.25` (the Q-074-01 power rating already used by the loader).
- `side_units(scn) -> list[dict]`: one dict per spawned unit in spawn order (groups in order, units within a group in order, the same order as `to_c`), keys `side` (0 or 1), `type`, `cost`, `hp0` (the type's hp), `group`.
- `force_cost(scn, side) -> float`: sum of `cost` over that side's units.
- `counts_for_cost(shares: dict[str, float], total_cost, scn) -> dict[str, int]`: integer unit counts per type whose cost is as close to `total_cost` as possible while keeping the shares of cost as close as possible; a type with a positive share gets at least 1 unit; deterministic (largest-remainder rounding on cost shares, ties to the type listed first); `total_cost` of 0 or empty shares give `{}`.
- Force size is stated in raider-equivalents: `size * unit_cost(scn, "raider")` in cost. The two sizes of a measurement are 8 and 16.

`skill/margin.py`
- `margin(result, scn) -> float`: `share_A - share_B` where a side's share is `sum(cost * hp / hp0 over its units alive at the end) / sum(cost over all its units)` (0 for a side with no units); the result's `unit` list gives `hp` and `alive` per spawn index; the margin lies in [-1, 1].
- `effective_margin(result, scn) -> (m, outcome)`: `outcome` is `"win_A"`, `"win_B"`, `"mutual"` (both eliminated), `"stalemate"` or `"cap"`; `m` is `margin` for the first three and `0.0` for a stalemate or a cap (a stalemate is not a win, README 4.2).

`skill/fight.py`
- `FightResult` (dataclass): `margin` (effective), `raw_margin`, `outcome`, `ticks`, `first_contact_tick` (-1 for none), `contact` (bool), `survivors` (tuple), `fight_seconds` (wall time of the C run is not stored; the dataclass carries only deterministic fields).
- `fight(scn, seed=0, lib="O2") -> FightResult`: runs with `trace=False` (no trace buffer, no exchange, no firing analysis) and fills the dataclass.
- `run_fights(jobs, processes=None, lib="O2") -> list[FightResult]`: `jobs` is a list of `(scenario, seed)`; results in job order; `processes` None, 0 or 1 is serial, otherwise `ProcessPoolExecutor` (processes only); a scenario that raises `ValueError` gives a `FightResult` with `outcome = "error"`, `margin = 0.0`, `contact = False` and the message in an `error` field (added to the dataclass, `None` otherwise). `batch.py` and its pinned fields are not touched.
- `measure_rate(scn, seeds, processes, lib) -> dict` with `fights`, `seconds`, `fights_per_second` (wall clock, for the report only, never in a deterministic path).

`skill/rstar.py`
- `RATIOS = (0.5, 0.7, 0.85, 1.0, 1.2, 1.4, 1.7, 2.0, 2.4, 2.9, 3.5, 4.2, 5.0, 6.0, 8.0)`: the fixed scan, enemy force over skilled force by cost.
- `build(ratio, swap) -> scenario`: supplied by the caller. The skilled side's force is fixed; the other side's force is `ratio` times it by cost. `swap = False` puts the skilled side on label A, `swap = True` on label B (labels exchanged, so a side-index bias cancels). Whichever label it holds, the skilled side's margin is `+margin` on label A and `-margin` on label B.
- `isotonic_nonincreasing(xs, ys) -> list[float]`: the least-squares non-increasing fit (pool-adjacent-violators), pure Python, same length as `ys`.
- `zero_crossing(xs, fitted) -> float | None`: the ratio at which the fitted curve crosses 0 going down, by linear interpolation; `None` when it is above 0 at every point (the skilled side beats the whole scan) or at or below 0 at every point.
- `rstar(build, ratios=RATIOS, seeds=(0, 1), refine=4, processes=None, lib="O2", viol_tol=0.15) -> RStar` (`rstar.py` imports `run_fights` as a module-level name, `from .fight import run_fights`, and calls it by that name, so tests can replace it with a scripted runner): for each ratio and each `swap` in `(False, True)` and each seed runs a fight; the point's value is the mean over seeds and both labels of the skilled side's effective margin; records `margin_A_label`, `margin_B_label` (means over seeds), `n_stalemate`, `n_no_contact`; then, inside the bracket `[last ratio with value > 0, first ratio after it with value <= 0]`, adds `refine` bisection points (ratios by repeated halving of the bracket) and recomputes; fits `isotonic_nonincreasing` over all points sorted by ratio and takes `zero_crossing`. `RStar` fields: `value` (the zero crossing, or `None`), `above_scan` (True when the skilled side beats the whole scan: then `value` is `None`), `below_scan` (True when it never wins), `points` (list of dicts `ratio`, `value`, `margin_A_label`, `margin_B_label`, `n_stalemate`, `n_no_contact`), `first_loss` (smallest scanned ratio with value < 0, else `None`), `last_win` (largest scanned ratio with value > 0, else `None`), `violation` (the largest rise of the raw value between neighbouring ratios, 0 when non-increasing), `monotonic` (`violation <= viol_tol`), `rerun` (bool), `valid` (False when still non-monotonic after the re-run), `skipped_ratios` (list), `scan_max` (float), `short_scan` (bool), `label_gap` (largest `|margin_A_label + margin_B_label|` over points: the two labels should agree on the skilled side's margin, so this is the side-label bias), `fights` (count). A non-monotonic curve is re-run once with seeds shifted by 1000 and, if still non-monotonic, returned with `valid = False` (and is left out of aggregates by callers). The scan must reach past 3 (it does: up to 8 where the force fits). **Unbuildable ratios.** An engagement holds at most `LL_MAX_UNITS = 128` units in all and must fit the arena, so a large ratio at a large size may not be buildable (size 16 at ratio 8 is 144 units). `build` may raise `ValueError` for such a ratio; the solver then SKIPS that ratio (it is not run, not an error, not counted as a stalemate), lists it in `skipped_ratios`, and records `scan_max`, the largest ratio actually run. `above_scan` means the skilled side beat every ratio that was run, and is only a statement about `scan_max`: a result with `above_scan` and `scan_max <= 3` is reported as not reaching the target scan (`short_scan = True`) and left out of aggregates. A stalemate is not a win: its margin is 0 (14.1).

`skill/controls.py`
- `mirror_build(size)`: returns a `build(ratio, swap)` for two raider forces on a flat, mirror-symmetric map with identical plays: a line abreast in ranks (14.3), BOTH sides `attack_move` at each other (a symmetric approach: two forces that hold apart never fight, and a side that holds still against one that advances is not a mirror), nearest target, spacing 50, jitter 10; `mirror_control(size, processes=None) -> RStar`.
- `advantage_build(size)`: the same map and plays where the skilled side's raiders have range 240 against 200 (a planted advantage of known direction; it must clear `1.0 + 1 / size`: if a plain range difference does not, plant it as the pass-3 measurements did, 220 against 200 already gave the longer-range side 72 percent at 10 v 10, 240 gave 99); `advantage_control(size, processes=None) -> RStar`.
- Pass criteria (tested): the mirror gives `value` within one raider-equivalent of 1.0, that is `abs(value - 1.0) <= 1 / size`, and `valid`; the advantage control gives `value > 1.0 + 1 / size` or `above_scan`.

### 14.2 K1: situations and guards

`skill/situation.py`
- `Situation` (dataclass): `id` (int), `seed` (int), `family` (str), `terrain` (a scenario `[terrain]` dict: preset and its parameters, `layer_spacing`, and the lists `cover`, `vantage`, `zone`, `slope` where present), `jitter` (spawn jitter, default 10), `anchor_A`, `anchor_B` (the points where each side starts, `(x, y)`), `facing_A`, `facing_B` (degrees), `layer` (the default layer, 3), `mix` (type name to share of cost, summing to 1), `hidden` (dict: `route` int, `layer` int: the enemy's real approach route and layer that the scouting skill is given and the naive side guesses), `approach_distance` (world units between the anchors by straight line), `notes` (list of str).
- `FAMILIES = ("flat", "block", "wall", "barrier_ramp", "lane", "ramp_defense", "cover")`: the map families (README 4.4 open point 5: Westley sets their proportions; the default sampler weights them equally).
- `sample_situations(n, seed, families=None) -> list[Situation]`: reproducible (`random.Random(seed)`), asymmetric (the two anchors are at different distances from the terrain feature; the feature is not centred; extras such as cover discs and vantage nodes are placed asymmetrically), force mixes drawn from the roster (raider, interceptor, vanguard, warden, bombard, bastion; between 1 and 3 types, shares multiples of 0.25), `hidden.route` in `{0, 1}` and `hidden.layer` in `{2, 3, 4}`.
- `base_scenario(sit) -> scenario dict`: loads `scenarios/base.toml`, sets `[terrain]` from the situation, `rules.spawn_jitter`, `run` parameters from `run_params`, no groups.
- `run_params(sit, slowest_speed=40.0) -> dict`: `stalemate_ticks = max(400, ceil(1.5 * approach_distance / slowest_speed * 20))` and `max_ticks = 6 * stalemate_ticks` capped at 20000, so waiting plays are not cut off while they approach.
- Guards: `min_spacing(jitter, body_radius=15.0) = 2 * body_radius + 2 * jitter` (spawn centres of one side must be at least this far apart: 50 at jitter 10); `spacing_ok(spacing, jitter, body_radius=15.0) -> bool`; `goal_clear(sit, x, y, layer) -> bool` is False when `(x, y)` is within 100 world units of the centre of any slope edge on that layer (README: holds or goals near a slope edge give degenerate fights, pass 5); `validate(sit) -> list[str]` returns reasons (empty when fine): anchors inside the arena and open on `layer`, `approach_distance` at least 600, anchors clear of slope edges, mix shares sum to 1.
- `audit(scn, seed, lib="O2") -> dict`: runs ONE traced fight and returns `overlap_pairs_max` (largest count of same-layer alive pairs closer than 29 outside the 40-unit slope-mouth radius, over ticks after 20), `stuck_units` (alive units with an order other than hold that moved less than 5 world units over the last 400 ticks while no enemy was within their range), `contact` (bool), `stalemate` (bool), `ticks`. Run on a sample of fights, not on every fight (it traces).
- `side_bias(rstar_result) -> float` is `RStar.label_gap`; a value above 0.15 flags a situation (README: side-label bias).

### 14.3 K2: plays and composition

`layerlab/scenario.py` change (the one loader change of K2): a group may carry `goals`, a list of `count` `[x, y]` pairs; unit `k` gets `goals[k]` as its own `gx, gy` instead of the group `goal` (`ll_spawn` already has them per unit); a wrong length raises `ValueError`; `goal` and `goals` together raise `ValueError`.

`skill/plays.py`
- `SKILLS = ("S1", "S2", "S3", "S4", "S5")`; `SLOT = {"S1": "where", "S2": "shape", "S3": "layer", "S4": "info", "S5": "matchup"}`; `all_combinations() -> list[frozenset]`: the 32 subsets of the five skills in a fixed order (by size, then lexicographic).
- A play for one side is a list of group dicts (scenario schema) built by `compose(sit, side, size, skills, ladder="line", enemy=None) -> list[dict]`, where `size` is the force in raider-equivalents, `skills` a frozenset, `ladder` the naive ladder step (`"blob"`, `"line"`, `"hold"`), `enemy` the enemy's `(mix, count by type)` the skilled plays may read. One code path: each of the five slots has a naive default and a skilled override; the slots are independent, so each of the 32 combinations is `compose` with that subset.
- Naive defaults (every slot absent): units spaced at `max(50, min_spacing)`; a line abreast is laid in **ranks**: at most 20 units across (1000 world units), further ranks behind it spaced 50 away from the enemy, so a force of up to 128 units fits the arena; all types in one mixed group in the roster order; start at the side's anchor on `sit.layer`; target policy nearest; order `attack_move` to the enemy anchor (the larger side always attacks, README 4.2) with per-unit goals at the enemy anchor laid out by the same shape as the start. Ladder: `"blob"` a box 5 wide; `"line"` a line abreast across the approach (the reference for bands); `"hold"` a line that holds still (order `hold`, no goal).
- S1 where (skilled): the side holds the best defensive point the terrain gives, from a deterministic rule per family: `lane` the exit end of the corridor on its own side inside it; `ramp_defense` on the plateau beside the slope, 300 beyond its top edge; `barrier_ramp` and `wall` and `block` behind the feature on its own side at 1.5 weapon ranges from it; `cover` behind the largest cover disc relative to the enemy anchor; `flat` no better point: the S1 play on a flat map is EXACTLY the naive play (it does not hold: a side that holds still against one that advances has its own effect, README 4.2, and must not be credited to the landscape). For the other families `hold`, with `chase_when_idle` left to the rules. Never within 100 of a slope edge (`goal_clear`).
- S2 shape (skilled): the force is a concave of arc 80 degrees at radius equal to 0.5 of `approach_distance` around the enemy anchor, units per-unit goals on the concave's slots (`goals`), spacing at least 50; it advances (`attack_move`) so the concave closes. Naive: the ladder shape.
- **The hidden layer is real.** The naive side stands on the layer `sit.hidden["layer"]` when the rule set allows cross-layer fire (config `LA`, `LB` or `LC`); under the base rules, where only same-layer units fight, a naive side on another layer could not be fought at all, so the naive side stands on `sit.layer` and there is nothing to scout (S4 is inert under base by construction, and the baseline says so). The skilled side WITHOUT S4 assumes the default guess `sit.layer`.
- S3 layer (skilled): the force starts one layer above the layer it believes the enemy holds: `guess + 1` where `guess` is `sit.layer` without S4 and `sit.hidden["layer"]` with S4 (so S3 is right only when the guess is right; clipped to the layers 1 to 5); naive: `sit.layer`. Under rules without cross-layer fire this skill is dead by construction (README 7); the baseline therefore also runs LA, LB and LC (`experiments/configs.py`).
- S4 info (skilled, the K2 upper bound): the play is given the hidden answer (`sit.hidden.layer`, and `sit.hidden.route`, the side of the main terrain feature the enemy starts on) and every other slot that needs it uses the true route or layer; plays without S4 use the default guess (`route 0`, `layer sit.layer`). Only S3 reads the layer; the route is recorded but unused until K4. The play is labelled `info = "given"`, an upper bound: real scouting waits for the order timeline (K4/K5). With S4 alone and nothing that uses the information the play equals the naive play; its premium arises in combination, which is the point.
- S5 matchup (skilled): the force is split into one group per type, laid abreast across the approach in the order that places each of its types opposite the enemy types it beats under the category matrix (Strike beats Siege, Line beats Strike, Siege beats Line; ties by roster order), reading the naive enemy's type order from `enemy`; naive: one mixed group.
- `build_scenario(sit, skills, size, ladder="line", processes=None)` returns `build(ratio, swap) -> scenario` for `rstar`: the skilled side's force is `size` raider-equivalents by cost with `sit.mix`, composed with `skills`; the naive side's force is `ratio * size` raider-equivalents with the same mix, naive (the given ladder), attacking; `swap` exchanges the labels (the skilled side becomes B, groups reordered, `side` fields swapped); `run` parameters from `run_params`; rules `base` plus an optional lever configuration (`config` in `None`, `"LA"`, `"LB"`, `"LC"`, applied with `experiments/configs.apply` semantics, which move into `skill/plays.py` as `apply_config(scn, cfg)` with the same tables).
- `profile(sits, sizes=(8, 16), ladder="line", config=None, processes=None, ratios=None, refine=None, seeds=(0, 1), combos=None) -> Profile` (`ratios`, `refine` override the `rstar` defaults for fast tests; `combos` restricts to a list of frozensets, default all 32): for each situation, each of the 32 combinations and each size computes `rstar` and R0 (naive against naive, `skills = frozenset()` on both sides, same ladder); stores per cell `value`, `valid`, `r0`, `premium` (`value / r0`; `None` when either is `None` or invalid) and the K1 flags; `Profile.aggregate()` gives for each combination the median premium over valid cells, the count of valid cells, and the count of invalid or above-scan cells (never averaged in silently).

### 15.1 Reach by unit type (S-164, rung L1)
- `ll_unit_type.reach[9]` multiplies the type's range by signed offset (target layer minus own layer, plus 4; index 4 is its own layer); it is used only when `reach_on = 1`, otherwise every offset is 1.0. The loader sets `reach_on` when a type carries `reach` (a list of 9, or a dict from offset -4..4 to multiplier, missing offsets 0).
- A target at an offset whose `reach` is 0 is never fired at, whatever the distance, and is not an acquisition candidate (`target`, `aim` or `chase`). Otherwise the effective maximum range against that target is `type.range * rules.range_mult[off] * type.reach[off]`; the global tables `range_mult`, `dmg_mult` and `aoe_layer_mult` still apply as before (the new design sets them to 1.0 at every offset and lets the types decide). Applies to direct fire, area fire and the burst ability's trigger.
- `ll_reach_validate`: every `reach` entry finite and >= 0 for a type with `reach_on = 1`; `reach_on` is 0 or 1.
- Starting roster values (Q-005-04, lab-tunable, set in scenarios, not in the engine): Line own layer only (`reach[4] = 1`); Strike own layer and one layer either way (`reach[3] = reach[4] = reach[5] = 1`); Siege own layer and downward only (`reach[0..4] = 1`, none upward); and one lab type that fires upward well (own layer and up to three layers above, `reach[4..7] = 1`). A reach is paid for with a weakness: the matchup and stats of the types, tuned by the lab.

### 15.2 Going dark (S-163, rung L2)
- `rules.emit_on = 1` turns it on; with 0 `ll_emit_factor` is 1.0 everywhere. A unit's state is `emit` (1 emitting, 0 silent): its initial value from `spawn.emit` (the loader default is 1), and one scheduled switch: at tick `spawn.emit_switch_tick` (-1 none) the state becomes `spawn.emit_switch_to`, immediately, at no cost (`ll_emit_update`, step 3, before vision).
- In `can_see` (5.2 step 4) the effective radius is multiplied by `ll_emit_factor(o, t)` = `emit_see_mult[o.emit] * emit_seen_mult[t.emit]` for a CROSS-LAYER pair (different effective layers) and 1.0 for a same-layer pair. `emit_see_mult` is how far an observer sees across layers by its state, `emit_seen_mult` how far a target is seen from other layers by its state. Starting values: `emit_see_mult = [1.0, 1.5]`, `emit_seen_mult = [0.5, 1.5]` (silent first).
- `ll_emit_validate`: `emit` and `emit_switch_to` in {0, 1}; `emit_switch_tick >= -1`; multipliers finite and >= 0.
- Every unit of a group shares the group's state in the scenario schema (`emit`, `emit_switch_tick`, `emit_switch_to` are group keys copied to each unit); the engine keeps the state per unit.

### 15.3 Targeted ping (S-162, rung L3)
- A unit with `spawn.ping_tick >= 0` pings once at that tick (a timeline of several pings comes with K4). The ping is aimed at the layer `spawn.ping_layer` (1 to 5) and the place `(ping_x, ping_y)`. It starts if the unit is alive, `tick >= unit.ping_ready_tick`, and the xy distance from the unit to the place is at most `rules.ping_reach`; otherwise it is refused (nothing happens, nothing is counted, no cooldown starts). Any unit type may ping.
- A started ping opens a window of `round(rules.ping_s * 20)` ticks (`(int)(x + 0.5)`, no libm) from the ping tick: for the pinger's side, every alive enemy unit whose effective layer equals `ping_layer` and whose xy distance to the place is at most `rules.ping_radius` is seen (it joins `side_sees`, `ll_ping_reveals`). The window ends early if the pinger dies. The same unit may ping again from `ping_tick + round(rules.ping_cooldown_s * 20)`.
- The ping does not reveal the pinger, does not change passive vision, and costs nothing.
- Alerts: when the window starts, the side owning any enemy unit revealed at that tick is alerted: `state.alerted_tick[side]` is set to the first such tick (-1 when never), `alerts[side]` counts the pings that revealed that side, and `alert_dx/dy[side]` is the unit vector from the centroid (xy mean at the ping tick) of that side's revealed units toward the pinger's xy (set at the first alert, left unchanged afterwards; if the centroid equals the pinger's position the vector is (0, 0)). They are copied to `ll_result.alerted_tick`, `alerts`, `alert_dir_x`, `alert_dir_y`. A play uses the alert as a trigger ("pinged from that direction", K4); the engine only reports it.
- `ll_ping_validate`: `ping_tick >= -1`; for `ping_tick >= 0` `ping_layer` in 1..5 and `ping_x`, `ping_y` finite; `rules.ping_reach`, `ping_radius`, `ping_s`, `ping_cooldown_s` finite and >= 0.

### 14.5 Revision of 2026-10-01 (README 4.2 to 4.4; the Architect's rewrite of K0 to K2, implementation contract)

Where this section differs from 14.1 to 14.4 it wins; the K0 to K2 builders change code and tests to match it.

1. **Ratio by headcount.** The scan ratio is enemy heads over skilled heads. Force size is a number of HEADS: sizes 8 and 16 mean 8 and 16 skilled heads. `Situation.mix` is the share of HEADS per type (multiples of 0.25, summing to 1). `counts_for_heads(shares, n, scn) -> dict[str, int]` in `skill/cost.py`: largest-remainder rounding of `shares * n`, a type with a positive share gets at least 1 when `n >= number of such types`, ties to the type listed first, deterministic; `{}` for `n <= 0` or no shares. The skilled side fields `counts_for_heads(mix, size)`; the naive side `counts_for_heads(mix, round(ratio * size))` (`(int)(x + 0.5)` rounding), so both sides carry the same proportions up to integer rounding. `counts_for_cost` stays (the cost report). `unit_cost`, `side_units`, `force_cost` stay; cost is REPORTED beside the headcount ratio, never used for the ratio: every point of an `RStar` carries `cost_ratio` (naive force cost over skilled force cost), and `RStar` carries `value_cost` (the `cost_ratio` interpolated at `value`, `None` when `value` is `None`). `margin` stays cost-weighted surviving hp share (strength), unchanged.
2. **A win needs a margin.** `rstar(..., win_margin=0.02)`: the skilled side beats a force when its signed margin is at least `win_margin` (stalemate and cap stay margin 0, never a win; mutual elimination is 0). The curve is the same mean margin; the break-even is where the isotonic fit crosses `+win_margin` (`zero_crossing(xs, [f - win_margin for f in fitted])`); `last_win`, `first_loss`, the bracket for refinement, `above_scan` (every run ratio at or above the threshold) and `below_scan` all use `value > win_margin` and `value <= win_margin` in place of `> 0` and `<= 0`. `win_margin` is also an argument of `profile`, `mirror_control`, `advantage_control` and recorded in every cell. The mirror and advantage control tolerances in 14.1 stay.
3. **Firing counts in every fight row.** `FightResult` gains `alive_ticks` and `firing_ticks` (2-tuples, from the result) and `heads` (2-tuple, starting headcount per label); `firing_per_head(label) = firing_ticks[label] / heads[label]` (0.0 for no heads). No trace is used. Each `RStar` point gains `skilled_firing_per_head` and `naive_firing_per_head` (means over seeds and both labels, taking the skilled side's number from whichever label it holds), `skilled_alive_ticks`, `naive_alive_ticks`, and `firing_adv` (the ratio of the two means, `None` if the naive mean is 0). `RStar` gains `firing_adv_at_rstar` (linear interpolation of `firing_adv` over ratio at `value`, `None` when `value` is `None` or `firing_adv` is missing there) and `firing_adv_equal` (the point at ratio 1.0, which is always in the scan).
4. **The firing-count time series for the fights nearest break-even.** `rstar_windows(build, rs, seeds=(0,), window_ticks=100, lib="O2") -> list[dict]`: for the two scanned ratios that bracket `rs.value` (`last_win` and `first_loss`; whichever exist), one traced fight per label (so up to four fights), each returning `ratio`, `swap`, `seed`, `margin`, and `windows`: per window of `window_ticks` ticks the count of units able to fire on the skilled and on the naive side (mean over the window's ticks, from the trace bit4, using `analysis.exchange` or the trace directly) and the alive counts. `profile` calls it for every cell with a valid `RStar` and stores the result in the cell as `windows`; a flag `no_windows` when none.
5. **Maps.** `MAP_SET = {"flat": "space", "block": "space", "wall": "space", "lane": "space", "cover": "space", "barrier_ramp": "land", "ramp_defense": "land"}` in `skill/situation.py`; `Situation.map_set` property. Profile cells carry `map_set`. `Profile.aggregate(map_set=None)` filters by it; reports always give the space table and the land table separately; only space results count toward a rule set's pass (README 4.4).
6. **Refusability per situation.** `Situation.refusable` (bool) and `Situation.refusable_reason` (str): True for `flat`, `block`, `wall`, `cover` and `barrier_ramp` (another route or layer exists around the feature, so the larger side could decline the fight), False for `lane` and `ramp_defense` (the only way through for the larger side is the contested passage). R* is still measured with the larger side made to attack: when the skilled side is the larger (ratio below 1) it also attacks (a hold play only when it is the smaller side, as now but decided by headcount). Cells carry `refusable`.
7. **Hidden-layer spawn bug.** A situation under a cross-layer config (`LA`, `LB`, `LC`) must build for every family: the naive side's spawn cells must be open on `sit.hidden["layer"]`. `sample_situations` picks `hidden.layer` among the layers on which BOTH anchors' spawn areas (the ranks they will use, up to the 128 then 4096 cap's width of 20 across) are open, and `validate` reports a situation where they are not. A `barrier_ramp` situation that has no such layer is resampled (the sampler is deterministic: next draw).
8. **Reports.** `experiments/baseline_report.py` gains, per rule set, a plot (PNG, matplotlib) of R* (y, log) against `firing_adv_at_rstar` (x, log), one point per (cell, situation) of valid space cells, with the least-squares line in log-log space, its slope and r squared printed, and a printed list of the points whose residual is more than 0.25 in log units ("some other number decided the fight"); the same for land cells in a second plot. It also prints C1 (per skill, the share of valid space cells where the skilled combo's `firing_adv_equal` exceeds the naive combo's, i.e. is above 1.0) and C2 (the r squared and slope). It reads the new baseline JSON, whose cell keys gain `map_set`, `refusable`, `value_cost`, `firing_adv_at_rstar`, `firing_adv_equal`, `win_margin`, `windows`.

9. **Whole-head scan (design chat, 2026-10-01).** Fractional ratios round to the same head count, so one fight appeared as several points and a printed "beats 8, loses to 10" could sit beside a loss at 8 and 9. `rstar(build, size=None, ...)`: when `size` (the skilled head count) is given the scan is over WHOLE enemy head counts. Each scan ratio `r` becomes `n = max(1, int(r * size + 0.5))`; duplicates are dropped; the point's ratio is exactly `n / size`; refinement bisects the head count between the last winning `n` and the first losing `n` using integer midpoints `(lo + hi) // 2` and stops when the two are adjacent (never a fractional count). Every point carries `heads` (the enemy head count). `RStar` gains `last_win_heads` and `first_loss_heads` (the bracket edges, `None` when absent); for a monotone curve with a bracket they differ by exactly 1, so "the skilled side beats N and loses to N + 1" is literally what the table's rows show. `size=None` keeps the old fractional behaviour (the scripted tests). `profile`, `mirror_control`, `advantage_control` and `experiments/small_batch.py` pass `size`; the summary line of `small_batch.py` is built from `last_win_heads` and `first_loss_heads`, never from `value * size`.

## 16. Unit cap (ABI version 4; Westley, 2026-10-01: "the cap should be much higher, I thought thousands")

`LL_MAX_UNITS = 4096` (both sides together), `LL_ABI_VERSION = 4`, `ffi.MAX_UNITS = 4096`, `ffi.ABI_VERSION = 4`. The engine state `ll_state` is allocated on the heap in `ll_run` (it no longer lives on the stack; the 4096-unit arrays make it megabytes), freed on every exit path, and the determinism contract is unchanged (O0 equals O2 byte for byte; `make det`). Every fixed-size array of `LL_MAX_UNITS` in the C sources is checked (`px`, `py` in `ll_move.c`, `can_fire` in `ll_sim.c`, `sees`, the damage queue); a stack array of 4096 doubles is fine, a state struct is not. The scenario and result structures grow (`ll_scenario.spawns`, `ll_result.unit`); `ffi.py` mirrors them. No behaviour changes for a scenario of at most 128 units: results are byte-identical to ABI 3 (a test pins this against stored digests of traced fights made before the change). A test runs a 1000 v 1000 flat fight to completion, deterministic across O0 and O2, and records the wall time (no pass mark on speed: a speed note goes to the run log; if the cost is quadratic the Architect decides whether to add a spatial index later).
